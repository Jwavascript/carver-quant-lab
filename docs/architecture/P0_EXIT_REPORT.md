## 3. 실제 연결 가능 범위 (Gate A)

확인한 사실 (CONFIRMED):

1. 위험 계산과 L3 게이트는 `FuturesContractSpec` 체결 장부(`FillLedger`)만 받으므로 가상 선물 월물만 판정한다. 증거 판정·주문 대조
   함수는 상품 종류를 검사하지 않지만, 그 결과를 위험·게이트 판정에 쓰려면 선물 장부가 필요하다.
2. ETF 체결·현금·NAV는 별도 경로다 (`EtfFillLedger` → `etf_account` → `cash_ledger` → `valuation`).
3. 선물 거래 손익(`trading_pnl`)은 있지만 선물 일일 정산의 현금 반영과 계좌 NAV 연결은 없다 (P0-03B 명세 §9).
4. 브로커 인증, 대조 완료 판정, 주문 전송은 없다. `lab.adapters`에는 주문 기록 Journal만 있다.
5. L3 게이트의 `NO_BLOCK_FOUND`는 "이 게이트의 범위에서 차단 사유를 찾지 못함"이며 주문 승인이 아니다. 판정 값에 승인 상태가 없다.
6. 주문 단위 `MATCH`는 비교한 필드의 일치일 뿐 계좌 대조 완료가 아니다 (`RECONCILIATION_NOT_ESTABLISHED`).
7. Journal `RECOVERED`는 저장된 기록의 복원일 뿐 기록 완전성의 증거가 아니다 (`JOURNAL_RECOVERY_NOT_ESTABLISHED`).

그래서 선물 주문에서 ETF 현금·NAV까지 이어지는 하나의 실행 경로는 없고, 두 TRACK을 따로 검증했다. 연결되지 않는 경계(미구현 의존성):

| 경계 | 현재 |
|---|---|
| 선물 거래 손익·정산 → 현금 장부·NAV | 연결 없음 (Q8-6 선물 정산, Q3-11 증거금 모델 OPEN) |
| ETF 주문 → 노출 검사·L3 게이트 | 없음 (위험 경로가 선물 장부만 받음) |
| 체결 장부·현금 장부 영속화 | 없음. Journal은 주문 사건·증거·Trading State 기록만 저장 |
| 주문 대조 결과 → Trading State (불일치 → HALTED, ADR-0003 S-3, ADR-0009 R9-8) | 연결 없음. 전이 의무는 L3 shell 미구현 |
| L3 결과 → 제출 시도 기록(BR-3) → 실행 경계(PK-11) | 없음 |
| 체결·현금 기록의 이용 가능 시각 | 없음. TRACK B의 시점 검사는 발생 시각 기준이고, TRACK A는 `FILL_RECORD_AVAILABILITY`를 미검증 입력으로 싣는다 |
| 체결 기록의 출처 ↔ 계좌의 확인 출처 | 검사 없음: 브로커 확인 계좌의 체결 장부도 시뮬레이션 체결을 받는다. 다만 주문별 체결 합이 확인 누적 체결과 달라지면 기존 귀속 검사가 거부하므로 수치 오류로 이어지지는 않는다 (INFERRED: 검토 probe) |

### 4.3 교차 불변조건

주문 후보 ≠ 실제 체결, 실제 포지션 ≠ 모든 주문 체결 가정 포지션 (3 대 15), 위험 통과 ≠ 제출 승인, Journal 복구 ≠ 기록 완전성, 주문 MATCH ≠ 계좌 대조 완료, UNKNOWN 일부 증거 ≠ 해소, 입금 ≠ 투자 손익, `COMPUTED` ≠ 브로커 확인 (`NAV_OPEN_POLICIES`), HALTED ≠ 자동 정상화, 늦은 정보 미사용, 다른 계좌의 증거·대조 거부: 모두 테스트로 확인했다. 월물·출처·통화 분리는 기존 Slice 테스트가 계속 지킨다.

### 4.4 이번 통합 검토

읽기 전용 독립 검토를 한 번 했다. 프로덕션 코드의 HIGH·MEDIUM 결함은 없었다. 통합 테스트의 MEDIUM 2건(테스트만 수정)을 고쳤다:
A3에 "관측했지만 아직 이용 가능하지 않은" 판단 시각(10:10)과 늦게 이용 가능해진 HALTED 기록을 넣었고, B5의 정보 기준 시각 검사가 각
검사 자체의 사유로 거부되는지 확인하게 했다. 검토자의 변형 32개 가운데 이 통합 파일이 잡는 것은 18개에서 22개로 늘었고, 남은 10개(매도
쪽 노출·현금 부호, 대조의 시점 검사 등)는 기존 단위 테스트가 잡는다. 무작위 비교(TRACK A 5,000건, TRACK B 2,000건)에서 독립 모형과
불일치가 없었다. 두 TRACK의 통합 시나리오는 매수 쪽만 다루며, 매도·공매도·전환은 단위 테스트가 지킨다.
