## 0. 규칙

- **D3A-19, D3A-49, D3A-50 세 항목은 2026-10-17 사용자 승인으로 핵심 원칙만 승인되었다** (상태 / 승인 = `DETAILS_OPEN / APPROVED_PRINCIPLE`). 승인 내용과 남은 세부는 각 항목의 "승인 기록 (R2)", "승인된 원칙", "승인되지 않은 세부" 칸과 하위 질문(`D3A-xx.n`)에 있다. 하위 질문은 기존 ID 아래에 둔 것이며 기존 ID를 대체하지 않는다. **나머지 47개 항목의 상태는 `OPEN`, 사용자 승인 여부는 `NOT_APPROVED`다.** 권장안은 검토를 돕기 위한 의견이며 결정이 아니다.
- 상태 값 (R2): `APPROVED_PRINCIPLE`은 핵심 원칙만 승인되었다는 뜻이고, `DETAILS_OPEN`은 세부 정책이 결정되지 않았다는 뜻이다. 승인된 세 항목의 구현 상태는 `NOT_IMPLEMENTED`, 관련 인수 테스트는 `SPECIFIED_NOT_IMPLEMENTED`다. **원칙 승인은 ACCEPTED ADR을 바꾸지 않는다.** 기존 ACCEPTED ADR과의 관계는 §9 충돌·개정 등록부에 있다. §9에서 규범 충돌(`NORMATIVE_CONFLICT`)로 분류된 부분은 ADR 개정이 승인될 때까지 계약 규범으로 적용하지 않는다.
- **기존 ADR의 질문 ID(`Qn-m`)를 새 ID로 대체하지 않는다.** 원래 질문은 각 ADR §11에 그대로 남아 있고, 이 등록부는 그 질문과 P0-03A 계약의 관계를 연결할 뿐이다. 기존 질문에 대한 권장안이 해당 ADR에 이미 있으면 그대로 옮기고 출처를 적었다.
- `D3A-xx`는 P0-03A에서 새로 생긴 설계 질문이거나, 기존 질문을 P0-03A 계약 관점에서 묶은 연결 항목이다. 각 항목의 "기존 질문과의 대응" 칸이 그 구분을 보여 준다.
- 결정 필요 시점 표기:

| 코드 | 의미 |
|---|---|
| T1 | 지금 결정 가능 (P0-03A 검토 시) |
| T2 | P0-03B·P0-03C 착수 전 |
| T3 | 구현(ADR-0004/0010 Stage 2 등) 착수 전 |
| T4 | 시장·브로커·데이터 공급자 선정 후 |
| T5 | P0-04 금융 검증 근거 확보 후 |
| T6 | Paper 설계 시 |

## 2. 식별자와 상품 모델

### D3A-01 도메인 타입 이름 규칙과 V1 이름 충돌

| 항목 | 내용 |
|---|---|
| 결정 질문 | 새 도메인 타입의 이름이 V1 클래스 이름과 겹치지 않게 어떤 규칙을 둘 것인가? ADR-0006의 가칭 `RollEvent`는 V1 `carver_quant.futures_data.RollEvent`와 이름이 같다. `InstrumentSpec`, `Fill`(`execution.py:29-32`)도 충돌 후보다 |
| 기존 질문과의 대응 | ADR-0004 Q4-2 (도메인 계약의 위치와 이름 규칙), ADR-0010 Q10-1 (패키지 이름). ADR-0004 §7: "이름이 비슷하면 혼동될 수 있으므로 P0-03에서 이름 규칙을 정해야 한다" |
| 대안 A | 새 타입은 V1 이름과 다른 이름을 쓴다 (예: `FuturesRollEvent`, `Instrument`) |
| 대안 B | 같은 이름을 쓰고 패키지 경로로만 구분한다 |
| 대안 C | schema 수준 이름(ADR-0011 FP-8)만 고유하게 하고 Python 클래스 이름은 제한하지 않는다 |
| 권장안과 근거 | **A** (+ 새 패키지 네임스페이스). 같은 이름은 테스트와 변환기에서 잘못된 클래스를 import하는 사고를 부른다. V1 `RollEvent`에는 known_at이 없으므로 잘못 쓰면 PIT 검사가 빠진다. V1 해시는 클래스 이름·모듈을 넣지 않으므로(ADR-0004 §3.5 probe, CONFIRMED) 이름 규칙은 V1 fingerprint에 영향이 없다. 새 인코더에서도 클래스 경로를 해시에 넣지 않는 것은 ADR-0011 FP-8의 제안이며 미승인이다 (D3A-43). 이 문서들은 잠정적으로 A를 따른다 |
| V1 호환성 영향 | 없음. V1 이름은 바꾸지 않는다 |
| 금융 정확성·안전성 영향 | 잘못된 타입 사용으로 인한 시점 검사 누락을 막는다 |
| 후속 단계 의존성 | P0-03B 체결 기록 이름(V1 `Fill`과 구분), D3A-37 |
| 결정 필요 시점 | T1 |
| 상태 / 승인 | OPEN / NOT_APPROVED |

### D3A-49 lot 규칙의 적용 범위: 새 주문 수량과 실제 보유·체결 수량 (R1 추가)

| 항목 | 내용 |
|---|---|
| 결정 질문 | ACCEPTED ADR-0006 I6-5("수량은 자산 유형의 단위를 따른다 (계약 수 / 주 수). 정수여야 하고 lot size의 배수여야 한다")를 (1) 새 주문 수량, (2) 부분 체결로 확인된 실제 수량, (3) 기업 행사 이후의 실제 보유 수량 가운데 어디까지 적용하는가? lot 배수가 아닌 실제 수량(단주)을 계약으로 표현할 수 있어야 하는가? |
| 기존 질문과의 대응 | 신규 (I6-5 적용 범위의 확인). 관련: ADR-0006 I6-5 (승인 원칙 9가 인용), I6-8, AT-0006-3 예외조건("ETF 수량이 lot size의 배수가 아니면 ValueError"), AT-0006-4 예외조건("분할 결과가 정수 주가 아니면 거부", 단주 처리 Q6-5), ADR-0009 원칙 1·3·8·12 (R9-2, R9-3), Q9-7 |
| 쟁점 | 가상 예: `ETF.KR1` lot 10. (1) 새 주문 15주는 I6-5에 따라 거부된다. (2) 10주 매수 주문이 3주만 부분 체결되면 실제 포지션은 +3주다 (lot 미만 부분 체결이 실제로 생길 수 있는지는 시장·브로커별 UNVERIFIED). (3) 10주 보유 중 3:2 분할(구주 2주당 신주 3주)이 일어나면 10 × 3/2 = **15주**다. 정수이므로 AT-0006-4의 "정수 주가 아니면 거부"에는 걸리지 않지만 lot 10의 배수가 아니다. 분할 전 가격 30,000 KRW이면 분할 후 기준가격은 30,000 × 2/3 = 20,000 KRW이고, 평가액은 분할 전후 모두 300,000 KRW다 (CONFIRMED: 일회성 계산). I6-5 문구는 세 경우를 구분하지 않는다. 모든 `Quantity`에 문구대로 적용하면 (2), (3)의 실제 수량을 표현할 수 없다. 반면 ACCEPTED ADR-0009 원칙 3(실제 포지션 = 검증된 기준 + 중복 제거된 체결), 원칙 12(부분 체결은 개별 체결 기록), ADR-0006 원칙 6과 I6-8(분할은 수량과 기준가격 변환)은 실제 상태를 그대로 기록하도록 요구한다 |
| 충돌 판단 | **문구 수준의 충돌이다** (INFERRED: 문서 대조). I6-5를 모든 수량에 적용하면 브로커가 보고한 실제 보유 15주를 표현할 수 없으므로, ADR-0009 원칙 3이 요구하는 실제 포지션 계산과 대조(Reconciliation)가 성립하지 않는다. 그 결과는 ADR-0009 원칙 8에 따라 `HALTED`일 것이다 (INFERRED). I6-5는 ACCEPTED 원칙이 인용한 규칙이므로 이 문서들은 그 의미를 고치거나 범위를 좁히지 않는다. 범위를 좁히는 것(실제 보유·체결 수량에는 lot 배수를 요구하지 않음)은 승인된 규칙의 적용 범위를 바꾸는 일이므로 해석 승인이나 새 ADR이 필요하다 (CLAUDE.md §7.1). **(R2)** 원문을 다시 대조해 `NORMATIVE_CONFLICT`로 분류했다 (CONFIRMED: 문서 대조, §9 CA-49) |
| 대안 A | I6-5를 모든 수량에 문구대로 적용한다. 단주 실제 수량은 표현할 수 없고, 그런 상품은 대조 불일치로 처리한다 (fail-closed) |
| 대안 B | 수량의 역할을 나눈다. 주문 수량(새 주문, 목표 포지션에서 만든 주문)에는 lot 배수를 요구한다. 실제 수량(체결 기록, 보유, 기업 행사 결과)에는 정수만 요구하고 lot 미준수를 표시한다. 단주를 줄이는 주문(단주 매도)을 허용할지는 Q6-5 |
| 대안 C | 단주 실제 수량은 표현하되, 그 상품은 사람 확인 전까지 자동 주문을 막는다 |
| 권장안과 근거 | **(R2) 2026-10-17 사용자가 대안 B의 핵심 방향(수량 역할 분리)에 해당하는 원칙 (1)~(6)을 승인했다 (아래 "승인 기록"). 대안 B에 있던 "lot 미준수 표시"는 승인되지 않았다 (D3A-49.9). 원칙 (2)는 ACCEPTED ADR-0006 I6-5와 규범 충돌이므로 ADR 개정 승인(또는 §9.2.4 (라)의 해석 확인) 전까지 적용 보류다 (§9 CA-49).** 아래는 R1 당시의 검토 의견이며 기록으로 남긴다. 검토 의견 (채택 아님): **B**를 검토할 것을 제안한다. 실제 상태를 표현하지 못하면 노출 계산과 대조가 불가능해진다. 다만 B는 I6-5의 적용 범위를 해석하는 것이므로 확인 전에는 쓰지 않는다. **결정 전 이 문서들의 계약**: 새 주문 수량에는 I6-5를 그대로 적용한다 (완화하지 않음). 실제 보유·체결 수량이 lot 배수가 아닐 때의 처리는 기대 결과 보류다. 어느 경우에도 lot 배수로 조용히 반올림하거나 일부를 버리지 않는다 [제안] (AT-03A-21). 부분 체결 뒤 남은 주문 수량(10주 주문 중 3주 체결이면 7주)도 lot 배수가 아니며, ADR-0009 원칙 4·5의 기대·최악 경우 예상 포지션 계산에 들어간다. 남은 수량의 표현도 이 결정에 포함한다 |
| V1 호환성 영향 | 없음 (V1은 ETF가 없고 정수 계약 수만 쓴다. 사실상 lot 1) |
| 금융 정확성·안전성 영향 | 단주를 조용히 반올림하면 15주가 10주(평가액 200,000 KRW, −33%)나 20주(400,000 KRW, +33%)로 기록되어 노출과 손익이 틀린다. 표현을 거부하면 안전 쪽(거래 중단)이지만, 모든 분할마다 운영이 멈출 수 있다 |
| 후속 단계 의존성 | P0-03B (실제 포지션, 체결 기록, 분할의 수량 변환), Q6-5, Q9-7 |
| 결정 필요 시점 | 원칙: 2026-10-17 승인. ADR-0006 개정 승인 또는 해석 확인: 지금 필요 (P0-03B의 실제 포지션 계약 설계 전, §9.2). 세부 D3A-49.1~49.9: T2 (P0-03B 착수 전). D3A-49.2·49.7은 lot이 1보다 큰 상품을 실제로 거래하기 전에 반드시 정한다 |
| 승인 기록 (R2) | 승인일 2026-10-17. 승인 주체: 프로젝트 사용자. 승인 근거: D3A-49 핵심 원칙에 대한 명시적 승인 (작업 P0-03A-FINAL). 승인 수준 `APPROVED_PRINCIPLE`, 세부 정책 `DETAILS_OPEN`, 구현 상태 `NOT_IMPLEMENTED`, 인수 테스트 `SPECIFIED_NOT_IMPLEMENTED`. 실제 시장 체결이나 브로커 제약의 구체적 처리 방식을 확정한 것이 아니다 |
| 승인된 원칙 (2026-10-17) | (1) 실제 보유 수량(Actual Position Quantity)과 신규 주문 수량(Order Quantity)은 의미가 다르다. (2) 실제로 발생한 체결, 부분 체결, 기업 행사에 따른 보유 수량은 사실 그대로 기록한다. (3) 신규 주문을 제출할 때 해당 거래 단위의 거래 제약을 별도로 검증한다. (4) 실제 수량을 lot 배수가 아니라는 이유로 조용히 반올림하거나 버리지 않는다. (5) 미체결 주문 잔량을 신규 주문과 동일하게 취급하지 않는다. (6) 주문 수량 검증과 체결·장부 기록의 책임을 분리한다. 예제 (가상 ETF): lot 10, 보유 10주, 3:2 분할 → 분할 후 실제 보유 15주는 유효한 실제 보유 기록으로 표현할 수 있어야 한다. 신규 15주 주문이 유효한지는 주문 제약으로 별도 검사한다. 15주를 10주나 20주로 자동으로 바꾸지 않는다 |
| 승인되지 않은 세부 (DETAILS_OPEN, 하위 질문) | **D3A-49.1** 부분 체결로 남은 주문 잔량에 lot 제약을 어떻게 적용할지. **D3A-49.2** 매도·청산 주문에 별도 lot 예외가 있는지 (Q6-5의 "단주 처리". Q6-5의 단주가 lot 미만 수량과 소수 주 가운데 무엇을 가리키는지는 문구상 분명하지 않다). **D3A-49.3** 기업 행사에 따른 소수 수량의 표현. **D3A-49.4** Fractional Share의 기록 방식. **D3A-49.5** 소수 수량의 현금 정산. **D3A-49.6** 수량의 Python 표현 (`int`, `Decimal` 등, D3A-11). **D3A-49.7** 브로커별 주문 제약 (D3A-08, Q6-5). **D3A-49.8** lot 제약의 유효 시점과 변경 이력. **D3A-49.9** 두 역할을 별도 타입으로 나눌지, lot 미준수 실제 수량을 어떻게 표시할지 (D3A-12). 정수 규칙(ADR-0001 §6.2, I6-5, AT-0006-4 예외조건)은 이 승인으로 바뀌지 않는다. 용어 (R2): R1 본문의 "단주"는 lot 미만 수량(odd lot)을 뜻한다. ADR-0006 AT-0006-4의 "단주 처리"는 정수가 아닌 분할 결과(소수 주)를 가리킨다. R2부터는 "lot 미만 수량"과 "소수 주"로 나눠 쓴다. 알려진 결과: ADR 개정(개정안 A) 뒤에도 새 주문과 목표 포지션에는 현행 lot 규칙이 적용되므로, 15주를 가진 상품은 주문 수량(목표 − 15)이 lot 10의 배수가 될 수 없어 위험 축소를 포함한 모든 자동 주문이 거래 단위 검사에 걸린다. 계좌 전체 `HALTED` 대신 그 상품만 막히는 트레이드오프다 (§9.2.3) |
| 기존 ADR 정합성 (R2) | **NORMATIVE_CONFLICT** (§9 CA-49). 원칙 (2)와 15주 예제는 ACCEPTED ADR-0006 I6-5("정수여야 하고 lot size의 배수여야 한다")를 바꿔야 성립한다. [ADR 본문]인 AT-0006-3 예외조건("ETF 수량이 lot size의 배수가 아니면 ValueError")도 같은 문장을 담고 있다. **ADR 개정(또는 이를 명시적으로 대체하는 새 ADR)이 승인되거나 사용자가 승인 범위의 해석을 확인하기(§9.2.4 (라)) 전까지 원칙 (2)를 계약 규범으로 적용하지 않는다 (적용 보류).** 원칙 (1), (3)~(6)은 ACCEPTED ADR과 충돌하지 않는다. 개정 제안과 승인 요청은 §9.2 |
| 상태 / 승인 | DETAILS_OPEN / APPROVED_PRINCIPLE (2026-10-17). 원칙 (2)는 ADR-0006 개정 승인(또는 해석 확인) 전까지 적용 보류 (§9 CA-49) |

| 쟁점 | ADR-0001 §5.1.4는 Raw Tradable Price를 "특정 월물이 실제로 거래된 가격"으로 정의하고 용도에 "체결"을 적는다. 이를 "raw 관측이면 체결가로 쓸 수 있다"로 읽으면, 정산가 100이 확인된 quote 없이 매수 체결가로 확정된다 (AT-03A-25). 해석을 좁히는 것은 ACCEPTED 문구를 바꾸는 것이 아니지만, 승인된 문구를 계약 규칙으로 구체화하는 일이므로 확인이 필요하다 |
| 대안 A | INV-33을 계약 규칙으로 확인한다 (해석 승인) |
| 대안 B | ADR 문구만 두고 INV-33을 두지 않는다. 체결가의 출처는 체결 모델 설계(Q1-1) 때 정한다 |
| 대안 C | 새 ADR로 가격 종류별 체결 사용 규칙을 정한다 |
| 권장안과 근거 | **(R2) 2026-10-17 사용자가 D3A-50 원칙 (1)~(8)을 승인했다 (대안 A의 핵심 금융 의미. 승인된 범위는 아래 "승인 기록"의 설명과 같다).** 아래는 R1 당시의 검토 의견이며 기록으로 남긴다. 검토 의견 (채택 아님): **A**. ADR-0004 원칙 2(관측값과 체결 가정 분리)와 ADR-0007 원칙 10(체결은 체결 가능 구간에서만)에서 바로 나오는 보수적 해석이다. 체결 모델과 주문 시각 정책(Q1-1)은 이 결정과 따로 남는다 |
| V1 호환성 영향 | 없음. V1은 호출자가 넘긴 quote로 체결가를 정한다 (`execution.py`) |
| 금융 정확성·안전성 영향 | 기준 가격을 체결가로 쓰면 실제 체결가와의 차이(스프레드, 슬리피지, 정산 이후 가격 변동)가 기록에서 빠진다. 매수 비용은 기대값 기준으로 과소 계상되기 쉽지만 (INFERRED), 개별 사례에서는 방향이 바뀔 수 있다. 예 (가상 비교 시나리오): 다음 체결 구간에서 2계약이 ask 101.5에 실제로 체결되었고(ask와 같은 체결가, 추가 슬리피지 없음, 수수료는 별도 항이라 비교에서 제외. 1.5 pt 차이에는 정산 이후 가격 변동도 포함) 체결가를 정산가 100.0으로 잘못 기록하면, `M` = 10일 때 체결분 손익이 2 × (101.5 − 100.0) × 10 = 30 USD 과대 계상된다. quote나 실제 체결가가 없으면 이 금액은 확정할 수 없다 (AT-03A-25 (a)) |
| 후속 단계 의존성 | P0-03B (체결 기록), Q1-1, Q12-1 |
| 결정 필요 시점 | 원칙: 2026-10-17 승인. 세부 D3A-50.1~50.8: T2, 브로커·시장 의존 부분은 T4 |
| 승인 기록 (R2) | 승인일 2026-10-17. 승인 주체: 프로젝트 사용자. 승인 근거: D3A-50 핵심 원칙에 대한 명시적 승인 (작업 P0-03A-FINAL). 승인 수준 `APPROVED_PRINCIPLE`, 세부 정책 `DETAILS_OPEN`, 구현 상태 `NOT_IMPLEMENTED`, 인수 테스트 `SPECIFIED_NOT_IMPLEMENTED`. INV-33 가운데 "실제 체결 기록이나 명시적인 체결 시뮬레이션 없이 Raw 관측을 체결가로 쓰지 않는다"는 핵심 금융 의미가 승인되었다 (원칙 (2)·(5)). INV-33 문구의 "승인된 체결 가정"에서 "승인된"이라는 한정은 원칙 (5)의 "명시적인"보다 강한 [제안]이다. Python 생성자 수준에서 모든 무단 변환이 불가능하다고 주장하지 않는다 (구현 후 인수 테스트로 확인, AT-03A-25 (b)) |
| 승인된 원칙 (2026-10-17) | (1) Raw 가격은 조정되지 않은 실제 상품·월물 가격을 의미한다. (2) Raw라는 이유만으로 실제 시장에서 즉시 체결할 수 있는 가격이 되는 것은 아니다. (3) 공식 종가나 정산가는 Raw이면서 평가용 가격일 수 있다. (4) Bid/Ask Quote는 시장 관측이며 실제 Fill과 같지 않다. (5) 체결 기록은 실제 Fill 또는 명시적인 체결 시뮬레이션에서 생성한다. (6) 정산가를 Bid/Ask Quote로 복사해 가상의 실거래 호가를 만들어서는 안 된다. (7) 평가가격, 시뮬레이션 체결가격, 실제 체결가격은 구분한다. (8) 기존 Raw/Adjusted 가격 분리 원칙을 유지한다 |
| 승인되지 않은 세부 (DETAILS_OPEN, 하위 질문) | **D3A-50.1** 주문 유형 (Q1-1, Q9-2). **D3A-50.2** 체결 모델 (Q1-1). **D3A-50.3** Spread·Slippage 정책. **D3A-50.4** 실제 거래 가능성 검증의 세부 로직. **D3A-50.5** 정산가의 평가 사용 기본 정책 (Q1-2, Q7-3, Q7-4). **D3A-50.6** Data Boundary의 정확한 검증 구현 (D3A-31). **D3A-50.7** Quote 유효시간. **D3A-50.8** 브로커 SDK의 호가 필드 의미 (브로커 선정 후, ADR-0012 Q12-1) |
| 기존 ADR 정합성 (R2) | **INTERPRETATION_ONLY + POLICY_DETAIL_OPEN** (§9 CA-50). "Raw Tradable Price"는 조정 가격과 대비되는 가격 종류의 이름이며 체결 가능성을 보장하는 규범이 아니다. ADR 개정은 필요 없다 |
| 상태 / 승인 | DETAILS_OPEN / APPROVED_PRINCIPLE (2026-10-17) |

### D3A-19 데이터 상태 판정의 기준 세션·우선순위·조기 도착·반복 판정

| 항목 | 내용 |
|---|---|
| 결정 질문 | (a) 상태를 어느 세션(들)을 기준으로 판정하는가? (b) 여러 상태의 조건이 동시에 성립하면 어느 상태인가 (네 상태 전체의 우선순위)? (c) 실제 공식 가격이 공표 예상 시각보다 먼저 도착하면 어떤 상태인가? (d) 평가용 판정과 의사결정 입력용 판정을 구분하는가? (e) 기준이 되는 이전 판정이 없는 첫 판정은 어떻게 하는가? (f) **(R1)** 정기 일정 밖에서 같은 세션을 다시 판정(비정기 재판정)하면, 그 판정은 직전 정기 판정과 **같은 주기**를 새 데이터로 다시 보는 것인가, **다음 주기**를 미리 보는 것인가? (g) **(R1)** 공식 가격이 끝내 오지 않는 세션은 언제까지 판정 대상에 남고, 무엇으로 해소하는가? (h) **(R1)** 늦게 도착한 가격은 이미 남긴 판정 기록을 고치는가, 새 판정 기록으로만 반영되는가? |
| 기존 질문과의 대응 | 신규 (이번 설계에서 발견한 정합성 쟁점). 관련: ADR-0007 §6.4 조건, AT-0007-1·AT-0007-2·AT-0007-4·AT-0007-5·AT-0007-7의 기대 출력, Q7-3, Q7-4 |
| 쟁점 | ADR-0007 §6.4를 글자 그대로 적용하면 조건이 겹친다. (1) 직전 세션 가격은 이용 가능하고 최신 종료 세션은 공표 대기: `FRESH`와 `PENDING_OFFICIAL` (AT-0007-4 기대 `PENDING_OFFICIAL`). (2) 그날 세션 가격이 들어온 상품(AT-0007-1의 K1)도 "마지막 공식 가격 이후 세션 없음"이므로 `MARKET_CLOSED` 조건이 성립하고, 휴장 상품(U1)도 휴장 전 세션 기준으로 `FRESH` 조건이 성립한다. 즉 K1과 U1이 **같은 조건 조합**을 갖는데 AT-0007-1은 K1 `FRESH`, U1 `MARKET_CLOSED`를 기대한다. (3) 세션 n−1 가격이 끝내 오지 않고 세션 n이 공표 대기이면 `MISSING_DATA`와 `PENDING_OFFICIAL`이 함께 성립한다. 최신 세션만 보면 결측이 가려진다. (4) 조기 도착은 원문에 없다. (5) **(R1) 반복 판정 반례**: AT-03A-05에서 `XKR` 세션 D는 15:30에 끝나고 공표 예상은 16:00이다. 16:30 첫 판정은 `MISSING_DATA`, 16:45에 공식 가격이 도착하고, 16:50에 같은 세션을 다시 판정하면 기대 결과는 `FRESH`다. R0 대안 A("직전 판정 이후 τ까지 끝난 세션")를 그대로 쓰면 16:50의 직전 판정은 16:30이고 (16:30, 16:50]에 끝난 세션이 없으므로 **대상이 0개 → `MARKET_CLOSED`**가 된다. 가격이 끝내 오지 않은 경우에도 16:50 판정이 `MARKET_CLOSED`가 되어 **결측이 휴장으로 바뀐다** (X7-6 위반). 정기 일정이 08:00이면 16:50 결과가 16:30 호출 여부에 따라 `FRESH`와 `MARKET_CLOSED`로 갈린다 (호출 이력 의존). ### D3A-48 ACCEPTED ADR 본문에만 있는 안전 규칙의 확인

| 항목 | 내용 |
|---|---|
| 결정 질문 | P0-03A 계약이 기대는 다음 규칙은 ACCEPTED ADR의 본문(규칙 표, 인수 테스트 명세)에 있지만, 그 ADR §2의 승인된 원칙 목록이나 규칙별 승인 표에 직접 포함되어 있지 않다. 각 규칙을 승인된 규칙으로 확인할 것인가? (1) ADR-0006 I6-11: 시장·브로커 의존 참조 데이터(lot size, 호가 표, 수수료, 세율, 결제일, 공매도 허용, 증거금)가 없으면 LIVE에서 그 상품의 위험 증가 차단. (2) ADR-0007 AT-0007-5 예외조건: 달력이 없어 휴장과 결측을 구분할 수 없으면 LIVE에서 결측으로 보고 위험 증가 차단. (3) ADR-0008 AT-0008-6 예외조건: 증거금 모델이 없으면 Paper/Live에서 위험 증가 차단. (4) ADR-0008 AT-0008-10 예외조건: 유효하지 않거나 지원하지 않는 통화 코드는 ValueError. (5) ADR-0010 PK-9 (a): V1 변환 경계의 V1 모듈 import. | 기존 질문과의 대응 | 신규 (승인 범위 확인). 관련: ADR-0006 §2, ADR-0007 §2, ADR-0008 §2, ADR-0010 §2 (PK-9 미승인), ADR-0012 §2 (BR-1), ADR-0010 Q10-2, ADR-0012 Q12-2, ADR-0007 Q7-9 |

- 개정안 A는 I6-5에 예외 단서 하나만 넣는다. "예상 포지션"을 예외에 넣은 것은 ACCEPTED ADR-0009 승인 원칙 5가 실제 포지션과 진행 중 주문으로 예상 포지션을 계산하도록 요구하므로, 실제 수량만 예외로 두면 그 계산 결과가 다시 규칙에 걸리기 때문이다.
- AT-0006-3 예외조건과 §5.1 표는 승인 원칙이 인용하지 않는 본문이다. 일관성을 위해 함께 고치는 것을 제안하지만 필수는 아니다.
- **선택 조항 (개정안 B, D3A-49.1의 기록 부분을 정함)**: "이미 제출된 주문의 남은 수량은 브로커가 보고한 대로 기록하고 예상 포지션에 반영하며, 새 주문으로 다시 검증하지 않는다." lot 미만 부분 체결이 생기면 남은 수량도 lot 배수가 아닐 수 있다. 이 조항이 없으면 그런 남은 수량은 현행 규칙에 걸려 표현할 수 없어 ACCEPTED ADR-0009 승인 원칙 4(진행 중 주문의 남은 수량 반영)와 긴장이 생긴다. 다만 이 조항은 D3A-49.1의 기록 부분을 정하므로 개정안 A와 따로 승인 여부를 묻는다. 남은 수량의 정정·취소 등 후속 처리의 lot 규칙은 A와 B 어느 쪽도 정하지 않는다.

#### 9.2.2 개정이 바꾸지 않는 것

- 모든 수량의 정수 규칙 (ADR-0001 §6.2, AT-0006-4 예외조건의 "정수 주가 아니면 거부")
- 새 주문 수량과 목표 포지션에 대한 현행 lot 배수 요구와 무효 주문의 거부
- 주문 경로의 거래 단위 검사와 그 결과 처리: ACCEPTED ADR-0003 S-5(수량이 브로커·거래소의 주문 단위에 맞는다, 위반 시 차단·`INVALID_LOT`). ADR-0012의 `NOT_SENT` 결과 분류는 승인 원칙 8(BR-2)이고, §6.5 (A)의 세부 처리(로컬 검증 실패 시 `NOT_SENT(LOCAL_VALIDATION)`, Trading State 유지)는 ADR-0012 §2가 승인 범위 밖으로 둔 §6의 제안이다
- 거래 단위 검증 (I6-3, I6-4)
- 수량 단위와 통화 단위의 구분, 단위가 다른 수량의 합산 금지 (I6-5의 나머지, I6-6, ADR-0008 X8-8)
- 무단 반올림 금지
- 기존 V1 타입, API, fingerprint (ADR-0006 승인 원칙 8, ADR-0004 P-1~P-6, ADR-0011 FP-1~FP-4)
- ADR-0006 승인 원칙 9의 문장

#### 9.2.3 개정이 정하지 않는 것 (승인 범위 밖)과 알려진 결과

- D3A-49.1~49.9: 부분 체결 뒤 남은 주문 잔량의 lot 처리(개정안 B를 따로 승인하지 않는 한), 매도·청산 주문의 lot 예외, 기업 행사의 소수 주 표현, Fractional Share 기록 방식, 소수 주의 현금 정산, 수량의 Python 표현, 브로커별 주문 제약, lot 제약의 유효 시점과 변경 이력, 역할별 타입 분리와 lot 미준수 표시. 실제 브로커 운영 정책도 정하지 않는다.
- 목표 포지션을 lot 배수로 반올림하는 규칙 (ADR-0006 §9의 "lot 반올림". 새 금융 공식이므로 별도 명세와 독립 검증이 필요하다).
- 현행 I6-5의 "lot size의 배수"와 ADR-0003 S-5의 "브로커·거래소의 주문 단위"가 lot 미만 주문을 받는 시장에서 어떻게 맞춰지는지 (D3A-49.7, Q6-5).
- **알려진 결과 (개정안 A만 승인할 때)**: 새 주문과 목표 포지션에는 현행 lot 규칙이 그대로 적용된다. ACCEPTED ADR-0009 R9-1에 따라 새 주문 의도 = 목표 − 기대 예상 포지션이다. lot 10에서 분할로 실제 보유가 15주가 되면, lot 배수인 어떤 목표 T(…, 0, 10, 20, …)에 대해서도 주문 수량 T − 15는 lot 10의 배수가 되지 않는다 (항상 10으로 나눈 나머지가 5. CONFIRMED: 일회성 계산). 따라서 주문 수량을 lot에 맞추는 규칙(미결정: D3A-49.1·49.2, ADR-0006 §9의 lot 반올림)이 정해지기 전에는 **그 상품의 자동 주문이 위험 축소 주문을 포함해 모두 거래 단위 검사에 걸린다** (ACCEPTED ADR-0003 S-5: 차단, `INVALID_LOT`). lot 미만 5주를 정리하려면 수동 주문이 필요하다 (ADR-0003 §6.2.1 마지막 항목과 §6.5: 차단된 축소 주문의 수동 처리는 별도 승인 절차).
- **실패 방식의 변화**: 개정 전에는 15주를 내부에서 표현할 수 없어 대조 불일치(ADR-0003 S-1, S-3)로 **계좌 전체가 `HALTED`**가 된다 (INFERRED). 개정안 A 뒤에는 대조가 성립해 계좌는 `NORMAL`로 남고, **그 상품의 자동 주문만 계속 거부되며 알림이 나간다** (ADR-0012 §6.5 (A). 이 세부 처리는 ADR-0012 §6의 제안). 어느 쪽에서도 그 상품의 포지션을 자동으로 줄일 수는 없다. 다른 상품의 거래를 계속하는 것과 계좌 전체를 멈추는 것 사이의 **트레이드오프**이며, "개정 전보다 나빠지지 않는다"고 단정하지 않는다. 그런 상품을 상품 단위 정지로 둘지(D3A-49 대안 C, ADR-0003 Q3-13)는 사용자 결정이다. 개정안 B를 승인하지 않으면 lot 미만 부분 체결 뒤 남은 주문 수량도 계속 표현할 수 없다 (§9.2.1). lot이 1보다 큰 상품을 실제로 거래하기 전에 D3A-49.1·49.2·49.7과 Q3-13을 정해야 한다.
- **검증된 기준 포지션**: 개정안 A의 예외는 승인된 원칙 (2)의 열거(체결, 부분 체결, 기업 행사)를 그대로 따른다. 체결 기록 없이 브로커 확인으로 들어온 기준 포지션(ACCEPTED ADR-0009 승인 원칙 3의 "검증된 기준 포지션", 예: 시스템 도입 시점의 보유)이 lot 배수가 아니면 예외 밖으로 읽힐 수 있고, 그러면 대조 불일치(ADR-0003 S-1, S-3)와 `HALTED` 경우가 다시 생긴다. 기준 포지션을 예외에 넣는 것(기준 포지션 조항)은 승인된 열거를 넓히는 것이므로 §9.2.6에서 따로 묻는다.

#### 9.2.4 반영 방식 선택지

| 방식 | 내용 | 평가 |
|---|---|---|
| (가) 부분 대체 ADR | 새 ADR(번호는 작성 시 부여, 예: ADR-0013)이 I6-5에 실제 수량 예외(개정안 A, 선택 시 B)를 더하고, [ADR 본문] AT-0006-3 예외조건의 해당 문장을 맞춘다. 그 밖의 ADR-0006 내용은 그대로 둔다. ADR-0006의 상태는 바꾸지 않고(ACCEPTED 유지), 개정 이력에 "I6-5의 lot 조항에 대한 실제 수량 예외와 AT-0006-3 예외조건의 해당 문장은 ADR-00NN이 정한다 (승인일)"을 기록한다 | **권장.** 바뀌지 않는 원칙 1~9를 다시 승인할 필요가 없다. 다만 CLAUDE.md §7.1의 상태 값에는 부분 대체가 없으므로, 이 기록 방식 자체도 승인 대상이다 |
| (나) 전체 대체 ADR | ADR-0006 전체를 새 ADR로 대체하고 `SUPERSEDED by NNNN`으로 바꾼다 | ADR-0006 변경 규칙과 가장 잘 맞지만, 바뀌지 않는 원칙 1~9까지 다시 승인해야 한다 |
| (다) ADR-0006 직접 개정 | I6-5와 AT-0006-3 문장을 ADR-0006 안에서 고친다 | ADR-0006 변경 규칙("핵심 결정을 바꾸려면 새 ADR로 대체한다. 오탈자, 링크, 명백한 문서 오류만 직접 고친다")과 맞지 않는다. 사용자가 이 규칙의 예외를 명시적으로 승인한 경우에만 가능하다 |
| (라) 승인 범위 해석 확인 | 승인 원칙 9가 I6-5의 lot 조항까지 승인하지 않았다고 사용자가 확인한다. 그러면 lot 조항은 [ADR 본문]이 되어 ADR 개정 없이 D3A-49 원칙 (2)를 적용할 수 있다 | ADR 개정 없이 푸는 유일한 길이다. 그러나 이 문서들이 R0부터 쓴 "승인 원칙이 인용한 규칙은 승인 범위"라는 기준을 이 경우에만 좁히는 해석이고, ADR-0006 본문(I6-5, [ADR 본문] AT-0006-3)에는 lot 배수 문장이 그대로 남는다. 권장하지 않는다 |

#### 9.2.5 승인 후 절차

1. 사용자가 §9.2.1의 문구와 §9.2.4의 방식을 승인한다.
2. 별도 작업에서 승인된 방식대로 ADR을 작성하거나 개정한다. 승인 날짜는 그 승인일로 기록하고 기존 ADR-0006 승인일(2026-10-16)로 소급하지 않는다.
3. 개정 이력과 승인 날짜를 기록한다.
4. P0-03A 문서(D3A-49, INV-12, TC-B1, AT-03A-21)와 `CLAUDE.md`의 정합성을 다시 검증한다.
5. 그 뒤 P0-03A-FINAL 완료 여부를 다시 판정한다.

#### 9.2.6 사용자 승인 요청 (문안)

> ADR-0006 I6-5에 §9.2.1의 개정안 A 단서(체결·부분 체결·기업 행사로 생긴 실제 보유·체결 수량에는 lot size 배수 요구를 적용하지 않고 사실대로 기록하며 반올림하거나 버리지 않음. 그 수량을 포함해 계산한 예상 포지션에도 lot size 배수 요구를 적용하지 않음)를 넣는 것을 승인한다. §9.2.3의 알려진 결과(그런 상품의 자동 주문은 주문 수량을 lot에 맞추는 규칙이 정해질 때까지 위험 축소 주문을 포함해 모두 거래 단위 검사에 걸리며, 계좌 전체 `HALTED` 대신 그 상품만 막힌다)를 확인했다. [ADR 본문]인 AT-0006-3 예외조건과 §5.1 표의 해당 문장도 §9.2.1대로 맞춘다 [예 / 아니오]. 개정안 B(이미 제출된 주문의 남은 수량을 브로커가 보고한 대로 기록하고 새 주문으로 다시 검증하지 않음)도 넣는다 [예 / 아니오]. 기준 포지션 조항(체결 기록 없이 브로커 확인으로 들어온 검증된 기준 포지션도 실제 수량 예외에 포함)도 넣는다 [예 / 아니오]. 반영 방식은 §9.2.4의 (가)~(다) 가운데 [선택]으로 한다. 개정 작업은 별도 작업에서 하며, 승인 날짜는 기존 ADR-0006 승인일(2026-10-16)로 소급하지 않는다. 새 주문과 목표 포지션의 lot 규칙, 상품 단위 정지(Q3-13), §9.2.3의 세부 사항은 이 승인에 포함되지 않는다.
>
> (대안) 개정 대신 §9.2.4 (라)를 택하는 경우: ADR-0006 승인 원칙 9의 승인 범위에 I6-5의 lot 배수 조항이 포함되지 않음을 확인한다.

(6) 원칙 (3)은 ADR-0001이 `V[c,t]`를 raw 평가가격으로 두고 Q1-2에서 정산가를 평가가격 후보로 든 것과 같다. §5.1.4의 "실제로 거래된 가격"이라는 정의 문구가 계산된 기준 가격일 수 있는 정산가를 포함하는지는 문구상 분명하지 않지만, ADR-0001 자신이 Q1-2에서 정산가를 평가가격 후보로 다루므로 원칙 (3)은 그 범위 안이다 (INFERRED). 평가가격 종류의 선택은 Q1-2로 열려 있다. (7) ADR-0007 승인 원칙 7(휴장 평가가격은 정책이 고른 평가값)과 원칙 (7)은 같은 방향이다 |
| 기존 규범의 변경이 필요한지 | 아니오 |
| 선택적 문언 명확화 | 필수가 아니다. 나중에 ADR-0001 §5.1.4와 ADR-0004 §6.4에 "Raw Tradable Price는 조정하지 않은 거래 단위 가격이라는 종류 이름이며 체결 가능성을 보장하지 않는다"는 주석을 다는 것을 검토할 수 있다. 이것이 CLAUDE.md §7.1의 "명백한 문서 오류" 수정에 해당하는지 분명하지 않으므로 이번에는 하지 않았고, 하려면 별도 승인이 필요하다 |

| V1 호환성 영향 | 없음. V1은 호출자가 넘긴 quote로 체결가를 정한다 (`execution.py`) |

| 사용자 추가 승인 필요 여부 | ADR 개정: 불필요. 세부 질문: 별도 결정 필요 |
| 분류 | 원칙 (1)~(8): `INTERPRETATION_ONLY`. 세부: `POLICY_DETAIL_OPEN` |
