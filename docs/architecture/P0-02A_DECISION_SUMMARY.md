## 1. ADR 관리 방식 (제안)

| 항목 | 제안 |
|---|---|
| 위치 | `docs/adr/` |
| 파일 이름 | `NNNN-kebab-case-title.md`. 번호는 `0001`부터 순서대로 부여하고 재사용하지 않음 |
| 구조 | 1 Title, 2 Status, 3 Context, 4 Decision Drivers, 5 Considered Options, 6 Proposed Decision, 7 Consequences / Trade-offs, 8 Compatibility with V1, 9 Financial Integrity Implications, 10 Acceptance Criteria, 11 Open Questions, 12 Related Code and Documents |
| 상태 | `PROPOSED` → (사용자 승인) `ACCEPTED`, 또는 `REJECTED`. 나중에 바뀌면 `SUPERSEDED by NNNN`. **상태 변경은 사용자 승인으로만 한다** |
| 수정 원칙 | ACCEPTED된 ADR의 결정 내용은 고치지 않고 새 ADR로 대체한다. 오탈자와 링크 수정은 예외 |
| 확인 수준 표기 | CLAUDE.md §7의 `CONFIRMED` / `INFERRED` / `UNVERIFIED`를 따른다 |

이 관리 방식 자체도 사용자 승인 대상이다. CLAUDE.md §7은 "ADR 위치는 P0-02에서 정한다"고 되어 있다. CLAUDE.md는 이번 작업에서 수정하지 않았다.

## 4. 핵심 숫자 예제 요약

모든 예제는 저장소 밖의 일회성 스크립트로 계산했다. 독립 산술 결과와 V1 함수 실행 결과를 대조했다. 한도 값은 시연용이며 권고값이 아니다.

| 시나리오 | 결과 | ADR |
|---|---|---|
| 1. quote mid(102) ≠ 평가가격(104), 0→10 ct, M=10 | V1 2일 손익 80, 일반 회계 280. 차이 200 = 10 × (104 − 102) × 10 | 0001 AT-1 |
| 2. 종가 체결 vs 시가 체결 (시가 103, 종가 104) | 종가 체결 −20, 시가 체결 +80. 차이 100 = 개장→종가 움직임 × 수량 × M | 0001 AT-2 |
| (보충) roll일, leg별 mid가 종가와 다른 경우 | V1 30, 일반 회계 55 | 0001 AT-3 |
| 3. 짧은 이력, 작은 vol (가상의 상품, M=250,000, 계좌 5천만) | V1이 세 번째 관측일에 vol 0.0354, forecast 8.36을 산출 → **59 ct, gross leverage 103배**. 다섯 번째 관측일에는 124 ct, 217배. 이때 long-run vol = 단기 vol이라 비율 검사로는 잡히지 않음 | 0002 AT-1 |
| 4. 목표가 leverage 한도 초과 (계약당 1.75배, 현재 1 → 목표 3) | A: 백테스트 중단 / B: 증가 거부, 1 유지 / C: 한도 4.0이면 2로 축소 | 0003 AT-1 |
| 5. 미체결 주문 포함 시 한도 초과 (체결 1 + 미체결 매수 1, 목표 3) | 미체결을 무시하면 최악의 경우 7.0배를 놓침. 미체결을 포함하면 새 주문 없음 (예상 3.5배) | 0003 AT-3 |

## 8. P0-03 범위와 P0-01 임시 배정의 정리

- **P0-03의 공식 범위는 Domain Contracts 설계다.** P0-01 문서(V1_GAP_ANALYSIS §1, §6.2)에는 "P0-03 범위는 저장소 문서에 정의되어 있지 않다"고 적고, 테스트 보강과 저위험 정리 작업(T-01~T-06, A-04, A-05, A-11, A-12, F-14 관련)을 "P0-03 후보"로 잠정 배정했다. P0-01 문서는 이번 작업에서 수정하지 않았으므로 **이 문서가 그 배정을 정정한다.**
- 위의 코드 수정 후보는 **이번 작업에서 진행하지 않았다.** P0-03의 공식 범위에도 포함되지 않으므로 별도로 다시 배정해야 한다 (사용자 결정).
- 세 ADR이 P0-03 Domain Contracts에 넘기는 계약 후보 (INFERRED, 설계 대상 목록):

| 계약 후보 | 출처 |
|---|---|
| 시장 데이터 관측값의 타임스탬프 (`signal_as_of`, `data_available_at`), quote와 평가가격의 분리 | ADR-0001 |
| 체결 기록 (`order_submitted_at`, `fill_at`, 월물, 수량, 체결가, 수수료) | ADR-0001, ADR-0003 |
| 평가 주기와 평가가격 (월물별, raw) | ADR-0001 |
| 신호 상태 (`NOT_CALCULABLE` / `CALCULABLE` / `RESTRICTED` / `TRADABLE`)와 사유 코드 | ADR-0002 |
| 미체결 주문과 상태 불명확 주문의 표현 | ADR-0003 |
| 위험 결정 (`ALLOW` / `REDUCE_TO_LIMIT` / `BLOCK_INCREASE`)과 사유 코드, 거래 상태 (`NORMAL` / `RESTRICTED` / `HALTED`) | ADR-0003 |
| 모드·프로필·한도의 manifest 기록과 schema version 정책 | 세 ADR 공통 |
| `ExecutionMarketDay` 분해와 역방향 의존 해소 (D-01) | V1_DEPENDENCY_ANALYSIS §2.4 |
