## 3. Context

### 3.1 V1의 현재 동작 (CONFIRMED)

V1의 일간 처리 순서는 다음과 같다 (`contract_aware_daily_step.py:126-258`, `daily_step.py:41-102`).

1. 전일 보유 포지션 × (당일 adjusted price − 전일 adjusted price) × multiplier × fx = gross PnL
2. t−1 signal로 목표 포지션을 계산 (`system_backtest.py:176-183`)
3. 당일 quote에서 매수는 ask, 매도는 bid (± 슬리피지)로 체결
4. 비용 = 수수료 + |체결가 − quote mid| × multiplier × |수량|
5. 새 포지션은 다음 날 gross PnL에서 **당일 adjusted 종가**부터 평가

당일 거래한 수량에 대해 "체결가 → 당일 평가가격" 구간의 손익은 계산하지 않는다. 그래서 **quote mid = 당일 평가가격**이라는 가정이 숨어 있다. quote에는 시각 정보가 없다 (`system_backtest.py:28-47`).

### 3.2 기존 테스트가 이 가정을 어떻게 쓰는가 (CONFIRMED, 측정)

감사용 일회성 pytest plugin(저장소 밖)으로 306개 테스트를 실행하면서 step 호출을 기록했다. 거래가 발생한 비-roll step 호출 **154건 모두에서 quote mid가 `current_adjusted_price`와 정확히 같았다** (`daily_step` 11건, `contract_aware_daily_step` 143건). roll일 호출 18건은 step 입력에 월물별 원시 종가가 없어서 비교하지 못했다 (UNVERIFIED).

### 3.3 운영 조건

- 일간 신호, **하루 1회 사용자 점검**이 전제다 (CLAUDE.md §1).
- 하루 1회 사용자 점검은 **감독 행위**다. 주문 제출, 체결 확인, 미체결 처리, Reconciliation은 사람의 점검과 별개로 **자동으로** 수행되어야 한다 (CLAUDE.md §8). 사람의 점검 주기가 하루 1회라고 해서 체결 상태 확인도 하루 1회면 된다는 뜻은 아니다.
- 거래 시장과 브로커가 정해지지 않았다. 따라서 **이 ADR은 특정 거래 시각(시가, 종가, 특정 시각)을 확정하지 않는다.**

## 4. Decision Drivers

1. **시점 무결성**: 주문 결정에 쓰는 데이터는 주문 시점에 실제로 사용 가능해야 한다 (look-ahead 금지).
2. **실제 주문 가능성**: 백테스트의 체결 가정을 실제 시장과 브로커 주문 유형으로 재현할 수 있어야 한다.
3. **회계 정합성**: 체결가, quote mid, 평가가격이 서로 다른 시각의 값일 때 그 차이가 손익에 정확히 반영되어야 한다.
4. **Raw와 Adjusted의 구분**: 체결과 평가에는 거래 가능한 원시 가격을, 신호에는 조정 가격을 쓴다.
5. **ETF·선물 공통성**: 같은 회계식이 roll(선물)과 분배금(ETF)을 모두 다룰 수 있어야 한다.
6. **V1 호환성**: 기존 306개 테스트를 기대값 수정 없이 통과시킬 수 있는 경로가 있어야 한다.
7. **구현 복잡도**: Phase 0~1 규모에 맞아야 한다.

## 5. Considered Options

### 5.1 용어 정의와 시점 계약 (모든 대안에 공통)

#### 5.1.1 다섯 가지 시각과 의사결정 시점

| 용어 | 의미 | 비고 |
|---|---|---|
| `observed_at` (관측 시각) | 입력 값 하나가 나타내는 시장 상태의 시각. 예: "세션 t−1의 종가" | 데이터의 *내용* 시각. 입력마다 있다 |
| `signal_as_of` | 신호 계산에 쓴 입력 가운데 가장 늦은 `observed_at` | 신호의 내용 시각 |
| `data_available_at` (데이터 이용 가능 시각) | 입력 값 하나가 시스템에서 실제로 사용 가능해진 시각 | 종가·정산가는 세션이 끝난 뒤 일정 지연을 두고 공표될 수 있다. 지연 시간은 시장과 데이터 공급자에 따라 다르다 (UNVERIFIED). 공급자가 나중에 값을 수정하면, 수정된 값은 새 `data_available_at`을 가진 별개의 관측으로 다룬다 |
| `decision_at` (주문 의사결정 시점) | 주문 후보를 계산하고 위험 검사(ADR-0003)를 끝낸 시각 | R1에서 추가. 주문에 쓴 모든 입력의 기준 시각 |
| `order_submitted_at` (주문 제출 시각) | 주문을 브로커에 제출한 시각. 백테스트에서는 가정값 | |
| `fill_at` (체결 시각) | 체결 시각. 체결가는 이 시각의 시장에서 결정됨 | 부분 체결이면 체결마다 하나 |
| `valuation_at(t)` (평가 시각) | 평가 주기 t의 손익 평가 시각. 평가가격은 이 시각의 가격 | 세션 종가, 거래소 정산가 중 무엇을 쓸지는 미정 (Q1-2) |

#### 5.1.2 시점 불변조건 (Timestamp Invariant)

```
(I-1) 주문에 쓴 모든 입력 x에 대해:  observed_at(x) ≤ data_available_at(x) ≤ decision_at
(I-2) decision_at ≤ order_submitted_at ≤ fill_at
(I-3) 평가 주기 t의 구간은 (valuation_at(t−1), valuation_at(t)]  — 왼쪽 열림, 오른쪽 닫힘
```

- **I-1이 핵심이다.** "주문에 쓴 입력"에는 신호(가격, vol, forecast)만이 아니라 사이징에 쓴 계좌 값, fx, 위험 검사에 쓴 가격·포지션·미체결 주문 목록이 모두 포함된다. 그중 하나라도 `decision_at`보다 늦게 이용 가능해졌다면 그 주문은 look-ahead다.
- 신호 입력만 보면 `signal_as_of ≤ data_available_at ≤ decision_at`이 된다. R0의 불변조건(`signal_as_of ≤ data_available_at ≤ order_submitted_at ≤ fill_at`)은 이 조건의 특수한 경우다.

#### 5.1.3 체결의 평가 주기 귀속 규칙

- 체결 k는 `valuation_at(t−1) < fill_at[k] ≤ valuation_at(t)`인 **유일한 주기 t**에 귀속된다. 그 체결의 수량, 체결분 손익 항, 수수료가 모두 주기 t에 들어간다.
- 평가 시각 **이전 또는 같은 시각**의 체결만 그 주기의 체결분 손익에 포함한다.
- 평가 시각 **이후**의 체결(예: 장 마감 뒤 시간외 체결, 지연 체결 통보)은 다음 주기 t+1에 귀속된다. 체결분 손익은 `Δq × (V[c,t+1] − F)`이고, `q[c,t]`(주기 t 종료 시 보유)에는 포함하지 않는다.
- 귀속 규칙은 두 주기의 **합계** 손익을 바꾸지 않는다. 바뀌는 것은 주기별 손익, 주기 종료 보유 수량, 그리고 이를 쓰는 계좌 평가·drawdown·위험 검사다 (AT-0001-7).
- 경계값(`fill_at = valuation_at(t)`)을 주기 t에 넣는다는 것은 이 ADR의 제안이다. 실제 거래소의 종가 결정 시각과 체결 통보 시각의 관계는 시장 선정 후 확인한다 (Q1-8).
- 내부 보유 `q[c,t]`는 주기 경계 기준의 회계 값이다. 같은 순간의 브로커 포지션과 비교(Reconciliation, ADR-0003)할 때는 **같은 기준 시각**으로 맞춰야 한다. 경계 이후 체결이 있으면 두 값이 정당하게 다를 수 있다.

#### 5.1.4 가격 종류

| 가격 종류 | 정의 | 용도 |
|---|---|---|
| Raw Tradable Price `P[c,t]` | **특정 월물 c**(또는 ETF 종목)가 실제로 거래된 가격. 연속 시계열이 아님 | 체결, 평가, 명목가치, 증거금, 위험 검사 |
| Back-adjusted Price | roll gap(선물) 또는 분배금·분할(ETF)을 반영한 연속 시계열. 값은 조정 기준일에 따라 과거로 갈수록 실제 거래 가격과 달라짐 | **신호 계산 전용** (PIT로 생성). 체결·평가·명목가치에 쓰지 않는다 |
| Quote mid `mid[c,fill_at]` | 체결 시각의 (bid + ask) / 2 | 체결 비용 측정 기준 |
| Valuation price `V[c,t]` | `valuation_at(t)`의 월물 c 가격 | 평가 손익 |

### 5.2 대안 A — 전일 종가 신호 → 당일 종가 부근 체결 → 다음 날부터 새 포지션 평가 (V1)

- 회계: V1 그대로 (§3.1). 당일 체결 수량의 체결→평가 구간 손익은 0으로 간주한다.
- 전제: `mid[c,fill_at] = V[c,t]`
- 실제 주문 방법: 종가 단일가나 MOC(Market-On-Close) 계열 주문이 필요하다. 대상 시장에 그런 주문이 있는지는 UNVERIFIED.

### 5.3 대안 B — 전일 종가 신호 → 다음 세션 시가 부근 체결 → 체결부터 당일 종가까지 손익 반영

- 회계: 일반화 회계식(§6.2)으로, 체결 수량에 `Δq × (V[c,t] − F)`를 반영한다.
- 실제 주문 방법: 시가 단일가, MOO(Market-On-Open), 장 초반 지정가 등. 대상 시장의 지원 여부는 UNVERIFIED.
- 추가로 필요한 데이터: 체결 시각의 quote, 거래한 월물의 당일 평가가격

### 5.4 대안 C — 신호·주문·체결·평가를 모두 타임스탬프 이벤트로 분리하는 일반 모델

- 회계: 이벤트 스트림(시장 데이터, 신호, 주문, 체결, 평가)을 시간순으로 처리한다.
- 장중 다회 체결, 부분 체결, 정정·취소, 장중 위험 점검까지 다룰 수 있다.

## 6. Proposed Decision

### 6.1 결정 요지

**B의 일반화 회계식을 표준 회계 규칙으로 채택한다. 체결 시점은 코드에 고정하지 않고 데이터 계약(타임스탬프 필드)과 설정으로 표현한다. A(V1)는 이 회계식의 특수 사례로 보존한다. C는 일간 손익 회계에는 쓰지 않고, Live 주문 생애주기 관리가 필요해지는 Phase 1 이후에 별도 ADR로 재검토한다.**

- 시가 체결과 종가 체결 가운데 어느 쪽을 운영 기본값으로 할지는 **결정하지 않는다.** 시장과 브로커가 정해진 뒤 사용자가 결정한다 (Q1-1).
- 이 ADR은 회계식과 시점 불변조건만 정한다.

### 6.2 일반화 일간 회계식 (공식 명세, CLAUDE.md §3.2)

**입력**

> **R2**: R0·R1의 공식은 `M`과 `fx[t]`를 모든 상품에 공통인 스칼라처럼 썼다. 그 형태는 **상품 하나, 통화 하나**일 때만 맞다. R2에서 여러 상품(multi-instrument)과 여러 통화를 다루는 일반형으로 바꿨다. §10의 기존 숫자 예제(AT-0001-1~8)는 모두 상품 하나, `M` 하나, fx = 1인 특수 사례이므로 값이 그대로 유효하다.

**입력**

| 기호 | 의미 | 단위 |
|---|---|---|
| `c` | 월물(또는 ETF 종목). 각 c는 정확히 하나의 상품 `i(c)`에 속함 | — |
| `κ(c)` | 월물 c의 거래통화 (상품 사양의 통화, V1 `InstrumentSpec.currency`) | — |
| `M[c]` | 월물 c의 계약승수 (multiplier) | κ(c)/pt/ct (>0) |
| `q[c,t−1]` | 평가 주기 t 시작 시 월물 c의 보유 수량 | ct (정수) |
| `V[c,t]`, `V[c,t−1]` | 월물 c의 평가가격 (raw) | c의 pt |
| `Δq[k]` | 주기 t에 귀속된 체결 k의 수량 (매수 +, 매도 −) | ct (정수, ≠0) |
| `F[k]` | 체결 k의 체결가 (raw) | c(k)의 pt |
| `c(k)` | 체결 k의 월물 | — |
| `fee[k]` | 체결 k의 수수료 | 통화 `κ_fee(k)` (≥0). **수수료 통화는 미해결** (Q1-4). 정해지기 전에는 V1처럼 `κ_fee(k) = κ(c(k))`로 가정한다 (`costs.py:105-113`) |
| `D[c,t]` | (ETF) 주기 t에 귀속되는 주당 분배금 | κ(c)/ct. 선물은 0 |
| `fx[κ,t]` | 통화 κ 1단위의 기준통화 환산율. 기준통화 자신은 `fx[BC,t] = 1` | BC/κ (>0). **어느 시각의 환율을 쓸지는 미해결** (Q1-4, D-08) |

**출력**

- `PnL_κ[κ,t]`: 주기 t의 통화별 손익 (단위 κ)
- `PnL[t]`: 주기 t의 기준통화 손익 (단위 BC)
- (보고용) 상품별 기준통화 손익 `PnL_i[i,t]`. 같은 통화의 상품만 묶어서 계산하고 같은 방식으로 환산한다

**공식**

```
(1) 통화별 합산 — 같은 통화 κ에 속하는 항만 더한다

PnL_κ[κ,t] =   Σ_{c : κ(c)=κ}      q[c,t−1] × (V[c,t] − V[c,t−1]) × M[c]          ← 보유분 평가손익
             + Σ_{k : κ(c(k))=κ}   Δq[k]   × (V[c(k),t] − F[k])   × M[c(k)]       ← 체결분: 체결가→평가가격
             + Σ_{c : κ(c)=κ}      q[c,t−1] × D[c,t]                              ← (ETF) 분배금
             − Σ_{k : κ_fee(k)=κ}  fee[k]                                         ← 수수료

(2) 기준통화 환산 — 환산한 뒤에만 통화끼리 더한다

PnL[t] = Σ_κ  fx[κ,t] × PnL_κ[κ,t]
```

- **체결마다 그 체결 월물의 계약승수 `M[c(k)]`를 쓴다.** 다른 상품의 승수나 포트폴리오 공통 승수를 쓰지 않는다.
- **서로 다른 통화의 금액은 (2)에서 환산하기 전에 더하지 않는다.** USD 1,000과 KRW 1,000을 더한 2,000은 의미 없는 값이다 (AT-0001-9의 W1).
- 환산율은 **통화로 키를 잡는다** (`fx[κ,t]`). 같은 통화를 쓰는 두 상품은 같은 주기에 같은 환산율을 써야 한다. V1은 환산율을 상품별 일간 입력(`ExecutionMarketDay.fx_to_base`)으로 받고, `InstrumentSpec.currency`로 환산율을 찾지 않는다. 그래서 같은 통화의 두 상품이 같은 날 서로 다른 환산율을 가져도 막지 않는다 (CONFIRMED: `portfolio_backtest.py:134, 494`, `fx.py`에 통화 키가 없음). 단, V1은 상품별로 환산한 뒤 더하므로 "환산 전 합산" 오류는 없다.
- 상품 하나, 통화 하나이면 공식은 R0 형태 `PnL[t] = fx[t] × (…× M …)`로 줄어든다. 기존 예제는 이 특수 사례다.

**FX 변동 자체의 영향 (이 공식의 범위 밖, D-08)**

위 공식은 **거래 손익**을 주기 t의 환산율로 바꾼 값이다. 다음은 다루지 않는다. 별도 검토 사항으로 D-08에 넘긴다.

- 외화 현금, 외화 증거금 예치금, 미정산 외화 손익의 **기준통화 평가액이 환율 변동만으로 바뀌는 효과** (예: USD 현금 10,000을 보유하고 환율이 1,350 → 1,360으로 바뀌면 기준통화 평가액이 100,000 BC 늘어남. 거래 손익은 0)
- 외화 손익을 언제 기준통화로 바꾸는지(실제 환전 여부, 정산 주기)
- 위험 검사(ADR-0003)의 명목가치·증거금에 쓰는 환산율의 시각

**보조 분해** (보고용. 손익 계산에 다시 더하거나 빼지 않는다):

체결분 항은 항상 다음과 같이 **부호 있는(signed) 형태로** 정확히 분해된다 (항등식). 아래에서 `M`은 그 체결 월물의 `M[c(k)]`이고, 금액 단위는 그 월물의 통화 κ(c(k))다. 기준통화로 환산하는 것은 (2)에서 한 번만 한다.

```
Δq × (V − F) × M  =  Δq × (V − mid) × M      ← valuation gap (체결 시각 mid → 평가가격)
                   − Δq × (F − mid) × M      ← 부호 있는 체결 비용 (signed execution cost)
```

- 부호 있는 체결 비용 `Δq × (F − mid) × M`은 불리한 체결(매수가 mid보다 비쌈, 매도가 mid보다 쌈)이면 양수, 유리한 체결(가격 개선, price improvement)이면 **음수**다.
- **절댓값 형태 `|Δq| × |F − mid| × M`은 부호 있는 형태와 같을 때만 쓸 수 있다.** 같아지는 조건은 `sign(F − mid) = sign(Δq)`, 즉 **불리한 방향으로 체결된 시장가 주문**(매수 ≥ mid, 매도 ≤ mid)이다. V1의 execution price cost(`costs.py:23-70`)가 이 형태다. V1은 이 전제를 강제하고 있어서, 매수가 mid보다 싸거나 매도가 mid보다 비싸면 `ValueError`를 낸다 (CONFIRMED, `costs.py:50-65`).
- 지정가 주문, 가격 개선 체결, 체결 시각과 다른 시각의 mid를 기준으로 쓰는 경우에는 절댓값 형태가 틀린다. 이때는 부호 있는 분해를 써야 한다 (AT-0001-8의 변형).

**이중 차감 금지 (No Double Counting)**

체결가에서 mid까지의 차이(스프레드 + 슬리피지)는 **다음 두 방식 가운데 정확히 한 곳에서만** 손익에 반영한다.

| 방식 | 체결분 손익 항 | 별도 체결 비용 차감 | 사용처 |
|---|---|---|---|
| (a) 체결가 기준 | `Δq × (V − F) × M`을 포함 | **하지 않음.** 수수료만 차감 | 일반 모드 (§6.2 공식) |
| (b) mid 기준 비용 분해 | `Δq × (V − mid) × M` (valuation gap)을 포함 | 부호 있는 체결 비용 `Δq × (F − mid) × M`을 차감 | 보고 또는 동치 계산 |
| V1 / 호환 모드 | (b)에서 valuation gap = 0으로 둔 것 (`V := mid`) | 절댓값 체결 비용을 차감 (불리한 체결만 허용) | `V1_COMPAT` |

- 체결가 기준 항 `Δq × (V − F)`를 쓰면서 체결 비용을 다시 빼면, 스프레드와 슬리피지가 두 번 빠진다. 이것을 금지한다 (AT-0001-8).
- 보고서의 비용 분해 표는 위 항등식의 **구성 항을 보여 주기만** 한다. 합계 손익은 §6.2 공식 하나로만 계산한다.

V1과의 관계 (불리한 체결, D=0, 비-roll일 때):

```
일반화 PnL = V1 PnL + Σ_k fx[κ(c(k)),t] × Δq[k] × (V[c(k),t] − mid[k]) × M[c(k)]
```

**전제조건**

- 시점 불변조건(§5.1.2)이 성립하고, 체결은 귀속 규칙(§5.1.3)에 따라 주기에 배정되어 있어야 한다.
- 체결가 `F[k]`와 평가가격 `V`는 같은 월물의 **raw** 가격이어야 한다. adjusted 가격을 쓰면 안 된다. 숫자만 봐서는 raw와 adjusted를 구분할 수 없으므로, 이 전제는 P0-03 데이터 계약의 타입(가격 종류 표시)으로 강제해야 한다.
- 각 월물 c는 하나의 상품과 하나의 거래통화 κ(c)에 속하고, `M[c]`는 그 월물의 존속 기간 동안 바뀌지 않는다. 거래소가 계약 사양을 바꾸면 다른 월물(다른 식별자)로 다룬다.
- 체결 기록의 월물·통화·승수는 상품 사양과 같아야 한다.
- 등장하는 모든 통화 κ(거래통화와 수수료 통화)에 대해 `fx[κ,t]`가 있어야 한다.
- 보유분 항은 raw 가격 차이를 쓴다. 가산 back-adjustment에서는 같은 보유 월물에 대해 adjusted 가격 차이와 raw 가격 차이가 같다. 그래서 V1의 adjusted 차이 계산은 선물에서 동치다 (INFERRED. V1 테스트 `test_roll_gap_does_not_create_artificial_return`이 일부를 확인함). ETF의 곱셈 조정에서는 동치가 아니므로 반드시 raw + `D`를 쓴다.

**예외조건 (ValueError, fail-fast)**

- 거래했거나 보유한 월물의 `V[c,t]`가 없음
- 시점 불변조건 위반 (예: 입력의 `data_available_at > decision_at`, `order_submitted_at < decision_at`, `fill_at < order_submitted_at`)
- 체결을 귀속할 주기를 정할 수 없음 (`fill_at`이 없거나 평가 시각 목록 밖에 있음)
- `F`, `V`, `M[c]`, `fx[κ,t]`가 비유한값이거나 `M[c] ≤ 0`, `fx[κ,t] ≤ 0`
- `fee < 0`, `Δq = 0`
- 손익에 등장하는 통화 κ의 `fx[κ,t]`가 없음. 기준통화가 아닌 통화에 환산율 1을 기본값으로 쓰지 않는다
- 월물 c의 통화 κ(c)나 상품 `i(c)`를 알 수 없음, 또는 체결 기록의 승수·통화가 상품 사양과 다름
- 같은 주기에 같은 통화 κ에 대해 서로 다른 환산율이 들어옴
- 값을 보간하거나 0으로 대체하지 않는다.

### 6.3 Roll 구간

롤은 같은 주기 안의 두 체결(구월물 매도 leg, 신월물 매수 leg)로 표현한다. 두 월물 모두 `V[·,t]`가 필요하다. 이 데이터는 V1 back-adjustment가 이미 요구하는 roll일 두 월물 종가와 같다 (`futures_data.py:103-113`). 다음 주기부터 보유분 항은 신월물 raw 가격 차이를 쓴다.

### 6.4 단계 적용 (구현은 이 ADR의 범위 밖)

1. P0-03 Domain Contracts: 타임스탬프 필드와 평가가격 입력을 데이터 계약으로 정의한다.
2. P0-04: 일반화 회계식을 독립 계산으로 검증한다 (§10의 숫자 예제).
3. 구현 단계: 기존 V1 API는 지금처럼 동작한다(암묵적 `V1_COMPAT`). 새 연구 API에서는 회계 모드를 명시적으로 선택한다. 적용 범위는 §8.0 (R2에서 "백테스트 기본값" 표현을 바꿈).

**`V1_COMPAT` 회계 모드의 정의** (R1에서 구체화):

- 체결분 항은 `V := mid[k]`로 평가한다. 따라서 valuation gap = 0이고, 체결 비용은 V1의 절댓값 형태(불리한 체결만 허용)다.
- 보유분 항은 V1처럼 **adjusted 가격 차이**를 쓴다.
- 따라서 `V1_COMPAT`는 "모든 곳에서 `V := mid`"가 아니라 **두 규칙을 섞은 모드**다. roll일에는 보유분 항(구월물의 adjusted 차이)과 체결분 항(구월물·신월물 leg의 mid)이 서로 다른 가격 기준을 쓴다. 이 조합이 V1의 roll 손익과 일치하는지는 구현과 회귀 검증 전까지 **INFERRED**다 (§8).
- `V1_COMPAT`는 **기존 테스트와 기존 연구 결과의 재현 전용**이다. 적용 범위는 §8.0을 따른다.

## 7. Consequences / Trade-offs

**장점**
- 시가 체결이든 종가 체결이든 같은 회계식으로 처리하므로, 체결 시점 결정을 미룰 수 있다.
- 숨은 가정(mid = 평가가격)이 명시적인 항(valuation gap)이 되어 보고하고 검증할 수 있다.
- ETF 분배금을 같은 식에 넣을 수 있다.

**단점과 비용**
- 데이터 요구가 늘어난다: 체결 시각 quote, 거래 월물의 평가가격, (일반 모드) 타임스탬프.
- 호환 모드와 일반 모드가 공존하는 동안 설정을 잘못 고르면 결과가 달라진다. 새 연구 API의 실행은 manifest에 모드를 기록해야 한다 (A-09). 기존 V1 API의 manifest는 바꾸지 않는다(§8.0). 기존 V1 manifest는 그 자체로 V1 동작의 기록으로 본다.
- B 방식의 시가 체결은 개장 단일가나 갭 위험을 가진다. 시가 quote의 품질과 유동성은 UNVERIFIED.

**하지 않는 것**
- 장중 다회 체결, 주문 상태 기계, 정정·취소는 다루지 않는다 (C, Phase 1 이후).

## 8. Compatibility with V1

### 8.0 `V1_COMPAT` 적용 범위 (R2, 세 ADR 공통)

> 이 절은 ADR-0001, ADR-0002, ADR-0003에 **같은 내용으로** 들어 있다. 세 ADR의 호환 모드(ADR-0001의 회계 모드, ADR-0002의 정책 프로필, ADR-0003의 사후 검사 모드)는 모두 이 규칙을 따른다. 한 곳을 고치면 세 곳을 함께 고친다.

| 경로 | 규칙 |
|---|---|
| **기존 V1 API** (현재 `src/carver_quant`의 공개 함수. 예: `run_daily_step`, `run_contract_aware_backtest`, `run_ewmac_system_backtest`, `run_prepared_portfolio_backtest`, `run_combined_ewmac_portfolio_backtest`) | 현재의 **입력, 동작, fingerprint를 바꾸지 않는다.** 정책 프로필 인자를 새로 요구하지 않는다. 이 API의 동작이 곧 암묵적 `V1_COMPAT`다 |
| **기존 백테스트 재현** | 기존 V1 API를 그대로 호출(암묵적 `V1_COMPAT`)하거나, 새 API에서 `V1_COMPAT`를 **명시적으로** 선택해 쓸 수 있다 |
| **새 연구 API** (ADR-0001~0003을 구현하는 새 진입점) | 정책 프로필을 **명시적으로** 선택해야 한다 (`RESEARCH`, 또는 재현 목적의 `V1_COMPAT`). **기본값은 없다.** 누락하면 ValueError |
| **Paper/Live** | `V1_COMPAT`를 선택할 수 없다 (ValueError). 허용되는 프로필은 `LIVE`뿐이다. 기존 V1 API는 거래 전 안전 검사가 없으므로 Paper/Live의 주문 경로에서 호출하지 않는다 |
| **우회 금지** | 프로필 누락, 알 수 없는 값, 빈 문자열, `None`, 대소문자 변형 등 어떤 형태로도 기본값이나 `V1_COMPAT`로 대체되지 않는다. Paper/Live에서는 설정 검증 단계에서 시작을 거부한다 (fail-closed) |
| **확인 수준** | 구현 전이므로 기존 306개 테스트 통과, 기존 실행 결과 보존, 기존 fingerprint 보존은 모두 **INFERRED**다. 보존 방법은 P0-03에서 정한다 (ADR-0001 Q1-9) |

### 8.1 요구사항 (R1)

`V1_COMPAT`는 다음을 **모두** 만족해야 한다. 하나라도 만족하지 못하면 그 구현은 호환 모드로 인정하지 않는다.

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| C-1 | 기존 306개 테스트가 기대값 수정 없이 통과 | `python -m pytest -q -W error` |
| C-2 | 기존 실행 결과(일별 PnL, 포지션, 체결가, 비용, 계좌)가 V1과 같음. 비-roll일과 **roll일 모두** | 회귀 테스트 (AT-0001-4) |
| C-3 | 기존 입력 fingerprint와 결과 fingerprint가 바뀌지 않음 | 기존 입력으로 계산한 fingerprint 값을 고정해 비교하는 회귀 테스트 |
| C-4 | §8.0의 경로별 규칙을 지킴: Paper/Live에서 `V1_COMPAT` 선택 불가, 새 연구 API는 프로필 명시 필수, 누락·잘못된 값으로 우회 불가 | 설정 검증 테스트. 위반하면 `ValueError` |

### 8.2 현재 확인 수준

| 항목 | 상태 |
|---|---|
| 비-roll일의 동치성 | 거래가 있는 비-roll step 154건 모두 mid = 평가가격 (CONFIRMED, 측정, §3.2). 대수적으로는 `V := mid`일 때 V1과 같다 (§6.2). 그러나 **구현이 없으므로 C-2는 INFERRED** |
| roll일의 동치성 | **INFERRED.** roll일 18건은 step 입력에 월물별 원시 종가가 없어서 측정하지 못했다. `V1_COMPAT`가 보유분 항과 체결분 항에 서로 다른 가격 기준을 쓰므로(§6.4), 롤오버까지 V1과 같게 동작하는지는 구현과 회귀 검증으로 확인해야 한다 |
| fingerprint 보존 | **아직 방법이 없다 (CONFIRMED 제약).** canonical payload는 dataclass의 **모든 필드**를 직렬화한다 (`backtest_manifest.py:332-346`). 따라서 `ExecutionMarketDay` 등에 필드를 추가하면 기본값이 있어도 기존 fingerprint가 바뀐다. 보존 방법(호환 모드에서 새 필드를 payload에서 빼는 방식, 별도 타입, schema version 분기 등)은 P0-03에서 정한다 (Q1-9) |

### 8.3 호환 모드의 한계

- `V1_COMPAT`의 전제(quote mid = 당일 평가가격, quote에 시각 정보 없음)는 **검증된 시장 사실이 아니라 V1 테스트 데이터의 성질**이다.
- 따라서 호환 모드를 근거로 미래 데이터 사용이나 잘못된 시점 가정을 새 운영 경로에 허용하지 않는다. 경로별 규칙은 §8.0이다. 요약하면 Paper/Live에서는 쓸 수 없고, 새 연구 API에서는 재현 목적으로 명시적으로 선택할 때만 쓴다.
- 새 연구 API에서 `V1_COMPAT`를 명시해 실행한 결과는 manifest에 모드를 기록한다. 기존 V1 API의 manifest와 fingerprint는 바꾸지 않는다 (§8.0, R2). 두 경우 모두 보고서에는 "V1 가정(mid = 평가가격)"이라고 표시한다.

### 8.4 그 밖의 영향

| 항목 | 영향 |
|---|---|
| 일반 모드 | 새 입력(평가가격, 타임스탬프)이 필요하므로 기존 테스트 입력으로는 실행되지 않는다. 새 테스트로 검증한다 |
| 경로 A·B1 (`daily_step`, `roll_aware_daily_step`) | 이 ADR의 일반 모드를 적용하지 않는다. 경로 위상은 별도 결정(D-02) |

## 9. Financial Integrity Implications

- **Look-ahead**: 불변조건을 강제하면 "종가 공표 전에 종가 기반 신호로 주문"하는 오류를 막을 수 있다. 백테스트에서는 `data_available_at`이 가정값이므로, 그 가정을 manifest에 기록해야 한다.
- **손익 누락·왜곡**: 일반 모드에서는 체결 시각과 평가 시각의 차이를 반영한다 (S1, S2).
- **비용 측정**: 비용은 여전히 체결 시각 mid 대비로 측정한다. 체결가 기준 손익과 mid 기준 비용 차감을 함께 쓰면 비용이 이중으로 빠진다. §6.2의 "이중 차감 금지" 규칙을 따른다 (AT-0001-8).
- **비용 부호**: 절댓값 형태의 비용은 불리한 체결의 시장가 주문에서만 맞다. 지정가 주문을 도입하면 부호 있는 분해가 필요하다.
- **FX와 수수료 통화**: R2에서 환산율을 통화별 `fx[κ,t]`로 바꿨다. 통화가 다른 손익은 환산한 뒤에만 더한다. 체결 시각 환율과 평가 시각 환율을 나눌지, 수수료를 어느 통화로 받는지, 수수료에 어느 시점의 환율을 쓰는지는 여전히 **미해결**이다 (Q1-4, D-08, GAP F-06).
- **FX 변동 자체의 평가 효과**: 외화 현금·예치금의 기준통화 평가액이 환율 변동만으로 바뀌는 효과는 이 공식에 없다. D-08의 별도 검토 사항이다 (§6.2).
- **승수 혼용**: 상품마다 승수가 다르다. 포트폴리오 공통 승수를 쓰면 손익이 자릿수 단위로 틀린다 (AT-0001-9의 W3).
- **평가 주기 귀속**: 평가 시각 이후 체결을 그 주기에 넣으면 주기별 손익, 주기 종료 보유 수량, drawdown이 틀어진다 (§5.1.3, AT-0001-7).
- **Roll**: roll 날짜와 그 결정 시점의 출처는 여전히 UNVERIFIED다 (F-07). 이 ADR은 roll 일정 생성 규칙을 정하지 않는다.

## 10. Acceptance Criteria

모든 숫자 예제는 감사용 일회성 스크립트(저장소 밖)로 계산했다. 독립 산술 결과와 V1 함수 결과를 대조했다. 단위: M=10 IC/pt/ct, fx=1, 수수료 1 IC/ct.

### AT-0001-1 Quote mid와 평가가격이 다른 경우 (시나리오 1)

- **입력**: 보유 0 → 목표 10. `V[t−1]=100`, quote bid/ask 101.9/102.1 (mid 102), `V[t]=104`, `V[t+1]=105`.
- **기대 출력**:

| 항목 | V1 / 호환 모드 | 일반 모드 |
|---|---|---|
| t일 체결 | +10 @ 102.1 | +10 @ 102.1 |
| t일 PnL | −20 (비용 20 = 수수료 10 + 0.1×10×10) | +180 = 10×(104−102.1)×10 − 10 |
| t+1일 PnL | +100 = 10×(105−104)×10 | +100 |
| 2일 합계 | **80** | **280** |
| 차이 | — | 200 = 10×(104−102)×10 (valuation gap) |

  V1 결과(−20)는 `run_daily_step` 실행으로 확인했다 (CONFIRMED).
- **전제**: 같은 월물, roll 없음
- **예외**: `V[t]`가 없으면 ValueError
- **V1 비교 방법**: 같은 입력에서 `V := mid`로 두면 일반 모드 결과가 V1과 같아야 한다
- **새 테스트 후보**: `test_general_accounting_includes_valuation_gap`, `test_compat_mode_equals_v1_when_valuation_equals_mid`

### AT-0001-2 종가 체결과 시가 체결의 손익 차이 (시나리오 2)

- **입력**: `V[t−1]=100`, 시가 103, 종가 `V[t]=104`, 반스프레드 0.1
- **기대 출력**:

| 경우 | 체결 | t일 PnL | 계산 |
|---|---|---|---|
| A: 종가 부근 체결 (mid 104) | +10 @ 104.1 | **−20** | 10×(104−104.1)×10 − 10 |
| B: 시가 부근 체결 (mid 103) | +10 @ 103.1 | **+80** | 10×(104−103.1)×10 − 10 |
| B: 5 → 10 | +5 @ 103.1 | **+240** | 5×4×10 + 5×(104−103.1)×10 − 5 |
| B: 10 → 5 | −5 @ 102.9 | **+340** | 10×4×10 + (−5)×(104−102.9)×10 − 5. 검산: 매도 5개 100→102.9 = 145, 유지 5개 = 200, 수수료 −5 |

- **해석**: A와 B의 차이 100은 개장부터 종가까지의 움직임(103→104) × 체결 수량 × M이다. 어느 쪽이 맞는지는 실제 체결 시각에 달려 있다. 이 ADR은 시각을 고정하지 않는다.
- **새 테스트 후보**: `test_open_fill_accounts_open_to_close_move`, `test_reduce_at_open_realises_prev_close_to_fill`

### AT-0001-3 Roll일 손익 연속성

- **입력**: A 월물 5개 보유. `V[A,t−1]=100`, `V[A,t]=101`, `V[B,t]=111`. 롤: A 매도 5 @100.4 (mid 100.5), B 매수 5 @110.1 (mid 110.0)
- **기대 출력**:
  - 일반 모드: 보유분 50 + A leg −5×(101−100.4)×10 = −30 + B leg 5×(111−110.1)×10 = +45 − 수수료 10 = **55**
  - V1 / 호환 모드: gross 50 − 비용 20 = **30**
  - 차이 25 = A leg gap (−25) + B leg gap (+50)
  - t+1일 보유분은 `5 × (V[B,t+1] − 111) × 10`
- **새 테스트 후보**: `test_roll_legs_valued_at_each_contract_close`

### AT-0001-4 V1 동치성 (회귀)

- 호환 모드에서 기존 306개 테스트가 기대값 수정 없이 통과해야 한다.

### AT-0001-7 평가 시각 이후에 체결이 발생하는 경우 (R1 추가, 인수 테스트 명세 1)

- **입력**: 단위 M=10 IC/pt/ct, fx=1, 수수료 1 IC/ct. 보유 0. `V[t−1]=100`, `V[t]=104`, `V[t+1]=105`. 매수 +10 주문이 `valuation_at(t)` **이후**(예: 시간외)에 104.1로 체결됨. 그 시각의 mid는 104.0
- **기대 출력**:

| 항목 | 올바른 귀속 (t+1) | 잘못된 귀속 (t) |
|---|---|---|
| 주기 t PnL | **0** (보유 0, 체결 없음) | 10×(104−104.1)×10 − 10 = −20 |
| 주기 t 종료 보유 `q[t]` | **0** | 10 |
| 주기 t+1 PnL | 10×(105−104.1)×10 − 10 = **80** | 10×(105−104)×10 = 100 |
| 2주기 합계 | 80 | 80 |

- **판단 근거**: §5.1.3. 합계는 같지만 주기 t의 손익, 보유 수량, 그리고 이를 쓰는 계좌 평가와 위험 검사가 달라진다. 주기 t 종료 시점의 위험 snapshot에 아직 체결되지 않은 포지션이 들어가면 안 된다.
- **예외조건**: 다음 평가 시각이 없으면 ValueError (경계 B-9). `V[t+1]`이 없으면 ValueError
- **V1 비교**: V1에는 시각 정보가 없으므로 이 상황을 표현할 수 없다. 새 모드에서만 검증한다
- **새 테스트 후보**: `test_fill_after_valuation_is_attributed_to_next_period`, `test_period_end_position_excludes_post_valuation_fill`

### AT-0001-8 이중 차감 방지 (R1 추가, 인수 테스트 명세 2)

- **입력**: AT-0001-1과 같다. 보유 0 → +10, bid/ask 101.9/102.1 (mid 102), 체결 102.1, `V[t]=104`, M=10, fx=1, 수수료 10
- **기대 출력** (주기 t):

| 계산 | 값 | 판정 |
|---|---|---|
| (a) 체결가 기준: 10×(104−102.1)×10 − 10 | **180** | 정답 |
| (b) mid 기준 분해: gap 10×(104−102)×10 = 200, 부호 있는 체결 비용 10×(102.1−102)×10 = 10, 수수료 10 → 200 − 10 − 10 | **180** | 정답. (a)와 같아야 함 |
| 잘못된 계산: (a) − 체결 비용 10 | 170 | **이중 차감. 테스트에서 실패해야 함** |

- **변형 (가격 개선 체결, 부호 있는 분해가 필요한 경우)**: 같은 조건에서 지정가 매수가 101.95(mid 102보다 0.05 쌈)에 체결
  - 체결가 기준: 10×(104−101.95)×10 − 10 = **195**
  - 부호 있는 분해: gap 200, 체결 비용 10×(101.95−102)×10 = **−5** → 200 − (−5) − 10 = **195** (일치)
  - 절댓값 분해를 잘못 쓰면: 200 − 5 − 10 = 185 (10 차이)
  - V1의 `calculate_execution_price_cost`는 이 입력에서 `ValueError`를 낸다 (CONFIRMED, `costs.py:50-57`). V1 호환 모드는 이 체결을 지원하지 않는다
- **판단 근거**: §6.2의 항등식과 이중 차감 금지 규칙
- **예외조건**: 호환 모드에서 불리하지 않은 체결(매수 < mid, 매도 > mid)이 들어오면 V1과 같이 ValueError. 일반 모드에서는 허용
- **새 테스트 후보**: `test_fill_price_pnl_does_not_subtract_execution_cost_again`, `test_cost_breakdown_reconciles_to_total_pnl`, `test_price_improvement_uses_signed_cost`

### AT-0001-9 계약승수와 통화가 다른 두 상품 (R2 추가)

가상의 상품 두 개를 쓴다. 특정 실제 상품의 사양이 아니다. 기준통화 BC = KRW. 환산율과 수수료는 계산을 보여 주기 위한 숫자다.

- **입력**:

| 항목 | 상품 A | 상품 B |
|---|---|---|
| 거래통화 κ | KRW (= BC) | USD |
| 계약승수 `M[c]` | 250,000 KRW/pt/ct | 50 USD/pt/ct |
| `fx[κ,t]` | 1 | 1,350 KRW/USD |
| 보유 `q[c,t−1]` | +2 ct | −3 ct |
| `V[c,t−1]` → `V[c,t]` | 350.00 → 352.00 | 5,000.00 → 4,990.00 |
| 주기 t의 체결 (평가 시각 이전) | +1 ct @ 351.10 | −1 ct @ 4,995.00 |
| 수수료 (거래통화로 가정, Q1-4) | 5,000 KRW | 2.5 USD |

- **기대 출력** (독립 산술로 계산):

| 항목 | 상품 A (KRW) | 상품 B (USD) |
|---|---|---|
| 보유분 | 2 × (352.00 − 350.00) × 250,000 = 1,000,000 | −3 × (4,990.00 − 5,000.00) × 50 = 1,500 |
| 체결분 | 1 × (352.00 − 351.10) × 250,000 = 225,000 | −1 × (4,990.00 − 4,995.00) × 50 = 250 |
| 수수료 | −5,000 | −2.5 |
| `PnL_κ` | **1,220,000 KRW** | **1,747.5 USD** |
| 기준통화 환산 | × 1 = 1,220,000 | × 1,350 = 2,359,125 |

  `PnL[t]` = 1,220,000 + 2,359,125 = **3,579,125 KRW**

- **잘못된 계산 (테스트에서 실패해야 함)**:

| ID | 오류 | 결과 | 차이 |
|---|---|---|---|
| W1 | 환산 전에 통화를 더함 (1,220,000 + 1,747.5) | 1,221,747.5 | −2,357,377.5 |
| W2 | 공통 스칼라 fx(1,350)를 모든 통화 합계에 적용 (R0 공식을 그대로 쓴 경우) | 1,649,359,125 | 약 460배 |
| W3 | B에도 A의 승수 250,000을 씀 | 11,813,716,625 | 약 3,300배 |

- **판단 근거**: §6.2 공식 (1)·(2). 체결마다 그 월물의 승수를 쓰고, 통화별로 합한 뒤 환산한다
- **특수 사례 확인**: B를 빼면 공식은 R0 형태와 같고, A만의 결과 1,220,000은 단일 상품 계산과 같다
- **예외조건**: `fx[USD,t]`가 없으면 ValueError (1로 대체하지 않음). 같은 주기에 USD 환산율이 두 개(예: 1,350과 1,351) 들어오면 ValueError. 체결 기록의 승수가 상품 사양과 다르면 ValueError
- **범위 밖**: 이 예제는 거래 손익만 다룬다. 환율 변동만으로 외화 현금 평가액이 바뀌는 효과는 D-08이다
- **새 테스트 후보**: `test_multi_currency_pnl_converts_before_summing`, `test_each_fill_uses_its_contract_multiplier`, `test_missing_fx_for_currency_is_rejected`, `test_conflicting_fx_for_same_currency_is_rejected`
