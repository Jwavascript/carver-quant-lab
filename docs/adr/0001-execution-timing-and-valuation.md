# ADR-0001: 체결 시점과 손익 회계 (Execution Timing and Valuation)

## 1. Title

체결 시점, 평가가격, 일간 손익 회계 모델

## 2. Status

**PROPOSED**. 사용자 승인 전이다. 승인 전에는 ACCEPTED로 바꾸지 않는다.

- 작성일: 2026-10-16
- 기준 커밋: `df6547e` (306 passed)
- 관련 P0-01 항목: GAP `F-02`(P0), `F-03`, `F-06`, `F-07`, `A-07`. 결정 ID는 D-03.

## 3. Context

### 3.1 V1의 현재 동작 (CONFIRMED)

V1의 일간 처리 순서는 다음과 같다 (`contract_aware_daily_step.py:126-258`, `daily_step.py:41-102`).

1. 전일 보유 포지션 × (당일 adjusted price − 전일 adjusted price) × multiplier × fx = gross PnL
2. t−1 signal로 목표 포지션을 계산 (`system_backtest.py:176-183`)
3. 당일 quote에서 매수는 ask, 매도는 bid (± 슬리피지)로 체결
4. 비용 = 수수료 + |체결가 − quote mid| × multiplier × |수량|
5. 새 포지션은 다음 날 gross PnL에서 **당일 adjusted 종가**부터 평가

당일 거래한 수량에 대해 "체결가 → 당일 평가가격" 구간의 손익은 계산하지 않는다. 그래서 **quote mid = 당일 평가가격**이라는 가정이 숨어 있다. quote에는 시각 정보가 없다 (`system_backtest.py:28-47`).

### 3.2 기존 테스트가 이 가정을 어떻게 쓰는가 (CONFIRMED, 측정)

감사용 일회성 pytest plugin(저장소 밖)으로 306개 테스트를 실행하면서 step 호출을 기록했다. 거래가 발생한 비-roll step 호출 **154건 모두에서 quote mid가 `current_adjusted_price`와 정확히 같았다** (`daily_step` 11건, `contract_aware_daily_step` 143건). roll일 호출 18건은 step 입력에 월물별 원시 종가가 없어서 비교하지 못했다 (UNVERIFIED).

### 3.3 운영 조건

- 일간 신호, **하루 1회 사용자 점검**이 전제다 (CLAUDE.md §1).
- 하루 1회 사용자 점검은 **감독 행위**다. 주문 제출, 체결 확인, 미체결 처리, Reconciliation은 사람의 점검과 별개로 **자동으로** 수행되어야 한다 (CLAUDE.md §8). 사람의 점검 주기가 하루 1회라고 해서 체결 상태 확인도 하루 1회면 된다는 뜻은 아니다.
- 거래 시장과 브로커가 정해지지 않았다. 따라서 **이 ADR은 특정 거래 시각(시가, 종가, 특정 시각)을 확정하지 않는다.**

## 4. Decision Drivers

1. **시점 무결성**: 주문 결정에 쓰는 데이터는 주문 시점에 실제로 사용 가능해야 한다 (look-ahead 금지).
2. **실제 주문 가능성**: 백테스트의 체결 가정을 실제 시장과 브로커 주문 유형으로 재현할 수 있어야 한다.
3. **회계 정합성**: 체결가, quote mid, 평가가격이 서로 다른 시각의 값일 때 그 차이가 손익에 정확히 반영되어야 한다.
4. **Raw와 Adjusted의 구분**: 체결과 평가에는 거래 가능한 원시 가격을, 신호에는 조정 가격을 쓴다.
5. **ETF·선물 공통성**: 같은 회계식이 roll(선물)과 분배금(ETF)을 모두 다룰 수 있어야 한다.
6. **V1 호환성**: 기존 306개 테스트를 기대값 수정 없이 통과시킬 수 있는 경로가 있어야 한다.
7. **구현 복잡도**: Phase 0~1 규모에 맞아야 한다.

## 5. Considered Options

### 5.1 용어 정의 (모든 대안에 공통)

| 용어 | 의미 | 비고 |
|---|---|---|
| `signal_as_of` | 신호가 반영하는 시장 데이터의 마지막 관측 시각. 예: "세션 t−1의 종가" | 데이터의 *내용* 시각 |
| `data_available_at` | 그 데이터가 시스템에서 실제로 사용 가능해진 시각 | 종가·정산가는 세션이 끝난 뒤 일정 지연을 두고 공표될 수 있다. 지연 시간은 시장과 데이터 공급자에 따라 다르다 (UNVERIFIED) |
| `order_submitted_at` | 주문을 브로커에 제출한 시각. 백테스트에서는 가정값 | 항상 `data_available_at` 이후여야 함 |
| `fill_at` | 체결 시각. 체결가는 이 시각의 quote에서 결정됨 | 부분 체결이면 여러 개 |
| `valuation_at` | 손익 평가 시각. 평가가격은 이 시각의 가격 | 세션 종가, 거래소 정산가 중 무엇을 쓸지는 미정 (Open Question Q1-2) |

**시점 불변조건 (Timestamp Invariant)**:

```
signal_as_of ≤ data_available_at ≤ order_submitted_at ≤ fill_at
fill_at ≤ valuation_at   (같은 평가 주기 안에서 평가할 때)
```

`fill_at > valuation_at(t)`인 체결은 다음 평가 주기 t+1에 귀속된다.

| 가격 종류 | 정의 | 용도 |
|---|---|---|
| Raw Tradable Price `P[c,t]` | 월물 c(또는 ETF 종목)의 실제 거래 가격 | 체결, 평가, 명목가치 |
| Back-adjusted Price | roll gap(선물) 또는 분배금·분할(ETF)을 반영한 연속 시계열 | **신호 계산 전용** (PIT로 생성) |
| Quote mid `mid[c,fill_at]` | 체결 시각의 (bid + ask) / 2 | 체결 비용 측정 기준 |
| Valuation price `V[c,t]` | `valuation_at(t)`의 월물 c 가격 | 평가 손익 |

### 5.2 대안 A — 전일 종가 신호 → 당일 종가 부근 체결 → 다음 날부터 새 포지션 평가 (V1)

- 회계: V1 그대로 (§3.1). 당일 체결 수량의 체결→평가 구간 손익은 0으로 간주한다.
- 전제: `mid[c,fill_at] = V[c,t]`
- 실제 주문 방법: 종가 단일가나 MOC(Market-On-Close) 계열 주문이 필요하다. 대상 시장에 그런 주문이 있는지는 UNVERIFIED.

### 5.3 대안 B — 전일 종가 신호 → 다음 세션 시가 부근 체결 → 체결부터 당일 종가까지 손익 반영

- 회계: 일반화 회계식(§6.2)으로, 체결 수량에 `Δq × (V[c,t] − F)`를 반영한다.
- 실제 주문 방법: 시가 단일가, MOO(Market-On-Open), 장 초반 지정가 등. 대상 시장의 지원 여부는 UNVERIFIED.
- 추가로 필요한 데이터: 체결 시각의 quote, 거래한 월물의 당일 평가가격

### 5.4 대안 C — 신호·주문·체결·평가를 모두 타임스탬프 이벤트로 분리하는 일반 모델

- 회계: 이벤트 스트림(시장 데이터, 신호, 주문, 체결, 평가)을 시간순으로 처리한다.
- 장중 다회 체결, 부분 체결, 정정·취소, 장중 위험 점검까지 다룰 수 있다.

### 5.5 비교

| 기준 | A (V1) | B | C |
|---|---|---|---|
| 구현 복잡도 | 가장 낮음. 이미 구현됨 | 중간. 회계식 항 1개, 평가가격 입력, 타임스탬프 필드 추가 | 높음. 이벤트 엔진, 주문 상태 기계, 시간 정렬 |

| ETF 확장 | 분배금 현금흐름 없음 | 분배금 현금흐름 항을 추가하기 쉬움 | 가능 |
| 기존 306개 테스트 | 변경 없음 | **호환 모드(평가가격 := quote mid)를 쓰면 변경 없음** (§8) | 대규모 재작성 |
| Live 주문 상태 관리 | 다루지 않음 | 다루지 않음 (ADR-0003, Phase 1) | 직접 다룸 |

## 6. Proposed Decision

### 6.1 결정 요지

**B의 일반화 회계식을 표준 회계 규칙으로 채택한다. 체결 시점은 코드에 고정하지 않고 데이터 계약(타임스탬프 필드)과 설정으로 표현한다. A(V1)는 이 회계식의 특수 사례로 보존한다. C는 일간 손익 회계에는 쓰지 않고, Live 주문 생애주기 관리가 필요해지는 Phase 1 이후에 별도 ADR로 재검토한다.**

- 시가 체결과 종가 체결 가운데 어느 쪽을 운영 기본값으로 할지는 **결정하지 않는다.** 시장과 브로커가 정해진 뒤 사용자가 결정한다 (Q1-1).
- 이 ADR은 회계식과 시점 불변조건만 정한다.

### 6.2 일반화 일간 회계식 (공식 명세, CLAUDE.md §3.2)

**입력**

| 기호 | 의미 | 단위 |
|---|---|---|
| `q[c,t−1]` | 평가 주기 t 시작 시 월물(종목) c의 보유 수량 | ct (정수) |
| `V[c,t]`, `V[c,t−1]` | 월물 c의 평가가격 (raw) | pt |
| `Δq[k]` | 주기 t 안의 체결 k의 수량 (매수 +, 매도 −) | ct (정수, ≠0) |
| `F[k]` | 체결 k의 체결가 (raw) | pt |
| `c(k)` | 체결 k의 월물 | — |
| `M` | multiplier | IC/pt/ct |
| `fee[k]` | 체결 k의 수수료 | IC (≥0) |
| `fx[t]` | 기준통화 환산율 | BC/IC (>0) |
| `D[c,t]` | (ETF) 주기 t에 귀속되는 주당 분배금 | IC/ct. 선물은 0 |

**출력**: `PnL[t]` (BC)

**공식**

```
PnL[t] = fx[t] × (  Σ_c  q[c,t−1] × (V[c,t] − V[c,t−1]) × M          ← 보유분 평가손익
                  + Σ_k  Δq[k]   × (V[c(k),t] − F[k])   × M          ← 체결분: 체결가→평가가격
                  + Σ_c  q[c,t−1] × D[c,t]                           ← (ETF) 분배금
                  − Σ_k  fee[k] )
```

**보조 분해** (보고용):

```
Δq × (V − F) × M  =  Δq × (V − mid) × M      ← valuation gap (체결 시각 mid → 평가가격)
                   − |Δq| × |F − mid| × M     ← 체결가 비용 (스프레드 + 슬리피지, V1의 execution price cost)
```

두 번째 항이 V1 비용과 같다 (`costs.py:23-70`). 즉

```
일반화 PnL = V1 PnL + fx × Σ_k Δq[k] × (V[c(k),t] − mid[k]) × M    (D=0일 때)
```

**전제조건**

- 시점 불변조건(§5.1)이 성립해야 한다.
- 체결가 `F[k]`와 평가가격 `V`는 같은 월물의 **raw** 가격이어야 한다. adjusted 가격을 쓰면 안 된다.
- 보유분 항은 raw 가격 차이를 쓴다. 가산 back-adjustment에서는 같은 보유 월물에 대해 adjusted 가격 차이와 raw 가격 차이가 같다. 그래서 V1의 adjusted 차이 계산은 선물에서 동치다 (INFERRED. V1 테스트 `test_roll_gap_does_not_create_artificial_return`이 일부를 확인함). ETF의 곱셈 조정에서는 동치가 아니므로 반드시 raw + `D`를 쓴다.

**예외조건 (ValueError, fail-fast)**

- 거래했거나 보유한 월물의 `V[c,t]`가 없음
- 시점 불변조건 위반 (예: `data_available_at > order_submitted_at`)
- `F`, `V`, `M`, `fx`가 비유한값이거나 `M ≤ 0`, `fx ≤ 0`
- `fee < 0`, `Δq = 0`
- 값을 보간하거나 0으로 대체하지 않는다.

### 6.3 Roll 구간

롤은 같은 주기 안의 두 체결(구월물 매도 leg, 신월물 매수 leg)로 표현한다. 두 월물 모두 `V[·,t]`가 필요하다. 이 데이터는 V1 back-adjustment가 이미 요구하는 roll일 두 월물 종가와 같다 (`futures_data.py:103-113`). 다음 주기부터 보유분 항은 신월물 raw 가격 차이를 쓴다.

### 6.4 단계 적용 (구현은 이 ADR의 범위 밖)

1. P0-03 Domain Contracts: 타임스탬프 필드와 평가가격 입력을 데이터 계약으로 정의한다.
2. P0-04: 일반화 회계식을 독립 계산으로 검증한다 (§10의 숫자 예제).
3. 구현 단계: 호환 모드(`V := mid`, 즉 valuation gap = 0)를 기본값으로 두어 기존 테스트를 보존한다. 일반 모드는 명시적으로 켠다.

## 7. Consequences / Trade-offs

**장점**
- 시가 체결이든 종가 체결이든 같은 회계식으로 처리하므로, 체결 시점 결정을 미룰 수 있다.
- 숨은 가정(mid = 평가가격)이 명시적인 항(valuation gap)이 되어 보고하고 검증할 수 있다.
- ETF 분배금을 같은 식에 넣을 수 있다.

**단점과 비용**
- 데이터 요구가 늘어난다: 체결 시각 quote, 거래 월물의 평가가격, (일반 모드) 타임스탬프.
- 호환 모드와 일반 모드가 공존하는 동안 설정을 잘못 고르면 결과가 달라진다. manifest에 모드를 기록해야 한다 (A-09).
- B 방식의 시가 체결은 개장 단일가나 갭 위험을 가진다. 시가 quote의 품질과 유동성은 UNVERIFIED.

**하지 않는 것**
- 장중 다회 체결, 주문 상태 기계, 정정·취소는 다루지 않는다 (C, Phase 1 이후).

## 8. Compatibility with V1

| 항목 | 영향 |
|---|---|
| 기존 306개 테스트 | **호환 모드에서는 변경 없음** (INFERRED). 근거: 회계식이 `V := mid`일 때 V1과 대수적으로 같고(§6.2), 거래가 있는 비-roll step 154건 모두 mid = 평가가격이다 (CONFIRMED, §3.2). roll일 18건도 호환 모드 정의상 gap 항이 0이므로 영향이 없다 |
| 일반 모드 | 새 입력(평가가격, 타임스탬프)이 필요하므로 기존 테스트 입력으로는 실행되지 않는다. 새 테스트로 검증한다 |
| `ExecutionMarketDay` / fingerprint | 필드를 추가하면 입력 fingerprint가 바뀐다 (A-02, A-09). P0-03에서 schema version 정책과 함께 다룬다 |
| 경로 A·B1 (`daily_step`, `roll_aware_daily_step`) | 이 ADR의 일반 모드를 적용하지 않는다. 경로 위상은 별도 결정(D-02) |

## 9. Financial Integrity Implications

- **Look-ahead**: 불변조건을 강제하면 "종가 공표 전에 종가 기반 신호로 주문"하는 오류를 막을 수 있다. 백테스트에서는 `data_available_at`이 가정값이므로, 그 가정을 manifest에 기록해야 한다.
- **손익 누락·왜곡**: 일반 모드에서는 체결 시각과 평가 시각의 차이를 반영한다 (S1, S2).
- **비용 측정**: 비용은 여전히 체결 시각 mid 대비로 측정한다. 평가가격 대비 측정과 섞으면 비용이 이중으로 계산될 수 있으므로 보조 분해의 정의를 따른다.
- **FX**: 이 ADR은 `fx[t]` 하나를 유지한다. 체결 시각 환율과 평가 시각 환율을 나눌지는 미정이다 (Q1-4, D-08).
- **Roll**: roll 날짜와 그 결정 시점의 출처는 여전히 UNVERIFIED다 (F-07). 이 ADR은 roll 일정 생성 규칙을 정하지 않는다.

## 10. Acceptance Criteria

모든 숫자 예제는 감사용 일회성 스크립트(저장소 밖)로 계산했다. 독립 산술 결과와 V1 함수 결과를 대조했다. 단위: M=10 IC/pt/ct, fx=1, 수수료 1 IC/ct.

### AT-0001-1 Quote mid와 평가가격이 다른 경우 (시나리오 1)

- **입력**: 보유 0 → 목표 10. `V[t−1]=100`, quote bid/ask 101.9/102.1 (mid 102), `V[t]=104`, `V[t+1]=105`.
- **기대 출력**:

| 항목 | V1 / 호환 모드 | 일반 모드 |
|---|---|---|
| t일 체결 | +10 @ 102.1 | +10 @ 102.1 |
| t일 PnL | −20 (비용 20 = 수수료 10 + 0.1×10×10) | +180 = 10×(104−102.1)×10 − 10 |
| t+1일 PnL | +100 = 10×(105−104)×10 | +100 |
| 2일 합계 | **80** | **280** |
| 차이 | — | 200 = 10×(104−102)×10 (valuation gap) |

  V1 결과(−20)는 `run_daily_step` 실행으로 확인했다 (CONFIRMED).
- **전제**: 같은 월물, roll 없음
- **예외**: `V[t]`가 없으면 ValueError
- **V1 비교 방법**: 같은 입력에서 `V := mid`로 두면 일반 모드 결과가 V1과 같아야 한다
- **새 테스트 후보**: `test_general_accounting_includes_valuation_gap`, `test_compat_mode_equals_v1_when_valuation_equals_mid`

### AT-0001-2 종가 체결과 시가 체결의 손익 차이 (시나리오 2)

- **입력**: `V[t−1]=100`, 시가 103, 종가 `V[t]=104`, 반스프레드 0.1
- **기대 출력**:

| 경우 | 체결 | t일 PnL | 계산 |
|---|---|---|---|
| A: 종가 부근 체결 (mid 104) | +10 @ 104.1 | **−20** | 10×(104−104.1)×10 − 10 |
| B: 시가 부근 체결 (mid 103) | +10 @ 103.1 | **+80** | 10×(104−103.1)×10 − 10 |
| B: 5 → 10 | +5 @ 103.1 | **+240** | 5×4×10 + 5×(104−103.1)×10 − 5 |
| B: 10 → 5 | −5 @ 102.9 | **+340** | 10×4×10 + (−5)×(104−102.9)×10 − 5. 검산: 매도 5개 100→102.9 = 145, 유지 5개 = 200, 수수료 −5 |

- **해석**: A와 B의 차이 100은 개장부터 종가까지의 움직임(103→104) × 체결 수량 × M이다. 어느 쪽이 맞는지는 실제 체결 시각에 달려 있다. 이 ADR은 시각을 고정하지 않는다.
- **새 테스트 후보**: `test_open_fill_accounts_open_to_close_move`, `test_reduce_at_open_realises_prev_close_to_fill`

### AT-0001-3 Roll일 손익 연속성

- **입력**: A 월물 5개 보유. `V[A,t−1]=100`, `V[A,t]=101`, `V[B,t]=111`. 롤: A 매도 5 @100.4 (mid 100.5), B 매수 5 @110.1 (mid 110.0)
- **기대 출력**:
  - 일반 모드: 보유분 50 + A leg −5×(101−100.4)×10 = −30 + B leg 5×(111−110.1)×10 = +45 − 수수료 10 = **55**
  - V1 / 호환 모드: gross 50 − 비용 20 = **30**
  - 차이 25 = A leg gap (−25) + B leg gap (+50)
  - t+1일 보유분은 `5 × (V[B,t+1] − 111) × 10`
- **새 테스트 후보**: `test_roll_legs_valued_at_each_contract_close`

### AT-0001-4 V1 동치성 (회귀)

- 호환 모드에서 기존 306개 테스트가 기대값 수정 없이 통과해야 한다.
- 추가 속성 테스트 후보: 무작위 입력에서 `V := mid`일 때 일반 회계식과 V1 회계식의 차이가 부동소수점 허용 오차 안에 있어야 한다. 허용 오차는 근거를 두고 정한다 (CLAUDE.md §3.2).

### AT-0001-5 시점 불변조건

- `data_available_at > order_submitted_at`이거나 `fill_at < order_submitted_at`이면 ValueError
- `fill_at > valuation_at(t)`이면 해당 체결은 t+1에 귀속된다
- **새 테스트 후보**: `test_order_before_data_available_is_rejected`, `test_fill_after_valuation_rolls_to_next_period`

### AT-0001-6 ETF 분배금 (명세만, 수치는 예시)

- **입력**: 100주 보유, 주당 분배금 0.5, raw 가격이 분배락으로 50.0 → 49.5 (그 밖의 변동 없음), M=1
- **기대 출력**: 보유분 100×(49.5−50.0) = −50, 분배금 +50, 합계 **0**
- **미정**: 분배금을 귀속하는 날짜 기준(배당락일, 지급일)은 Q1-5
