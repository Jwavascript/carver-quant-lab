**승인된 원칙**

1. 자산 유형별 Tagged Union을 쓴다 (§6.1, §6.2).
2. 공통 구성요소는 합성(Composition)으로 재사용한다 (§6.2).
3. `FuturesInstrument`와 `EtfInstrument`를 구분한다 (§6.2).
4. 선물의 상품 ID와 실제 거래 월물 ID를 구분한다 (§6.2, I6-3).
5. ETF의 거래 단위는 상장 종목 자체다 (§6.2, I6-4).
6. 선물 롤과 ETF 분배금·분할을 서로 다른 금융 이벤트로 처리한다 (I6-1, I6-2, I6-8, I6-9).
7. 거래 가능한 raw 가격과 연구용 조정 가격을 구분한다 (I6-7).
8. 기존 V1 `InstrumentSpec`은 재현성을 위해 보호한다 (§6.7).
9. 상품별 승수, 통화, 수량 단위와 자산 유형별 비용·자금 제약을 구분한다 (I6-5, I6-6, I6-10, §6.4, §6.5).

### 3.3 ETF에 필요하지만 V1에 없는 것 (V1_DEPENDENCY_ANALYSIS §4)

- 거래대금 비율 수수료, 최소 수수료, 매도 세금 (대상 시장의 구조와 세율은 UNVERIFIED)
- 매수 대금, 사용 가능 현금, 결제일 T+n (UNVERIFIED)
- 분배금 현금흐름, 분할
- 곱셈 방식 가격 조정 (총수익 기준 등). 곱셈 조정은 상수 이동 불변성을 깨므로 full-history 신호 경로에서 실제 look-ahead가 된다 (GAP F-03)
- 가격대별 호가 단위 (일부 시장. 대상 시장 규칙은 UNVERIFIED)
- 공매도 제약 (UNVERIFIED)

V1에서 승수 1, 롤 0건으로 ETF를 흉내 낼 수는 있다 (V1_DEPENDENCY_ANALYSIS §4.1). 하지만 계약당 수수료, 현금 제약 없음, 분배금 없음, 가산 조정 때문에 그 결과는 ETF 결과가 아니다.

## 4. Decision Drivers

1. **잘못된 상태를 만들 수 없게**: 자산 유형과 맞지 않는 조합(ETF의 만기, 선물의 분배금)을 생성 단계에서 막는다.
2. **금융 단위의 일관성**: 수량 단위(계약 수, 주 수), 승수, 통화가 자산 유형별로 명확해야 한다 (ADR-0001 R2).
3. **V1 호환**: V1 `InstrumentSpec`과 V1 fingerprint를 바꾸지 않는다 (ADR-0001~0003 §8.0).
4. **비용 정책 확장**: 계약당 수수료와 비율 수수료·세금을 같은 틀에서 고를 수 있어야 한다.
5. **상품과 실제 거래 계약의 구분**: 선물은 신호의 대상(상품)과 체결의 대상(월물)이 다르다.
6. **확장성**: 다른 자산 유형을 추가할 때 기존 유형의 규칙을 건드리지 않아야 한다.
7. **미정 사항을 고정하지 않음**: 시장·브로커가 정해지지 않았다.

## 5. Considered Options

### 5.1 자산 유형별 필수 개념 (모든 대안에 공통)

| 개념 | 선물 (Futures) | ETF | 공통 여부 |
|---|---|---|---|
| 신호의 대상 | 상품(기초자산 root, 예: 지수 선물 상품) | 상장 종목 | 상품 식별자는 공통 |
| 체결·평가의 대상 (거래 단위) | **월물 계약** (contract identifier) | 상장 종목 자체 | 다름 |
| 수량 단위 | 계약 수 (정수) | 주 수 (정수, lot 단위의 배수) | 다름 |
| 승수 | 월물별 `M[c]` (거래통화/pt/계약) | 1 (거래통화/주, 가격이 곧 1주 가격) | 다름 |
| 거래통화 | 있음 | 있음 | 공통 |
| 호가 단위 | 고정 tick이 일반적 (대상 시장 UNVERIFIED) | 가격대별 표일 수 있음 (UNVERIFIED) | 규칙 구조는 공통 |
| 만기 | 있음 (만기일, 최종 거래일) | 없음 | 선물 전용 |
| 가격 연속성 이벤트 | 롤 이벤트 | 분배금, 분할 | 다름 |
| 신호용 조정 시계열 | 가산 back-adjustment (V1) | 곱셈 조정 또는 총수익 시계열 (방법 미정) | 결과 계약은 공통 (ADR-0004 §6.4) |
| 체결·평가 가격 | 월물별 raw | 종목 raw | 공통 원칙 (ADR-0001) |
| 거래 비용 | 계약당 수수료 (+ 스프레드·슬리피지) | 거래대금 비율 수수료, 최소 수수료, 매도 세금 (+ 스프레드·슬리피지) | 스프레드·슬리피지만 공통 |
| 자금 | 증거금 | 매수 대금 (현금), 결제일 | 다름 |
| 공매도 | 일반적으로 가능 | 시장·브로커 규칙 (UNVERIFIED) | 다름 |
| 손익의 추가 항 | 없음 (롤은 체결 다리로 표현) | 분배금 `D[c,t]` (ADR-0001 §6.2) | 다름 |

### 5.2 대안 A — 기존 `InstrumentSpec`에 선택 필드를 추가

- **내용**: `asset_type`, `exchange`, `expiry`, `lot_size`, 수수료 구조 등을 선택 필드(기본값 `None`)로 추가한다.
- **장점**: 타입이 하나라 공통 계산 코드가 단순하다. 기존 생성자 호출은 기본값 덕분에 그대로 동작한다.
- **단점**:
  - 자산 유형별 필수 필드가 모두 "선택"이 되어, 무엇이 필수인지가 검증 코드에만 남는다.
  - ETF에 만기를 넣거나 선물에 분배금 정책을 넣는 조합을 생성 단계에서 막지 못한다.
  - **현재 payload 동작에서는 필드를 추가하는 순간 모든 V1 입력 fingerprint가 바뀐다** (probe CONFIRMED). ADR-0001 §8.0과 충돌한다. ADR-0001 Q1-9에서 "호환 모드에서 새 필드를 payload에서 빼는 방식"을 고르면 이 단점은 줄어들지만, 아래 단점은 그대로 남는다.
  - 상품과 월물을 구분하는 구조가 없다.

### 5.3 대안 B — 공통 기본 사양과 Futures/ETF 전용 사양을 합성(Composition)

- **내용**: 공통 기본 사양(식별자, 통화, 수량 규칙, 호가 규칙)에 선물 전용 구성요소 또는 ETF 전용 구성요소를 붙인다.
- **장점**: 공통 계산이 공통 구성요소만 보면 된다. 전용 구성요소 안에서는 필수 필드가 명확하다. V1 타입과 분리된다.
- **단점**: 한 상품에 전용 구성요소가 둘 다 붙거나 하나도 없는 상태를 만들 수 있다. "정확히 하나"를 검증 코드로 막아야 한다.

### 5.4 대안 C — Tagged Union으로 자산 유형별 명세를 분리

- **내용**: 자산 유형 판별자(discriminator)를 가진 변형 타입(`FuturesInstrument | EtfInstrument`)을 둔다. 각 변형은 자기 필수 필드를 생성 단계에서 강제한다. 공통 계산은 공통 인터페이스나 판별자별 분기로 접근한다.
- **장점**: 잘못된 조합을 만들 수 없다. 판별자별 분기에서 처리하지 않은 유형은 기본 분기에서 거부되므로 누락이 드러난다. 새 유형은 새 변형으로 추가한다.
- **단점**: 공통 필드를 변형마다 반복하면 중복이 생긴다. 공통 계산이 판별자별 분기를 거쳐야 할 수 있다.

### 5.5 비교

| 기준 | A (선택 필드 확장) | B (합성) | C (Tagged Union) |
|---|---|---|---|
| 필수 필드의 명확성 | 낮음 (모두 선택 필드) | 중간 (구성요소 안에서는 명확) | **높음** (변형마다 생성 시 강제) |
| 잘못된 자산 유형 조합 방지 | 낮음 (검증 코드에 의존) | 중간 ("정확히 하나" 검증 필요) | **높음** (구조적으로 불가능) |
| 금융 단위의 일관성 | 낮음 (ETF 승수를 1이 아닌 값으로 넣을 수 있음) | 중간 | **높음** (변형마다 단위 고정, ETF 승수 = 1 고정) |
| 기존 V1 호환성 | **낮음** (현재 payload 동작에서는 V1 fingerprint 전부 변경. Q1-9의 선택에 따라 완화 가능) | 높음 (V1 타입 불변) | 높음 (V1 타입 불변) |
| 비용 정책 확장성 | 낮음 (선택 필드 조합 증가) | 중간~높음 | **높음** (변형별 비용표 타입) |
| 상품 식별자와 실제 거래 계약의 구분 | 낮음 (`symbol` 하나) | 중간 | **높음** (선물 변형은 상품과 월물 사양을 분리) |
| 다른 자산 유형 확장 | 선택 필드가 계속 늘어남 | 구성요소 추가 + 검증 갱신 | 변형 추가 + 분기 갱신 (누락은 거부로 드러남) |
| 공통 계산 재사용 | 쉬움 | 쉬움 (공통 구성요소) | 공통 구성요소를 합성하면 쉬움 |

## 6. Proposed Decision

### 6.1 결정 요지

**C를 채택하되, 변형 안의 공통 부분은 B의 공통 구성요소로 합성한다 ("공통 구성요소를 합성한 Tagged Union"). V1 `InstrumentSpec`은 바꾸지 않는다. V1 사양은 재현용 변환기로만 새 선물 변형에 연결한다.**

- 아래 타입 이름은 모두 **가칭**이다. 필드와 자료형은 P0-03에서 확정한다.
- 시장·브로커에 따라 달라지는 값은 타입에 상수로 넣지 않고, 출처와 기준 시점(`as_of`)이 있는 참조 데이터로 받는다.

### 6.2 구조

**공통 구성요소**

| 구성요소 (가칭) | 내용 |
|---|---|
| `InstrumentIdentity` | 내부 상품 ID, 거래소(venue), 거래통화 κ |
| `QuantityConvention` | 수량 단위 (`CONTRACT` / `SHARE`), lot size (정수 ≥ 1) |
| `PriceIncrementRule` | 고정 tick 또는 가격대별 표. 값은 참조 데이터 |

**자산 유형별 변형**

| 변형 (가칭) | 판별자 | 구성 |
|---|---|---|
| `FuturesInstrument` | `FUTURES` | identity, 수량 규칙(단위 = `CONTRACT`), 호가 규칙, 월물 체인 참조, 롤 정책 참조(롤 이벤트를 어떻게 만드는지, GAP F-07), 증거금 모델 참조(ADR-0003 Q3-11), 선물 비용표 참조 |

|---|---|---|
| 선물 | 상품 ID | **월물 ID** |
| ETF | 상품 ID | 상품 ID (상장 종목 자체가 거래 단위) |

**이벤트 타입 (가칭)**

| 이벤트 | 대상 | 내용 |
|---|---|---|
| `RollEvent` | 선물만 | 상품 ID, 효력일, 구월물 ID, 신월물 ID, 알려진 시각(known_at, ADR-0004 §6.5) |
| `CorporateAction` | ETF만 | 분배금(배당락일, 지급일, 주당 금액, 통화) 또는 분할(효력일, 비율) |

### 6.3 자산 유형 경계 규칙 (불변조건)

| ID | 규칙 | 위반 시 |
|---|---|---|
| I6-1 | `RollEvent`는 선물에만 쓴다. ETF에 롤 이벤트를 넣거나 가산 back-adjustment를 요청하면 거부한다 | ValueError (AT-0006-1) |
| I6-2 | `CorporateAction`은 ETF에만 쓴다. 선물에 분배금·분할을 넣으면 거부한다 | ValueError (AT-0006-1) |
| I6-3 | 선물의 가격·quote·포지션·체결·증거금은 **월물 ID로** 표현한다. 월물 ID가 없거나 그 상품의 체인에 없는 ID면 거부한다. 활성 월물을 추측해서 채우지 않는다 | ValueError (AT-0006-2) |
| I6-4 | ETF는 월물 체인이 없다. 거래 단위는 상품 자체다 | — |
| I6-5 | 수량은 자산 유형의 단위를 따른다 (계약 수 / 주 수). 정수여야 하고 lot size의 배수여야 한다. 단위가 다른 수량을 더하지 않는다 (예: 상품 간 "총 포지션" 합계) | ValueError |
| I6-6 | 승수: 선물은 월물 사양의 `M[c]`, ETF는 1. 다른 상품의 승수나 포트폴리오 공통 승수를 쓰지 않는다 (ADR-0001 R2) | ValueError |
| I6-7 | 체결·평가·명목가치·증거금·현금은 **raw 거래 가격**만 쓴다. 신호용 조정 가격은 연구 전용 타입이다 (ADR-0004 §6.4) | 가격 종류 불일치로 거부 |
| I6-8 | ETF 분할은 효력일에 **수량과 기준가격을 바꾸는 이벤트**다. 손익, 거래, 비용이 아니다 | AT-0006-4 |
| I6-9 | ETF 분배금은 ADR-0001 회계식의 `D[c,t]` 항으로만 반영한다. 선물 롤은 체결 다리(구월물 매도, 신월물 매수)로만 반영한다. 두 개념을 같은 항이나 같은 보고 분류에 섞지 않는다 | AT-0006-5 |
| I6-10 | 모든 상품은 거래통화 κ를 가진다. FX는 κ로 찾는다 (ADR-0001 R2). V1과 달리 통화가 계산에 실제로 쓰인다 | 환산율이 없으면 ValueError |
| I6-11 | 시장·브로커에 따라 달라지는 값(호가 단위 표, lot size, 수수료율, 세율, 결제일, 공매도 허용 여부, 증거금)은 출처와 `as_of`가 있는 참조 데이터로 받는다. LIVE 프로필에서 값이 없으면 그 상품의 위험 증가 주문을 막는다 (fail-closed, ADR-0002 §6.4, ADR-0003 §6.2.2와 같은 원칙) | 차단 |

### 6.4 비용 정책의 확장

| 비용 요소 | 선물 | ETF | 공통 |
|---|---|---|---|
| 스프레드·슬리피지 | mid 대비 부호 있는 체결 비용 (ADR-0001 §6.2) | 같음 | **공통** |
| 수수료 | 계약당 고정 수수료 (V1 방식) | 거래대금 비율, 최소 수수료 (구조와 값 UNVERIFIED) | 다름 |
| 세금 | (대상 시장 확인 필요) | 매도 시 거래세 등 (UNVERIFIED) | 다름 |
| 수수료 통화 | 미해결 (ADR-0001 Q1-4) | 미해결 | — |

- 비용표는 자산 유형별 타입으로 두고, 상품 변형이 자기 비용표를 참조한다.
- ETF 비율 수수료, 최소 수수료, 세금은 **새 금융 공식**이다. 구현하려면 입력·출력·단위·전제조건·예외조건 명세, 독립 수치 검증, 단위 테스트, 사용자 승인이 필요하다 (CLAUDE.md §3.2, §5).
- V1의 계약당 수수료 경로(10개 모듈)는 바꾸지 않는다.

### 6.5 자금 모델: 증거금과 현금

| 항목 | 선물 | ETF |
|---|---|---|
| 포지션을 열 때 필요한 자금 | 증거금 (모델은 ADR-0003 Q3-11) | 매수 대금 + 비용 (현금) |
| 손익의 현금 반영 | 일일 정산으로 매일 현금에 반영되는 것이 일반적 (대상 시장 UNVERIFIED) | 매도할 때 실현. 보유 중에는 평가손익 |
| 결제 | — | T+n (UNVERIFIED). 매도 대금을 언제 쓸 수 있는지는 ADR-0003 Q3-7 |
| 거래 전 위험 검사 (ADR-0003 L1) | margin usage, gross leverage | 사용 가능 현금 − 미체결 매수 예약분, gross leverage |

- **계좌 평가액(NAV)과 사용 가능 현금은 다른 값이다.** ADR-0001 회계식은 NAV의 변화(손익)를 계산한다. ETF를 사면 현금이 줄고 포지션 평가액이 같은 만큼 늘어 NAV는 비용만큼만 줄지만, 사용 가능 현금은 크게 준다 (AT-0006-3).
- V1은 손익만 누적하고 현금 원장이 없다 (V1_DEPENDENCY_ANALYSIS §4.1). 현금 원장과 결제일 모델은 후속 결정이 필요하다 (Q6-9, D-08, D-09).

### 6.6 신호 계산과의 연결

- 신호 함수(vol, forecast)의 입력은 자산 유형과 무관한 "연구용 조정 시계열" 계약으로 바꾼다 (ADR-0004 §6.4). 선물은 V1의 가산 back-adjustment로, ETF는 분배금·분할 조정으로 이 계약을 만든다.
- **ETF 신호는 PIT 경로로만 만든다.** 곱셈 조정에서는 full-history 경로가 실제 look-ahead가 된다 (GAP F-03, ADR-0005 E-2).
- V1의 vol은 가격 차이 기준(pt/d)이다. 곱셈 조정 시계열에서는 과거 구간의 가격 수준이 축소되어 있으므로, 가격 차이 vol이 현재 raw 가격 단위의 vol과 달라질 수 있다 (INFERRED). 백분율 vol 등으로 바꾸는 것은 금융 공식 변경이므로 P0-04 검증과 승인을 거친다 (Q6-6).
- 사이징 공식(평균 포지션 = 위험 예산 ÷ (vol × M × fx))은 ETF에서 M = 1로 그대로 쓸 수 있다. 단위 검증은 P0-04 V-05에 포함한다.

### 6.7 V1과의 관계

- V1 `InstrumentSpec`은 바꾸지 않는다 (fingerprint 보존, ADR-0004 P-1).
- V1 → `FuturesInstrument` 변환기(재현용, 명시적 `V1_COMPAT`에서만):
  - 상품 ID = `symbol`, 거래통화 = `currency`
  - 월물 ID = V1 `ContractPrice.contract`와 `RollEvent`에 나오는 이름
  - 모든 월물의 `M[c]` = V1 `multiplier`, 호가 규칙 = 고정 `tick_size`
  - 거래소와 만기일은 V1에 없으므로 "제공되지 않음"으로 표시한다. 만기일 필수 여부는 Q6-2이며, 권장안을 채택하면 이 표시는 `V1_COMPAT` 재현에서만 허용된다
- V1으로는 ETF를 표현하지 않는다. 승수 1, 롤 0건으로 흉내 낸 V1 결과는 ETF 연구 결과의 근거로 쓰지 않는다 (§3.3).

### 6.8 ACCEPTED ADR과의 정합성

| ACCEPTED 결정 | 이 ADR의 대응 | 충돌 여부 |
|---|---|---|
| ADR-0001 R2: 월물별 `M[c]`, 통화별 `fx[κ,t]`, 통화별 합산 후 환산 | `FuturesContract`의 `M[c]`, ETF 승수 1, 모든 상품의 거래통화 (I6-6, I6-10) | 없음 |
| ADR-0001 §6.2: 체결·평가는 raw, 신호는 adjusted. ETF는 raw + `D` | I6-7, I6-9 | 없음 |
| ADR-0001 Q1-5: 분배금 귀속일(배당락일/지급일) 미정 | `CorporateAction`에 두 날짜를 모두 두고 선택은 열어 둠 (Q6-7) | 없음 (열린 질문 유지) |
| ADR-0002: 거래 허용은 상품 단위, LIVE fail-closed | I6-11 (참조 데이터 누락 시 위험 증가 차단) | 없음 |
| ADR-0003: L1에서 증거금(선물)과 현금(ETF)을 같은 틀로 계산, Q3-7 결제일, Q3-11 증거금 모델 | §6.5 | 없음 (열린 질문 유지) |
| ADR-0001~0003 §8.0: V1 API·fingerprint 불변 | V1 `InstrumentSpec` 불변, 변환기는 재현용 (§6.7) | 없음 |

## 7. Consequences / Trade-offs

**장점**
- 자산 유형에 맞지 않는 데이터를 입력 단계에서 거부한다.
- 수량 단위, 승수, 통화가 타입에 고정되어 다상품·다통화 회계(ADR-0001 R2)가 안전해진다.
- 선물의 "상품 ↔ 월물" 구분이 명시되어 Paper/Live의 월물별 주문·증거금·Reconciliation에 바로 쓸 수 있다.
- V1과 V1 fingerprint는 영향을 받지 않는다.

**단점과 비용**
- 공통 계산이 판별자별 분기를 거칠 수 있다. 분기를 한곳에 모아야 누락이 생기지 않는다.
- ETF를 실제로 쓰려면 비용·현금·결제·기업 행사 모델이 모두 필요하다. 이 ADR만으로 ETF 백테스트가 가능해지지 않는다.
- 참조 데이터(호가 표, 수수료, 세율, 결제일)가 없으면 LIVE에서 거래가 막힌다. 의도한 동작이다.

## 8. Compatibility with V1

이 ADR은 ADR-0001 §8.0(세 ADR 공통)의 `V1_COMPAT` 적용 범위를 그대로 따른다.

| 항목 | 영향 |
|---|---|
| V1 `InstrumentSpec` | 변경 없음 (ADR-0004 P-1의 잠정 규칙. 현재 payload 동작에서는 필드를 추가하면 fingerprint가 바뀜) |
| 기존 306개 테스트 | 변경 없음 (새 타입은 추가만 함. 구현 후 회귀 확인 필요, INFERRED) |
| V1 선물 경로 (롤, 월물 장부, 계약당 수수료) | 변경 없음 |
| V1으로 ETF 흉내 내기 | 계속 가능하지만 ETF 결과로 인정하지 않음 |

## 9. Financial Integrity Implications

- **조정 방식과 look-ahead**: ETF 곱셈 조정은 full-history 경로에서 look-ahead를 만든다. ETF 신호는 PIT만 쓴다 (§6.6).
- **분할 오처리**: 분할을 손익으로 처리하면 2:1 분할 하루에 보유 100주 기준 −2,960의 가짜 손실이 생긴다 (AT-0006-4).
- **분배금과 롤의 혼동**: 분배금을 롤 손익처럼, 롤을 분배금처럼 처리하면 비용과 수익 분류가 틀어진다 (I6-9).
- **승수와 단위**: ETF 주식 수에 선물 승수를 쓰면 손익이 약 16,410배로 틀린다 (AT-0006-3 W2: 17,550,999,325 대 1,069,525).
- **현금 제약**: NAV만 보면 ETF 매수가 거의 비용 없이 보인다. 사용 가능 현금을 따로 검사하지 않으면 현금보다 많이 사는 주문이 통과한다 (ADR-0003 AT-0003-6).
- **lot 반올림**: lot size가 1보다 크면 목표 포지션을 lot 배수로 반올림하는 새 규칙이 필요하다. V1은 정수 반올림(`round_half_away_from_zero`, `position.py:8-18`)만 있다. 새 반올림 규칙은 금융 공식 추가이므로 명세와 독립 검증이 필요하다.
- **만기**: 만기가 지난 월물을 보유하는 상태를 막아야 한다. 실물 인수도 여부는 대상 시장에 따라 다르다 (UNVERIFIED). 새 엔진이 최종 거래일 이후의 월물 포지션을 거부하도록 하는 것을 권장한다. 이를 위해서는 만기일 정보가 필요하다 (만기일 필수 여부는 Q6-2).
- **특수 ETF**: 레버리지·인버스 ETF는 경로 의존 수익을 가지므로 vol 기반 사이징의 의미가 달라질 수 있다 (INFERRED, Q6-8).

## 10. Acceptance Criteria

인수 테스트는 **명세**다. 이번 작업에서 구현하지 않았다. 아래 상품은 모두 가상의 상품이며 특정 실제 상품의 사양이 아니다. 수수료·환율은 계산을 보여 주기 위한 숫자다.

### AT-0006-1 ETF에 선물 Roll 데이터를 넣으면 거부된다 (인수 테스트 명세 4)

- **입력**:
  - (a) `EtfInstrument`(가칭) 하나와, 그 상품 ID를 가리키는 `RollEvent` 한 건
  - (b) 같은 ETF에 대해 가산 back-adjustment(선물 방식) 조정 시계열을 요청
  - (c) 대칭 사례: `FuturesInstrument`에 분배금 `CorporateAction`을 넣음
- **기대 결과**: (a), (b), (c) 모두 데이터 경계에서, 신호 계산 전에 **ValueError**로 거부된다. 오류에는 자산 유형과 이벤트 종류가 맞지 않는다는 사유가 들어 있다.
- **전제조건**: 상품에 자산 유형 판별자가 있고, 이벤트가 타입으로 구분된다 (I6-1, I6-2).
- **예외조건**: 롤 이벤트 목록이 비어 있는 ETF, 기업 행사가 없는 선물은 정상 입력이다.
- **V1 호환성 영향도**: 없음. V1에는 자산 유형이 없고, V1 선물 경로는 지금처럼 롤 이벤트를 받는다.
- **새 테스트 후보**: `test_etf_rejects_roll_events`, `test_etf_rejects_additive_back_adjustment`, `test_futures_rejects_distribution_events`

### AT-0006-2 선물에 필요한 Contract Identifier가 없으면 거부된다 (인수 테스트 명세 5)

- **입력**:
  - (a) 월물 ID가 빈 문자열이거나 없는 `FuturesContract`
  - (b) 월물 ID 없이 상품 ID만 붙은 선물 가격·quote·체결
  - (c) 그 상품의 체인에 없는 월물 ID (다른 상품의 월물)
  - (d) 월물 ID가 아니라 상품 ID를 키로 쓴 선물 포지션
- **기대 결과**: 모두 생성 단계나 데이터 경계에서 **ValueError**. 활성 월물을 추측해서 채우지 않는다.
- **전제조건**: 월물 체인이 참조 데이터로 주어진다 (I6-3).
- **예외조건**: ETF는 월물 ID가 필요 없다. 상품 ID를 거래 단위로 쓴다 (I6-4).
- **V1 호환성 영향도**: 없음. V1도 월물 이름의 빈 문자열을 거부한다 (`futures_data.py:12-14`, `:27-31`). V1 변환기는 V1 월물 이름을 월물 ID로 쓴다.
- **새 테스트 후보**: `test_futures_contract_requires_identifier`, `test_futures_quote_requires_contract_in_chain`, `test_futures_position_keyed_by_contract`

### AT-0006-3 통화와 승수가 다른 두 상품을 같은 포트폴리오에서 처리한다 (인수 테스트 명세 6)

- **입력**: 기준통화 BC = KRW. `fx[USD,t]` = 1,350 KRW/USD, `fx[KRW,t]` = 1. 체결은 모두 평가 시각 이전.

| 항목 | 선물 F (KRW) | ETF E (USD) |
|---|---|---|
| 수량 단위 | 계약 | 주 |
| 승수 | `M[c]` = 250,000 KRW/pt/계약 | 1 USD/주 (고정) |
| 보유 `q[t−1]` | +2 계약 | +100 주 |
| 평가가격 `V[t−1]` → `V[t]` | 350.00 → 352.00 | 50.00 → 50.50 |
| 주기 t의 체결 | 없음 | +20 주 @ 50.40 |
| 수수료 (시연용) | — | 0.50 USD |

- **기대 결과** (독립 산술로 계산):

| 항목 | F (KRW) | E (USD) |
|---|---|---|
| 보유분 | 2 × (352.00 − 350.00) × 250,000 = 1,000,000 | 100 × (50.50 − 50.00) × 1 = 50 |
| 체결분 | — | 20 × (50.50 − 50.40) × 1 = 2 |
| 수수료 | — | −0.50 |
| 통화별 손익 | **1,000,000 KRW** | **51.50 USD** |
| 기준통화 환산 | × 1 = 1,000,000 | × 1,350 = 69,525 |

  - `PnL[t]` = **1,069,525 KRW**
  - 기말 수량: F +2 계약, E +120 주. **단위가 다르므로 두 수를 더하지 않는다** (I6-5).
  - 명목가치(BC): F = 2 × 352 × 250,000 = 176,000,000 KRW. E = 120 × 50.50 × 1 × 1,350 = 8,181,000 KRW.
  - ETF 매수의 현금 유출: 20 × 50.40 + 0.50 = **1,008.50 USD** (그날 환율로 1,361,475 KRW 상당). 계좌 평가액(NAV)은 손익만큼만 바뀌고, 사용 가능 현금은 매수 대금만큼 준다 (§6.5). 원화로 언제 환전되는지는 D-08이다.
- **잘못된 계산 (테스트에서 실패해야 함)**:

| ID | 오류 | 결과 (KRW) |
|---|---|---|
| W1 | 환산 전에 통화를 더함 (1,000,000 + 51.50) | 1,000,051.5 |
| W2 | ETF 주식 수에 선물 승수 250,000을 씀 | 17,550,999,325 |

- **전제조건**: ADR-0001 §6.2 multi-instrument 공식. 두 선물로 된 같은 종류의 예제는 ADR-0001 AT-0001-9에 있다.
- **예외조건**: `fx[USD,t]`가 없으면 ValueError (1로 대체하지 않음). ETF 수량이 lot size의 배수가 아니면 ValueError. 체결가가 호가 규칙에 맞지 않으면 ValueError.
- **V1 호환성 영향도**: 없음. V1은 ETF를 표현하지 않는다. 두 선물만 있는 V1 포트폴리오는 지금도 상품별 승수와 상품별 환산율을 쓴다 (통화 키는 없음, ADR-0001 R2).
- **새 테스트 후보**: `test_mixed_futures_and_etf_pnl_converts_by_currency`, `test_etf_uses_unit_multiplier`, `test_quantities_with_different_units_are_not_summed`, `test_etf_purchase_reduces_available_cash_not_nav`

### AT-0006-4 ETF 분할은 손익이 아니라 수량·기준가격 변환이다

- **입력**: ETF 100주 보유. 전일 raw 종가 60.00. 효력일 t에 2:1 분할. t의 raw 평가가격 30.40
- **기대 결과**:
  - 효력일에 수량 100 → 200주, 기준가격 60.00 → 30.00으로 바뀐다. 거래도 비용도 없다.
  - 손익 = 200 × (30.40 − 30.00) = **80** (분할 전 기준으로 환산해도 100 × (60.80 − 60.00) = 80)
  - 분할을 무시하면 100 × (30.40 − 60.00) = **−2,960**의 가짜 손실이 생긴다 (테스트에서 실패해야 함).
- **전제조건**: I6-8. 분할 이벤트에 효력일과 비율이 있다.
- **예외조건**: 비율이 0 이하이거나 비유한값이면 ValueError. 분할 결과가 정수 주가 아니면(단주 처리 정책 미정) 거부한다 (Q6-5).
- **V1 호환성 영향도**: 없음 (V1은 ETF를 표현하지 않음).
- **새 테스트 후보**: `test_etf_split_converts_quantity_and_reference_price`, `test_etf_split_is_not_pnl`

### AT-0006-5 ETF 분배금과 선물 롤은 서로 다른 회계 항이다

- **입력**: (a) ETF: ADR-0001 AT-0001-6의 숫자 (100주, 주당 분배금 0.5, raw 가격 50.0 → 49.5). (b) 선물: ADR-0001 AT-0001-3의 롤 (구월물 A 5 계약 매도, 신월물 B 5 계약 매수)
- **기대 결과**:
  - (a): 보유분 −50, 분배금 `D` 항 +50, 합계 **0**. 분배금은 체결이나 비용으로 기록되지 않는다.
  - (b): 롤은 두 개의 체결 다리로 기록되고, 손익은 ADR-0001 AT-0001-3과 같다 (일반 모드 55). 롤은 `D` 항이나 분배금 분류에 들어가지 않는다.
  - 보고서의 손익 분해에서 분배금과 롤 비용이 서로 다른 분류로 나온다.
- **전제조건**: I6-9.
- **예외조건**: 분배금 귀속일 기준(배당락일/지급일)은 ADR-0001 Q1-5이 정해질 때까지 테스트에서 명시적으로 주입한다.
- **V1 호환성 영향도**: 없음.
- **새 테스트 후보**: `test_distribution_is_reported_separately_from_roll_costs`
