**승인된 원칙**

1. 세션, 관측, 의사결정, 평가를 실제 시각(instant)으로 표현한다 (§6.1).
2. 시각 비교는 UTC 기반으로 하고, 현지 시각에는 IANA 타임존을 쓴다 (§6.2 C7-1, C7-2).
3. 계좌 단위의 일간 의사결정 일정과 평가 일정을 둔다 (§6.1, C7-4).
4. 장중 다회 이벤트를 처리하는 범용 이벤트 엔진은 이번 목표에 포함하지 않는다 (§6.1).
5. 상품별 데이터 상태 `FRESH`, `MARKET_CLOSED`, `PENDING_OFFICIAL`, `MISSING_DATA`를 구분한다 (§6.4).
6. 휴장과 데이터 결측은 거래소 달력과 실제 관측을 함께 보고 판정한다 (§6.4, X7-6).
7. 마지막 공식 가격을 쓴 평가는 정책에 따라 선택한 평가값이며, 실제 현재 시장가치와 같다고 단정하지 않는다 (§6.4, §6.5, R1).
8. 이전 가격 사용, 잠정 평가, 공표 전 가격 사용은 명시적 평가 정책으로 통제한다 (§6.5).
9. 공식 가격의 관측 시각, 공표 예상 시각, 실제 이용 가능 시각을 구분한다 (§5.1, §6.4, R1).
10. 주문 의도 생성, 주문 제출, 실제 체결 가능 시각을 구분한다 (§6.3, R1).
11. 미래 데이터 사용, 표시 없는 forward fill, 보간, 가격 0 대입, 고정 시차 변환을 금지한다 (§6.3, §6.7 X7-1~X7-5).
12. 기존 V1의 날짜 처리와 fingerprint를 보존한다 (§6.1, §8).

### 3.2 문제

- 한국 ETF, 미국 ETF, 해외 선물은 서로 다른 거래소, 타임존, 휴장일, 세션을 가진다 (각 시장의 실제 규칙은 UNVERIFIED).
- **같은 날짜 문자열이 같은 정보 이용 시점을 뜻하지 않는다.** 예를 들어 IANA tz 규칙으로 계산하면 America/New_York의 16:00은 2026-03-05(EST)에는 Asia/Seoul 다음 날 06:00이고, 2026-03-10(EDT)에는 다음 날 05:00이다 (2026-10-16 계산, tzdata 2026.5). 날짜만으로는 "미국 d일 종가가 한국 d+1일 아침에 이용 가능한가"를 판단할 수 없다.
- 한 시장이 휴장인 날에도 그 시장 상품의 보유 포지션은 존재하고 평가되어야 한다.
- 거래일에 데이터가 빠진 것(결측)과 시장이 열리지 않아 데이터가 없는 것(휴장)은 금융적으로 다르다. 앞의 것은 실제 가격 움직임을 숨길 수 있고, 뒤의 것은 움직임이 없었다.

## 4. Decision Drivers

1. **look-ahead 금지**: 의사결정 입력은 `decision_at`까지 이용 가능해야 한다 (ADR-0001 I-1). 날짜가 아니라 시각으로 판단한다.
2. **보유 포지션은 매 평가 주기 평가**: 시장이 닫혔다고 포지션이나 가격이 사라지지 않는다.
3. **휴장과 결측의 구분**: 둘을 같은 방식으로 처리하지 않는다.
4. **명시적 평가 정책**: 이전 가격을 쓸 때는 정책과 신선도 표시가 있어야 한다. 무조건 forward fill을 기본값으로 두지 않는다.
5. **실전 구현 가능성**: 하루 1회 점검 운영(CLAUDE.md §1)에 맞는 복잡도여야 한다.
6. **V1 호환**: V1 경로의 날짜 동작을 바꾸지 않는다 (ADR-0005).
7. **미확인 시장 사실을 고정하지 않음**: 거래 시간, 휴장일, 공표 지연은 데이터로 받는다.

## 5. Considered Options

### 5.1 용어 정의 (모든 대안에 공통)

| 용어 | 정의 | 소유 |
|---|---|---|
| **Exchange Calendar** (거래소 달력) | 거래소마다 세션 목록과 휴장일을 정의하는 참조 데이터. 거래소의 IANA 타임존을 가진다 | 참조 데이터 (ADR-0004) |
| **Trading Session** (거래 세션) | 한 번의 연속 거래 구간. 시작·종료 시각은 UTC 시각(instant)으로 저장하고, 거래소 현지 시각과 타임존을 함께 기록한다 | 거래소 달력 |
| **Trading Day** (거래일) | 거래소가 세션에 붙이는 거래 날짜 라벨. 야간 세션은 거래소 규칙에 따라 다음 거래일에 귀속될 수 있다 (규칙은 거래소별, UNVERIFIED). **UTC 날짜나 현지 달력 날짜와 같다고 가정하지 않는다** | 거래소 달력 |
| **Market Open / Closed** | 어느 시각(instant)에 그 상품의 세션이 진행 중인지 여부 | 달력에서 계산 |
| **Non-trading Day** (비거래일) | 달력상 세션이 없는 날 (주말, 휴장일). 데이터가 없는 것이 정상이다 | 거래소 달력 |
| **Decision Time** (`decision_at`) | 계좌의 의사결정 시각. 계좌 단위 일정이다 (ADR-0001) | 계좌 의사결정 일정 |
| **Data Available Time** (`data_available_at`) | 관측값을 실제로 쓸 수 있게 된 시각 (ADR-0001, ADR-0004) | 관측값 |
| 공식 가격의 세 가지 시각 (R1) | (1) **관측 시각** `observed_at`: 공식 가격이 나타내는 시장 시각 (예: 종가 결정 시각). (2) **실제 이용 가능 시각** `data_available_at`: 그 값이 실제로 시스템에 들어온 시각 (관측 기록). (3) **공표 예상 시각** (expected availability): 달력과 데이터 계약이 "이때까지 들어와야 한다"고 정한 시각 (참조 데이터, 가정값). 셋은 서로 다를 수 있으며 섞지 않는다 | 관측값 / 데이터 계약 |
| 주문 제출 시각과 체결 가능 시각 (R1) | `order_submitted_at`은 주문을 브로커에 보낸 시각이다 (ADR-0001). 체결은 세션이나 단일가 매매처럼 **체결이 가능한 구간**에서만 일어난다. 세션 밖(개장 전 등)에 주문을 접수받는지는 **시장, 브로커, 주문 유형에 따라 다르다** (UNVERIFIED). 접수되더라도 체결 가능 시각은 그 다음 체결 구간이다 | 달력 + 브로커 규칙 |
| **Valuation Schedule** (평가 일정) | 계좌의 평가 시각 목록 `valuation_at(t)`. 평가 주기는 (`valuation_at(t−1)`, `valuation_at(t)`] (ADR-0001 I-3) | 계좌 평가 일정 |
| **Missing Data** (결측) | 달력상 세션이 있었고 공식 가격이 있어야 하는데 없는 상태 | Data Boundary 판정 |
| **Stale Price** (오래된 가격) | 쓸 수 있는 가장 최근 관측이 허용 기간보다 오래된 상태. 사유(휴장 / 결측 / 공표 대기)를 함께 표시한다 | Data Boundary 판정 |
| 공식 평가가격 (official mark) | 평가 정책이 평가가격으로 인정하는 관측 (종가, 정산가 등. 종류는 ADR-0001 Q1-2) | 관측값 + 평가 정책 |

**마지막 관측 가격 사용과 보간은 다르다.**
- 마지막 관측 가격 사용: 평가 시각까지 이용 가능했던 가장 최근 공식 가격을 그대로 쓴다. 미래 정보를 쓰지 않는다. 다만 이 값은 **정책적으로 고른 평가가격**일 뿐이다. 시장이 닫혀 있는 동안에도 다른 시장, 관련 상품, 환율, 뉴스로 인해 그 상품의 실제 가치는 바뀔 수 있다. 가격 움직임을 숨길 수 있으므로 정책과 신선도 표시가 필요하다.
- 보간: 앞뒤 관측으로 값을 만든다. 뒤의 관측은 평가 시각에 알 수 없으므로 **look-ahead다. 금지한다.**

### 5.2 대안 A — 모든 상품의 공통 거래일(교집합)만 사용

- **내용**: 모든 거래소가 열린 날짜만 남긴다.
- **장점**: V1의 "날짜가 같아야 함"과 가장 가깝다. 구현이 쉽다.
- **단점**: 한 시장이 휴장인 날에는 다른 시장 상품도 거래하지 못한다. 시장이 많을수록 거래일이 줄어든다. 날짜 문자열 기반이라 시각 기준 look-ahead 문제(§3.2)가 그대로 남는다. 보유 포지션의 손익은 사라지지는 않지만 다음 공통일로 미뤄진다.

### 5.3 대안 B — 모든 상품 거래일의 합집합을 쓰고 상품별 거래 가능성과 평가 가능성을 구분

- **내용**: 어느 시장이든 열린 날을 모두 남기고, 날짜·상품마다 "거래 가능", "새 공식 가격 있음"을 표시한다.
- **장점**: 각 시장의 거래 기회를 살린다. 휴장 상품을 명시적으로 다룬다.
- **단점**: 여전히 날짜 단위다. 서로 다른 타임존의 "같은 날짜"가 어느 시각인지 정의하지 않으면 정보 이용 시점을 판단할 수 없다.

### 5.4 대안 C — 타임스탬프 기반 글로벌 이벤트 달력

- **내용**: 세션, 관측, 의사결정, 평가를 모두 UTC 시각(instant)으로 다룬다. 상품별 세션과 평가 이벤트를 관리한다.
- **장점**: DST, 야간 세션, 공표 지연을 정확히 표현한다. 정보 이용 시점을 시각으로 판단한다.
- **단점**: 일반적인 이벤트 엔진(장중 다회 이벤트 처리)까지 만들면 하루 1회 시스템에 비해 과하다. ADR-0001도 일간 회계에는 이벤트 엔진(대안 C)을 쓰지 않기로 했다.

### 5.5 비교

| 기준 | A (교집합) | B (합집합 + 상품별 상태) | C (타임스탬프 이벤트 달력) |
|---|---|---|---|
| look-ahead 방지 | 약함 (날짜 기반) | 약함 (날짜 기반) | **강함** (시각 기반, DST·공표 지연 반영) |
| 휴장 상품의 평가 | 공통일까지 미룸 | 상품별 상태로 처리 | 상품별 상태로 처리 |
| 휴장과 결측의 구분 | 불가 (날짜를 지움) | 가능 | 가능 |
| 거래 기회 | 줄어듦 | 유지 | 유지 |
| 실전 구현 가능성 | 높음 | 높음 | 일반 이벤트 엔진이면 낮음, 일간 일정으로 제한하면 중간 |
| 복잡도 | 낮음 | 중간 | 높음 (일반형) / 중간 (최소형) |
| V1 호환 | V1과 비슷하지만 V1 동작을 바꾸지 않음 | 새 경로 전용 | 새 경로 전용 |

## 6. Proposed Decision

### 6.1 결정 요지

**C를 최소 형태로 채택한다.** 세션, 관측, 의사결정, 평가를 시각(instant)으로 표현하고, 계좌는 **일간 의사결정 일정과 평가 일정**을 가진다. 각 의사결정·평가 시각에서 상품별 상태(시장 열림, 거래 가능, 최신 공식 가격과 그 신선도)를 계산한다. 이 상태 표현은 B의 상품별 구분을 시각 기준으로 만든 것이다. 장중 다회 이벤트를 처리하는 일반 이벤트 엔진은 만들지 않는다.

- V1 경로는 바꾸지 않는다. V1은 계속 날짜가 정확히 같아야 한다 (ADR-0005).
- 거래 시간, 휴장일, 공표 지연, 의사결정·평가 시각의 값은 정하지 않는다.

### 6.2 시각과 타임존 규칙

| ID | 규칙 |
|---|---|
| C7-1 | 모든 시각은 UTC 시각(instant)으로 저장한다. 거래소 현지 시각이 필요하면 거래소의 IANA 타임존과 함께 기록한다 |
| C7-2 | 현지 시각 ↔ UTC 변환은 타임존 데이터베이스로 한다. 고정 시차(예: "한국 = 미국 + 14시간")를 코드에 넣지 않는다 (DST 때문에 틀린다, AT-0007-3) |
| C7-3 | 거래일 라벨은 거래소 달력이 정한다. 시각의 UTC 날짜나 계좌 현지 날짜로 거래일을 추론하지 않는다 |
| C7-4 | 의사결정과 평가 일정은 **계좌 단위**다. 상품마다 따로 의사결정 일정을 두지 않는다 (하루 1회 점검 운영) |

### 6.3 의사결정 시각의 입력 판정

- `decision_at`의 입력은 `data_available_at ≤ decision_at`인 관측만 쓴다 (ADR-0001 I-1). 이 비교는 시각으로 한다.
- 각 상품에 대해 "`decision_at`까지 이용 가능해야 했던 최신 세션"을 달력과 공표 지연(데이터 계약, ADR-0004 §6.5)으로 계산하고, 실제 관측과 비교한다 (§6.4).
- **주문 의도 생성, 주문 제출, 체결 가능 시각을 구분한다** (R1).
  - 주문 의도는 `decision_at`에 만들 수 있다. 시장이 닫혀 있어도 만들 수는 있다.
  - 주문 제출(`order_submitted_at`)은 주문을 브로커에 제출한 시각이다 (ADR-0001 §5.1.1). 브로커가 그 시각에 주문을 받지 않는다면 제출하지 않고 `INTENT`로 둔다. 제출했는데 브로커가 거부하면 `REJECTED`다 (ADR-0009). 세션 밖 접수 가능 여부는 시장·브로커·주문 유형에 따라 다르다 (UNVERIFIED, Q7-9). ADR-0001 I-2(`decision_at ≤ order_submitted_at ≤ fill_at`)는 제출이 세션 안이어야 한다고 정하지 않는다.
  - 체결(`fill_at`)은 체결이 가능한 구간(세션, 단일가 매매)에서만 일어난다. 제출 시각을 체결 가능 시각으로 보지 않는다.
  - 의사결정 시각에 시장이 닫혀 있으면, 주문 의도를 다음 체결 구간까지 유지할지, 다음 의사결정에서 다시 계산할지, 제출 시점에 위험 검사를 다시 할지는 Q7-6이다 (AT-0007-7).
- **주문 가능 시각과 평가 가능 시각은 다르다.** 시장이 닫혀 있어도 평가는 하고, 평가 가격이 공표되지 않았어도 다른 상품의 주문은 할 수 있다.

### 6.4 상품별 데이터 상태 판정

평가 시각(또는 의사결정 시각) τ에서 상품 c의 상태는 다음 중 하나다.

| 상태 | 조건 | 의미 |
|---|---|---|
| `FRESH` | 달력상 τ까지 이용 가능해야 했던 최신 세션(공표 예상 시각 ≤ τ)의 공식 가격이 있고, 그 실제 `data_available_at ≤ τ` | 정상 |
| `MARKET_CLOSED` | 마지막 공식 가격 이후 달력상 세션이 없었음 (휴장, 주말) | 그 거래소에서 새 공식 가격이 만들어지지 않았음. 마지막 공식 가격은 평가 정책이 고른 평가가격이며, **실제 현재 시장가치라는 뜻은 아니다** (R1). 신선도(경과 시간)를 표시한다 |
| `PENDING_OFFICIAL` | 세션은 끝났지만 공식 가격의 **공표 예상 시각**이 τ보다 늦음 (장중 가격만 있을 수 있음) | 공식 가격을 아직 쓸 수 없음 |
| `MISSING_DATA` | 세션이 있었고 **공표 예상 시각**이 τ 이전인데, 실제로 이용 가능한 공식 가격이 없음 | 결측. 실제 가격 움직임을 모름 |

- 상태는 **달력과 관측을 함께 보고** 정한다. 관측이 없다는 사실만으로 휴장으로 판단하지 않는다.
- 상태와 함께 "사용한 공식 가격의 관측 시각, 경과 시간, 사유"를 기록한다.
- ADR-0002의 사유 코드와 연결: `MISSING_DATA`와 일정 이상 오래된 `MARKET_CLOSED`는 신선도 판정(ADR-0002 `STALE_DATA`, ADR-0003 S-7)의 입력이 된다. 휴장으로 인한 경과는 결측과 다른 사유로 표시한다. 허용 경과 시간의 값은 정하지 않는다.

### 6.5 평가 정책 (Valuation Policy)

평가 시각 `valuation_at(t)`에 보유한 모든 상품은 평가가격이 있어야 한다 (ADR-0001 §6.2). 상태별 처리는 **명시적으로 선택한 평가 정책**을 따른다. 기본값을 정하지 않는다 (Q7-3).

| 상태 | 권장 처리 (제안. 구체 처리 방식은 ACCEPTED 승인 범위 밖, Q7-3·Q7-4) | 금지 |
|---|---|---|
| `FRESH` | 그 공식 가격을 쓴다 | — |
| `MARKET_CLOSED` | 마지막 공식 가격을 평가가격으로 쓴다. 이것은 보간이 아니지만 **정책적으로 고른 평가가격**이며 실제 현재 시장가치와 다를 수 있다 (R1). 신선도와 사유 `MARKET_CLOSED`를 기록한다. 이번 주기 보유분 가격 손익은 "선택한 마지막 공식 평가가격을 그대로 유지한 경우의 **평가상** 가격 손익"으로서 0이다. 실제 가치 변화가 0이라는 뜻은 아니다 (환율 영향은 ADR-0008) | 가격을 0으로 두기, 포지션을 평가에서 빼기 |
| `PENDING_OFFICIAL` | 그 상품의 이번 주기 평가를 **잠정**(provisional)으로 표시하거나, 공식 가격이 공표된 뒤로 평가를 미룬다. 장중 가격을 공식 평가가격으로 쓸지는 정책이 명시적으로 허용할 때만 한다 (Q7-4) | 장중 가격을 표시 없이 공식 가격처럼 쓰기 |
| `MISSING_DATA` | 조용히 채우지 않는다. 처리 방식(실행 중단, 표시된 마지막 가격 사용 + 위험 증가 차단 등)은 프로필별로 사용자가 정한다 (Q7-3). LIVE에서는 그 상품의 위험 증가 주문을 막는다 (ACCEPTED ADR-0002 §6.4, ADR-0003 S-7의 원칙) | 보간, 0 대입, 표시 없는 forward fill, 포지션 삭제 |

- 마지막 가격을 쓴 평가는 결과와 manifest에 표시해야 한다. 결과를 읽는 사람이 어느 평가가 오래된 가격인지 알 수 있어야 한다.
- 새로 공식 가격이 들어오면 그 주기의 손익에 반영된다. 휴장이 끝난 뒤의 첫 공식 가격은 휴장 기간 전체의 움직임을 한 번에 반영한다. 손익이 사라지지 않고 뒤로 미뤄진다.

### 6.6 ADR-0001 평가 주기와의 관계

- 평가 주기 (`valuation_at(t−1)`, `valuation_at(t)`]는 계좌 단위이며 ADR-0001 I-3을 그대로 쓴다.
- 체결의 주기 귀속은 거래일 라벨이 아니라 `fill_at`과 `valuation_at`의 비교로 한다 (ADR-0001 §5.1.3). 야간 세션 체결이 거래소 기준 다음 거래일에 속하더라도, 회계 귀속은 시각 비교를 따른다.
- 평가 경계 규칙이 대상 시장과 맞는지 확인하는 일(ADR-0001 Q1-8)은 여전히 열려 있다.

### 6.7 금지 사항

| ID | 금지 |
|---|---|
| X7-1 | 시장이 닫혔다는 이유로 가격을 0으로 두거나 포지션을 없애는 것 |
| X7-2 | 앞뒤 관측을 써서 값을 보간하는 것 (look-ahead) |
| X7-3 | 표시 없이 이전 가격을 복사하는 것 (무조건 forward fill) |
| X7-4 | 같은 날짜 문자열이면 같은 시각에 이용 가능하다고 가정하는 것 |
| X7-5 | 고정 시차로 타임존을 변환하는 것 |
| X7-6 | 결측을 휴장으로, 휴장을 결측으로 처리하는 것 |

| ACCEPTED 결정 | 이 ADR의 대응 | 충돌 여부 |
|---|---|---|

| ADR-0001 Q1-2 (평가가격 종류), Q1-3 (공표 지연), Q1-8 (평가 경계의 시장 확인) | 열린 채로 둔다. 이 ADR은 그 값이 들어올 틀만 정한다 | 없음 |

## 7. Consequences / Trade-offs

**장점**
- 날짜 문자열 때문에 생기는 look-ahead를 시각 비교로 막는다 (DST 포함).
- 휴장 상품을 포트폴리오에서 빼지 않고 평가한다. 휴장과 결측이 구분된다.
- 다시장 포트폴리오를 실행할 수 있게 된다 (V1은 실행 불가).

**단점과 비용**
- 거래소 달력, 세션 시각, 공표 지연이라는 참조 데이터가 필요하다. 출처와 정확성은 아직 없다 (UNVERIFIED).
- 평가가 잠정이거나 오래된 가격으로 된 주기가 생긴다. 결과 보고에 표시가 필요하다.
- 휴장 뒤 첫 날에 손익이 몰린다. 일간 수익률 통계(변동성, Sharpe)가 이 영향을 받는다 (INFERRED).

## 8. Compatibility with V1

이 ADR은 ADR-0001 §8.0(세 ADR 공통)의 `V1_COMPAT` 적용 범위를 그대로 따른다.

| 항목 | 영향 |
|---|---|
| V1 경로 | 변경 없음. 날짜가 정확히 같아야 하고, 결측은 fail-fast다 |
| 기존 306개 테스트, fingerprint | 변경 없음 (이 ADR은 새 경로에만 적용) |
| V1 재현 (`V1_COMPAT`) | V1 입력의 날짜를 "모든 상품이 같은 날짜에 하나의 세션을 가진 달력"으로 해석해 재현한다. 시각 정보가 없으므로 시각 판정은 하지 않고, 이 사실을 결과에 표시한다 |
| V1 입력으로 다시장 연구 | 불가. 시각 정보가 없으므로 새 데이터 계약(P0-03)이 필요하다 |

## 9. Financial Integrity Implications

- **look-ahead**: 날짜 기반 정렬은 DST 기간에 따라 다른 시장의 종가를 너무 일찍 쓸 수 있다 (AT-0007-3). 시각 비교로 막는다.
- **가짜 손익**: 휴장 상품의 가격을 0으로 두거나 포지션을 빼면 큰 가짜 손실과 다음 날 가짜 이익이 생긴다 (AT-0007-5).
- **숨은 손익**: 결측을 표시 없이 이전 가격으로 채우면 실제 가격 움직임이 숨는다. 그 사이 위험 검사도 틀린 가격으로 한다.
- **통계 왜곡**: 휴장 뒤 첫날의 손익 집중, 잠정 평가는 수익률 통계에 영향을 준다. 보고서에 표시한다.
- **survivorship과 데이터 수정**: 상장폐지나 공급자 수정은 결측과 다른 사유다. 데이터 계층(GAP F-10)에서 다룬다.

## 10. Acceptance Criteria

인수 테스트는 **명세**다. 이번 작업에서 구현하지 않았다. 시장은 모두 **가상 시장**이며 실제 거래 시간과 휴장일이 아니다 (UNVERIFIED).

- 가상 시장 `XKR`: 타임존 Asia/Seoul. 가상 세션 09:00~15:30, 공식 종가 공표 15:30 + 30분 (가상)
- 가상 시장 `XUS`: 타임존 America/New_York. 가상 세션 09:30~16:00, 공식 종가 공표 16:00 + 30분 (가상)
- 계좌: 기준통화 KRW. 의사결정 시각과 평가 시각은 각 테스트에서 정한다

### AT-0007-1 한국 시장 거래일, 미국 시장 휴장일

- **입력**: D일에 `XKR`은 세션이 있고 `XUS`는 가상 휴장. 보유: KR ETF `K1` 100주(KRW), US ETF `U1` 10주(USD). `K1` 공식 종가 D−1 10,000 → D 10,100 KRW. `U1`의 마지막 공식 종가는 D 이전 세션의 50.00 USD. `valuation_at(D)`는 `XKR` 공표 이후의 시각. 주문 가능 여부는 평가 시각이 아니라 **계획된 주문 제출 시각과 체결 예정 시각**으로 판단한다 (R1)
- **기대 출력**:

| 상품 | 상태 | 평가가격 | 이번 주기 보유분 평가상 가격 손익 (상품 통화) | 주문 (제출·체결 예정 시각 기준) |
|---|---|---|---|---|
| `K1` | `FRESH` | 10,100 KRW | 100 × (10,100 − 10,000) = **+10,000 KRW** | `XKR` 세션 중에 제출·체결할 계획이면 가능. 평가 시각(공표 이후)에는 이미 세션이 끝났으므로, 그 시각에 만든 주문은 다음 체결 구간 대상 (AT-0007-7) |
| `U1` | `MARKET_CLOSED` (경과 시간 기록) | 50.00 USD (정책이 고른 마지막 공식 평가가격) | 10 × (50.00 − 50.00) = **0 USD** (선택한 평가가격을 유지한 경우의 평가상 손익. 실제 가치 변화가 0이라는 뜻은 아님) | D일에는 `XUS` 체결 구간이 없으므로 체결 불가. 개장 전 접수 가능 여부는 시장·브로커·주문 유형에 따름 (Q7-9). 다음 세션 처리는 Q7-6 |

  - `U1`의 포지션은 NAV에 남는다. 환율이 바뀌었다면 그 영향은 ADR-0008의 환산 손익이다.
- **전제조건**: §6.4, §6.5 (`MARKET_CLOSED` 처리 정책이 선택되어 있음)
- **예외조건**: 평가 정책이 선택되지 않았으면 ValueError (기본값 없음). `U1` 가격을 0으로 두거나 포지션을 빼면 실패
- **V1 호환성 영향**: 없음. V1은 이 입력을 날짜 불일치로 거부한다 (`portfolio_backtest.py:216-242`). 그 동작은 그대로다
- **새 테스트 후보**: `test_closed_market_position_is_valued_at_last_official_mark`, `test_closed_market_instrument_has_no_execution_window`

### AT-0007-2 한국 시장 휴장일, 미국 시장 거래일

- **입력**: AT-0007-1의 반대. D일(미국 날짜)에 `XUS` 세션이 있고, 대응하는 한국 날짜에 `XKR`은 가상 휴장. `U1` 공식 종가 50.00 → 51.00 USD. `K1` 마지막 공식 종가 10,100 KRW
- **기대 출력**: `U1` `FRESH`, 보유분 손익 10 × (51.00 − 50.00) = **+10 USD**. `K1` `MARKET_CLOSED`, 선택한 평가가격을 유지한 경우의 평가상 손익 0 KRW. `K1`은 그날 체결 구간이 없으므로 체결 불가 (접수 가능 여부는 Q7-9)
- **전제조건**: 평가 시각이 `XUS` 공표 이후 (가상: 16:30 America/New_York 이후)
- **예외조건**: 평가 시각이 `XUS` 공표 전이면 `U1`은 `PENDING_OFFICIAL` (AT-0007-4)
- **V1 호환성 영향**: 없음
- **새 테스트 후보**: `test_union_schedule_values_both_markets_with_status`

### AT-0007-3 DST 전후의 같은 현지 시각

- **입력**: 계좌 의사결정 시각은 매 영업일 05:45 Asia/Seoul로 같다. `XUS` 가상 종가 16:00 America/New_York, 공표는 30분 뒤 (가상)
- **기대 출력** (IANA tz 규칙으로 계산, tzdata 2026.5):

| `XUS` 세션 | 종가 시각 (UTC) | 종가 시각 (Asia/Seoul) | 공표 시각 (Asia/Seoul) | 의사결정 시각 | 이 종가를 쓸 수 있는가 |
|---|---|---|---|---|---|
| 2026-03-05 (목, EST) | 21:00 | 03-06 (금) 06:00 | 06:30 | 03-06 (금) 05:45 | **아니오** → 직전 세션(03-04) 종가를 쓴다 |
| 2026-03-10 (화, EDT) | 20:00 | 03-11 (수) 05:00 | 05:30 | 03-11 (수) 05:45 | **예** |

  - 고정 시차("미국 종가 = 한국 다음 날 06:00")를 가정한 구현은 3월 11일에 쓸 수 있는 종가를 버리고, 반대로 "05:00"을 가정한 구현은 3월 6일에 아직 공표되지 않은 종가를 쓴다 (look-ahead).
- **전제조건**: C7-1, C7-2
- **예외조건**: 타임존 데이터가 없으면 ValueError. 존재하지 않거나 두 번 존재하는 현지 시각(DST 전환 시각)을 입력하면 거부하거나 규칙을 명시해야 한다 (Q7-8)
- **V1 호환성 영향**: 없음 (V1에는 시각이 없음)
- **새 테스트 후보**: `test_availability_uses_instants_across_dst`, `test_no_fixed_offset_timezone_conversion`

### AT-0007-4 장중 가격은 있으나 공식 평가가격은 아직 공표되지 않은 경우

- **입력**: 가상 선물 `F1` (가상 시장, 공식 정산가 공표는 세션 종료 2시간 뒤). `valuation_at(t)`는 세션 종료 1시간 뒤. 그 시각에 장중 마지막 체결가 102.0은 있고 공식 정산가는 없다. 직전 공식 정산가 100.0
- **기대 출력**:
  - `F1` 상태 `PENDING_OFFICIAL`
  - 평가 정책에 따라 (a) 이번 주기 평가를 잠정으로 표시하거나 (b) 공식 가격 공표 뒤로 평가를 미룬다. 장중 가격 102.0은 정책이 명시적으로 허용할 때만 쓰고, 썼다면 "장중 가격 사용"을 표시한다
  - 같은 시각의 의사결정 입력(신호)은 직전 공식 가격 100.0까지만 쓴다
  - 체결의 주기 귀속은 ADR-0001 §5.1.3 그대로다
- **전제조건**: §6.4, §6.5, 공표 지연은 데이터 계약으로 주어짐
- **예외조건**: 정책이 정해지지 않았으면 평가를 확정하지 않고 오류를 낸다
- **V1 호환성 영향**: 없음
- **새 테스트 후보**: `test_unpublished_official_price_marks_valuation_pending`, `test_intraday_price_not_used_as_official_without_policy`

### AT-0007-5 한 상품에만 결측 데이터가 발생한 경우

- **입력**: D일 `XKR` 세션 있음. `K1`은 공식 종가 10,100 KRW가 있고, `K2`(50주, 마지막 공식 종가 20,000 KRW)는 D일 종가가 없다
- **기대 출력**:
  - `K1` `FRESH`. `K2` **`MISSING_DATA`** (휴장이 아님. 같은 거래소의 다른 상품은 세션이 있었음)
  - `K2`의 포지션은 그대로 남는다. 가격을 0으로 두지 않는다
  - 처리 (Q7-3에 따라 사용자가 정한 정책):
    - V1 경로: ValueError (현재 fail-fast 동작, 변경 없음)
    - 새 엔진 `LIVE`: `K2`의 위험 증가 주문 차단 (ADR-0002, ADR-0003 S-7). 평가에 마지막 가격을 썼다면 사유 `MISSING_DATA`로 표시
  - 잘못된 처리와 결과:

| 잘못된 처리 | 결과 |
|---|---|
| `K2` 가격을 0으로 둠 | 50 × (0 − 20,000) = −1,000,000 KRW 가짜 손실, 다음 날 같은 크기의 가짜 이익 |
| D+1 종가로 D를 보간 | look-ahead (D 평가 시각에 D+1 가격은 알 수 없음) |
| 표시 없이 20,000 KRW 복사 | 실제 움직임이 숨고, 숨은 상태로 위험 검사 |

- **전제조건**: §6.4 상태 판정은 달력과 관측을 함께 본다
- **예외조건**: 달력 정보가 없어 휴장인지 결측인지 판단할 수 없으면, LIVE에서는 결측으로 보고 위험 증가를 막는다 (fail-closed)
- **V1 호환성 영향**: 없음
- **새 테스트 후보**: `test_missing_data_is_not_treated_as_holiday`, `test_missing_price_is_never_zero_or_interpolated`

### AT-0007-6 야간 세션의 거래일 귀속과 회계 귀속 (명세만)

- **입력**: 가상 거래소 규칙: 현지 20:00에 시작하는 야간 세션은 다음 거래일에 귀속. 야간 세션 중 체결 1건
- **기대 출력**: 체결의 거래일 라벨은 거래소 규칙(다음 거래일)을 따르지만, 회계 주기 귀속은 `fill_at`과 `valuation_at` 비교로 정한다 (§6.6)
- **예외조건**: 거래소 규칙이 없으면 야간 세션 상품은 LIVE에서 거래하지 않는다
- **새 테스트 후보**: `test_night_session_trading_day_label_differs_from_accounting_period`

### AT-0007-7 공식 평가가 끝난 시점의 의사결정, 시장은 이미 닫힘 (R1 추가)

- **입력**: 가상 시장 `XKR` (세션 09:00~15:30 Asia/Seoul, 공식 종가 공표 예상 16:00). D일 16:30 Asia/Seoul에 의사결정 (`decision_at`). `K1` D일 공식 종가는 실제로 16:05에 들어옴 (`data_available_at`). 목표 포지션이 바뀌어 `K1` +10주 주문 의도가 생김
- **기대 출력**:

| 항목 | 결과 |
|---|---|
| 공식 종가 상태 | `FRESH` (관측 시각 15:30, 공표 예상 16:00, 실제 이용 가능 16:05 ≤ 16:30) |
| 주문 의도 생성 | **가능.** `decision_at` = 16:30, 상태 `INTENT` (ADR-0009 §6.2) |
| 실제 주문 제출 | D일 16:30에는 `XKR` 체결 구간이 없다. 세션 밖 접수가 가능한지는 시장·브로커·주문 유형에 따름 (Q7-9). 접수가 안 되면 `order_submitted_at`을 기록하지 않고 의도로만 남는다 |
| 체결 가능 시각 | 다음 `XKR` 체결 구간 (D+1이 거래일이라고 가정하면 D+1일 09:00 이후, 가상). 접수가 되더라도 그 전에는 체결되지 않는다 |
| 최악 경우 노출 | 제출 전 `INTENT`는 포함하지 않는다 (ADR-0009 §6.2). 제출되면 포함한다. 이렇게 제외해도 안전한 것은 제출 시점에 위험 검사를 다시 하는 경우뿐이며, 그 여부는 Q7-6에 달려 있다 |
| 다음 세션 처리 | **미결정** (Q7-6): 의도를 그대로 제출할지, D+1 의사결정에서 다시 계산할지, 제출 시점에 위험 검사를 다시 할지 |

- **전제조건**: §5.1 (주문 제출 시각과 체결 가능 시각), §6.3
- **예외조건**: `order_submitted_at`을 체결 가능 시각으로 기록하지 않는다. `fill_at`이 체결 구간 밖이면 ValueError (데이터 무결성)
- **V1 호환성 영향**: 없음 (V1에는 주문 제출과 체결의 시각 구분이 없음)
- **새 테스트 후보**: `test_intent_created_after_close_is_not_submitted_without_acceptance_window`, `test_submission_time_is_not_execution_time`
