## 3. Context

### 3.1 P0-03A-FINAL이 BLOCKED되었던 이유 (승인 전 상황)

2026-10-17 사용자는 P0-03A D3A-49의 핵심 원칙을 승인했다 [APPROVED_PRINCIPLE].

1. 실제 보유 수량(Actual Position Quantity)과 신규 주문 수량(Order Quantity)은 의미가 다르다.
2. 실제로 발생한 체결, 부분 체결, 기업 행사에 따른 보유 수량은 사실 그대로 기록한다.
3. 신규 주문을 제출할 때 해당 거래 단위의 거래 제약을 별도로 검증한다.
4. 실제 수량을 lot 배수가 아니라는 이유로 조용히 반올림하거나 버리지 않는다.
5. 미체결 주문 잔량을 신규 주문과 동일하게 취급하지 않는다.
6. 주문 수량 검증과 체결·장부 기록의 책임을 분리한다.

그런데 ACCEPTED ADR-0006 I6-5는 수량의 종류를 구분하지 않고 "정수여야 하고 lot size의 배수여야 한다"고 정한다. lot size 10인 가상 ETF를 10주 보유하다가 3:2 분할이 일어나면 실제 보유는 15주다. I6-5를 글자 그대로 적용하면 15주는 ValueError이므로, 원칙 (2)를 지킬 수 없고 브로커 보유와 내부 장부의 대조도 성립하지 않는다 (ADR-0003 S-1은 차단, S-3과 ADR-0009 R9-8은 `HALTED`). P0-03A 결정 등록부 §9.2는 이것을 `NORMATIVE_CONFLICT`(CA-49)로 분류했고, 해석만으로는 풀 수 없다고 판단했다. 그래서 이 ADR이 승인되기 전 P0-03A-FINAL은 BLOCKED였다.

이 ADR은 그 충돌을 푸는 **명시적인 부분 대체 규범**이다. 2026-10-19 ACCEPTED로 충돌은 해소되었다 (§2).

### 3.2 다른 ADR에는 lot 규칙이 없다

ACCEPTED ADR 가운데 lot을 다루는 것은 ADR-0003(S-5), ADR-0006, ADR-0012뿐이다 (CONFIRMED: ADR-0001~0012 본문 검색). ADR-0001은 수량이 정수라는 것만 요구한다. 따라서 충돌은 ADR-0006 안의 문제이며, ADR-0003·0012의 주문 쪽 검증은 이 ADR이 바꾸지 않는다.

## 5. Decision Drivers

1. 실제로 일어난 일(체결, 부분 체결, 기업 행사, 브로커가 확인한 보유)을 사실대로 기록해야 한다 [APPROVED_PRINCIPLE D3A-49 (2)]. 그래야 ADR-0009 R9-2의 실제 포지션 계산과 ADR-0003 S-1·S-3의 대조가 성립한다.
2. 신규 주문의 거래 단위 제약을 약하게 만들지 않는다 (I6-5의 주문 쪽, ADR-0003 S-5, ADR-0012 BR-2).
3. 정수 규칙과 단위 구분은 그대로 둔다 (ADR-0001 §6.2, I6-5).
4. ACCEPTED ADR을 조용히 다시 해석하지 않고, 바꾸는 범위를 명시한다 (CLAUDE.md §7.1, ADR-0006 변경 규칙).
5. Trading State 규칙을 새로 만들지 않는다 (ADR-0003 §6.5).
6. 미결정 정책(lot 미만 주문, 반올림, 소수 주, 상품 단위 정지 등)을 함께 정하지 않는다.
7. V1 타입, API, fingerprint를 바꾸지 않는다.

| 1. 전체 수량에 lot 강제 (현행 I6-5) | 실제 수량, 잔량, 예상 포지션을 포함한 모든 수량에 lot 배수를 요구 | 규칙이 단순하다. 기존 문서를 바꾸지 않는다 | 분할 15주, 부분 체결 3주, 잔량 7주, 도입 시점 기준 15주를 표현할 수 없다. D3A-49 원칙 (2)를 지킬 수 없고, 대조 불일치로 차단(S-1)과 `HALTED`(S-3, R9-8)가 반복된다 |
| **2. 역할별 수량 구분 (선택)** | 실제 수량·브로커 보고 기록·기록된 잔량·파생 예상 포지션에는 lot 배수를 요구하지 않고 사실대로 기록. 계산된 주문 후보는 계산·기록은 하되 제출 전 검증에서 lot 검사. 신규 주문 수량과 목표 포지션에는 현행 lot 규칙 유지 | D3A-49 원칙 (1)~(6)과 맞고, 주문 쪽 제약은 그대로다. 바꾸는 범위가 작다 | 기대 예상 포지션(실제 포지션 + 진행 중 주문의 남은 수량, ADR-0009 §5.1)이 lot 배수가 아니면, lot 배수인 어떤 목표에서도 주문 후보(목표 − 기대 예상 포지션, R9-1)가 lot 배수가 되지 않아 제출 전 검증에 걸린다. 주문 수량을 lot에 맞추는 규칙이 정해질 때까지 그 상태가 이어진다 (§12.2) |
| 3. 실제 수량 기록 허용 + 운영 제한 | 대안 2에 더해, lot 미만 실제 보유가 생긴 상품에 상품 단위 정지 등 운영 제한을 함께 정함 | 운영상 처리가 한 번에 정해진다 | 상품 단위 정지(ADR-0003 Q3-13)와 수동 처리 절차를 새로 정해야 하며, 이는 승인되지 않은 정책이다. 이 ADR의 범위를 넘는다 (Q13-4로 남김) |

## 7. Proposed Decision

### 7.1 정의 [ACCEPTED 2026-10-19]

| 용어 | 정의 |
|---|---|
| **실제 수량 (Actual Quantity)** | (a) 실제로 발생해 검증된 체결의 수량. 부분 체결 포함. Live에서는 브로커가 보고하고 ADR-0009 R9-9에 따라 반영된 체결. Backtest·Paper의 시뮬레이션 체결은 §7.2의 조건을 따른다 / (b) 기업 행사로 변환된 실제 보유 수량 (I6-8) / (c) 검증된 기준 포지션 (§7.4) / (d) (a)~(c)로부터 ADR-0009 R9-2에 따라 계산한 실제 포지션 |
| **브로커 보고 기록 (Broker-Reported Record)** | 브로커가 보고했지만 아직 검증·반영되지 않은 값: 대조에 쓰는 포지션 조회 결과(기준 포지션 후보 포함, ADR-0003 S-1·S-3, ADR-0012 BR-8), R9-9 반영 전의 체결 통보(같은 키의 내용 비교 포함), 브로커가 확인한 취소·만료 수량 (ADR-0009 §5.1의 남은 수량 식에 쓰임). **기록과 비교의 대상일 뿐, 검증·반영되기 전에는 실제 포지션이 아니다** |
| **기록된 주문 잔량 (Recorded Remaining Quantity)** | 이미 제출된 주문의 남은 수량. ADR-0009 §5.1의 정의(주문 수량 − 체결 수량 − 취소 확정된 수량)와 §6.2의 주문 상태에 따른다 |
| **파생 예상 포지션 (Derived Projected Position)** | 실제 포지션과 기록된 주문 잔량으로 계산한 기대 예상 포지션과 최악 경우 예상 포지션 (ADR-0009 §5.1, R9-7, ADR-0003 §6.3) |
| **계산된 주문 후보 (Computed Order Candidate)** | ADR-0009 R9-1로 계산한 주문 의도의 수량 (목표 − 기대 예상 포지션). 실제 수량에서 파생된 값이므로 lot 배수가 아닐 수 있다. 주문 상태 `INTENT`의 후보로 존재하며, 제출 전 검증에서 막힐 수 있다 (ADR-0012 BR-2, ADR-0003 S-5) |
| **신규 주문 수량 (New Order Quantity)** | 브로커에 제출하려는 주문의 수량. 제출 전 검증(I6-5의 lot 배수, ADR-0012 BR-2, 위험 축소 후보는 ADR-0003 S-5)을 통과해야 한다. 이미 제출된 주문의 정정·재제출 수량은 이 ADR이 따로 정하지 않는다 (Q13-1) |

### 7.2 R13-1 실제 수량의 lot 배수 예외 (A) [ACCEPTED 2026-10-19]

- 실제 수량에는 ADR-0006 I6-5의 lot size 배수 요구를 적용하지 않는다.
- 실제 수량은 사실대로 기록한다. lot size에 맞지 않는다는 이유로 반올림하거나 버리지 않는다 [APPROVED_PRINCIPLE D3A-49 (4)와 같음].
- 정수 규칙, 자산 유형의 수량 단위, 단위가 다른 수량의 합산 금지는 그대로 적용한다 (§9).
- Backtest·Paper의 시뮬레이션 체결에는 승인된 시뮬레이션 정책이 lot 미만 체결을 만들 수 있다고 정한 경우에만 이 예외를 적용한다. 그 정책이 정해지기 전까지 시뮬레이션 체결에는 현행 I6-5가 적용되며, 시뮬레이터가 lot 미만 체결을 만들면 현행대로 ValueError다 (ADR-0009 Q9-7, Q13-5).
- **R13-1a 브로커 보고 기록 [ACCEPTED 2026-10-19]**: §7.1의 브로커 보고 기록에는 lot size 배수 요구를 적용하지 않고 보고된 그대로 기록한다. 그래야 검증 전 값을 대조에 쓸 수 있다. 다만 이 기록은 검증(R13-3)이나 반영(R9-9)이 끝나기 전에는 실제 포지션을 바꾸지 않는다. 정수 규칙과 단위 규칙은 그대로 적용한다. 브로커 보고 기록의 수량도 정수 도메인 수량이며, 정수로 변환할 수 없는 보고는 원본 증거로만 보존한다 (아래).
- **원본 보고와 도메인 수량의 경계 (R13-1a)**: 브로커가 정수로 표현할 수 없는 값(예: 7.5주)을 보고하면, 그 값을 확정된 정수 도메인 수량으로 받아들이지 않고 7주나 8주로 반올림하지도 않는다. 그러나 원본 응답과 "정수로 변환할 수 없음"이라는 불일치 증거는 조용히 버리지 않고 원본 그대로 보존한다 (ADR-0012 승인 원칙 18: Adapter는 브로커 데이터를 번역·기록한다). 이런 보고가 있으면 그 수량은 대조에서 일치로 확인된 것이 아니며, 그 결과의 주문 차단과 Trading State는 ADR-0003 S-1·S-3과 ADR-0009 R9-8을 따른다. 원본 보존의 형식과 위치는 ADR-0009 Q9-9와 ADR-0012 Q12-7, 소수 주 지원 여부는 D3A-49.3~49.5로 남긴다. 이 조항은 소수 주를 지원하거나 정수 규칙을 완화하지 않는다.

### 7.3 R13-2 이미 제출된 주문의 잔량 (B) [ACCEPTED 2026-10-19]

- 이미 제출된 주문의 남은 수량은 확인된 주문·체결 상태에 따라 사실대로 기록하고 예상 포지션에 반영한다. 단지 lot size의 배수가 아니라는 이유로 새 주문으로 취급해 다시 검증하지 않는다 [APPROVED_PRINCIPLE D3A-49 (5)].
- **잔량을 기록하는 것과 새 주문을 제출하는 것은 다른 행위다.** R13-2는 남은 수량과 같은 크기의 새 주문을 낼 권한을 주지 않는다.
- 이미 제출된 주문을 정정하거나 취소 후 재제출할 때의 lot 규칙은 정하지 않는다 (Q13-1). 브로커가 정정·잔량을 어떻게 처리하는지도 확인되지 않았다 (ADR-0009 Q9-10, UNVERIFIED).

### 7.4 R13-3 검증된 기준 포지션 (C) [ACCEPTED 2026-10-19]

- 브로커 조회로 확인되고 검증된 기준 포지션(Verified Baseline Position, ADR-0009 R9-2의 "기준 포지션(검증된 시점)")은 실제 수량이다. lot 배수가 아니어도 그대로 기록한다.
- 이 ADR은 **언제** 기준 포지션을 새로 채택할 수 있는지 정하지 않는다. 시스템 도입 시점의 채택 절차, 복구 중 기준을 다시 잡는 것(재기준)을 허용할지와 그 조건은 열려 있다 (Q13-2, ADR-0009 Q9-8, ADR-0003 §6.5 Kill Switch (2), ADR-0012 Q12-16).
- 브로커 응답 하나가 왔다는 사실만으로 검증되었다고 보지 않는다. 기준 시각을 맞춘 대조(ADR-0003 S-3, [ADR 본문] ADR-0009 R9-13), 재시작 시 조회·대조(ADR-0012 승인 원칙 16), 기준 포지션과 그 뒤 체결의 중복 반영 방지(ADR-0009 R9-2, R9-9)는 기존 규칙을 따른다. 다만 이 규칙들은 브로커 값과 내부 기록을 비교하는 규칙이므로, 비교할 내부 기록이 없는 시스템 도입 시점에는 무엇이 "검증"인지 정해 주지 않는다. **도입 시점의 검증 방법은 전부 미결정이다** (Q13-2). 기준 시각 경계의 구현 세부도 정하지 않는다.
- 검증되기 전에는 그 값을 실제 포지션으로 확정하지 않는다. 그동안의 주문 차단과 Trading State는 ADR-0003(S-1, S-3, §6.5)을 따른다.

### 7.5 R13-4 파생 예상 포지션 [ACCEPTED 2026-10-19]

- 기대 예상 포지션과 최악 경우 예상 포지션은 실제 포지션과 기록된 주문 잔량으로 ADR-0009 §5.1, R9-7, ADR-0003 §6.3의 식 그대로 계산한다. lot size 배수 요구를 적용하지 않으며, lot에 맞추려고 값을 바꾸지 않는다.

### 7.6 R13-5 신규 주문과 목표 포지션은 현행 규칙 [ACCEPTED 2026-10-19]

- R13-1~R13-4는 **새 주문을 제출할 권한이나 거래 단위 예외를 주지 않는다.**
- 신규 주문 수량과 목표 포지션에는 현행 I6-5의 lot size 배수 요구가 그대로 적용된다. R13-5는 현행 규칙이 적용된다는 사실을 확인할 뿐, 신규 주문 lot 규칙을 이 ADR의 새 규범으로 고정하지 않는다. 그래서 나중에 D3A-49.2(lot 미만 정리 주문)나 lot 반올림 규칙을 정할 때 다룰 대상은 I6-5이며, ADR-0013을 다시 대체할 필요가 없다.
- 제출 전 검증: 모든 신규 주문은 I6-5의 lot 배수와 ADR-0012 BR-2의 로컬 검증(`NOT_SENT(LOCAL_VALIDATION)`)을 거친다. 위험 축소 후보는 ADR-0003 S-5(차단, `INVALID_LOT`)도 거친다 (S-5는 검증된 위험 축소 주문의 조건이다). 위험 축소 주문도 이 검사를 우회하지 않는다.
- 계산된 주문 후보(§7.1)는 lot 배수가 아니어도 후보로 계산·기록할 수 있다. lot 배수 요구는 그 후보를 **제출할 주문 수량으로 만드는 시점**(제출 전 검증)에 적용된다. 후보를 계산하는 순간 ValueError로 의사결정 주기 전체가 멈추지 않게 하려는 것이며, 주문 쪽 제약은 약해지지 않는다.
- 이 ADR은 주문 의도나 목표 포지션을 lot 배수로 자동 반올림하는 규칙을 만들지 않는다 (ADR-0006 §9, D3A-49.1·49.2).

### 7.7 R13-6 Trading State를 새로 정하지 않음 [ACCEPTED 2026-10-19]

- 실제 수량을 기록할 수 있게 되었다는 사실만으로 계좌가 `NORMAL`이라고 판단하지 않는다.
- 주문이 `INVALID_LOT`이나 `NOT_SENT(LOCAL_VALIDATION)`로 막혔다는 사실만으로 계좌가 `RESTRICTED`나 `HALTED`가 된다고 정하지 않는다.
- Trading State는 ACCEPTED ADR-0003 §6.5와 ADR-0009 R9-8을 따른다. 새 상태 전이나 상품 단위 정지가 필요하면 질문으로 남긴다 (Q13-4, ADR-0003 Q3-13).

### 7.8 R13-7 정수가 아닌 기업 행사 결과 [ACCEPTED 2026-10-19: 기존 규칙의 확인]

- 이 ADR은 정수 규칙을 완화하지 않는다. 분할 결과가 정수가 아니면(예: 7.5주) 소수 주로 기록하지 않고, 7주나 8주로 반올림하지도 않는다. 현행 처리(AT-0006-4 예외조건: 거부)를 바꾸지 않는다.
- 브로커가 정수가 아닌 수량을 직접 보고하는 경우의 원본 보존은 R13-1a의 경계를 따른다 (도메인 수량으로 받지 않되 원본과 불일치 증거는 보존).
- 소수 주 표현, 현금 정산(cash in lieu), 브로커가 정산한 뒤 보고하는 수량의 기록 방식은 정하지 않는다 (D3A-49.3~49.5, Q6-5).

## 8. 정확한 부분 대체 문구와 우선순위 [ACCEPTED 2026-10-19]

### 8.1 대체 문구

아래 인용은 R0-FIX2 본문 그대로이며 2026-10-19 AQ-13-2로 승인되었다. 첫 문장의 조건("ADR-0013이 ACCEPTED되면")은 2026-10-19에 충족되었으므로 이 문구는 그날부터 효력이 있다. 승인으로 범위가 넓어지지 않았다.

> ADR-0013이 ACCEPTED되면, ADR-0006 §6.3 I6-5의 "정수여야 하고 lot size의 배수여야 한다" 가운데 **lot size의 배수 요구**는 ADR-0013 §7.1이 정의한 실제 수량, 브로커 보고 기록, 기록된 주문 잔량, 파생 예상 포지션에는 적용하지 않는다. 계산된 주문 후보에는 계산·기록 시점에는 적용하지 않고, 그것을 제출할 주문 수량으로 만드는 제출 전 검증 시점에 적용한다. 그 밖의 수량, 특히 목표 포지션과 신규 주문 수량에는 계속 적용한다. I6-5의 나머지(자산 유형의 수량 단위, 정수, 단위가 다른 수량의 합산 금지)와 위반 시 ValueError는 바뀌지 않는다. 이미 제출된 주문의 정정·재제출 수량에 대한 별도 규칙은 ADR-0013이 정하지 않으며, 정해지기 전까지는 현행 I6-5가 적용된다.
>
> 우선순위: 실제 수량, 브로커 보고 기록, 기록된 주문 잔량, 파생 예상 포지션, 계산된 주문 후보의 계산·기록에 대해서만 ADR-0013(R13-1, R13-1a, R13-2, R13-3, R13-4, 그리고 R13-5 가운데 계산된 주문 후보의 계산·기록에 관한 부분)이 ADR-0006 I6-5보다 우선한다. 신규 주문 수량, 목표 포지션, 그 밖의 모든 수량에는 ADR-0006 I6-5를 그대로 적용하며, R13-5의 해당 문장은 그 사실을 확인할 뿐이다. 따라서 신규 주문이나 목표의 lot 규칙을 나중에 바꿀 때 고칠 대상은 I6-5다. ADR-0013은 ADR-0006의 다른 결정을 바꾸지 않는다.

### 8.2 I6-5를 읽는 방법

### 8.3 ADR-0006의 다른 문장에 미치는 영향 (ADR-0006의 본문은 편집하지 않음)

|---|---|

### 8.4 채택 후 교차 참조 (2026-10-19 승인, AQ-13-3)

CLAUDE.md §7.1의 상태 값(`PROPOSED` / `ACCEPTED` / `REJECTED` / `SUPERSEDED by NNNN`)에는 부분 대체가 없다. 이 ADR은 새 상태 값을 만들지 않는다. R0~R0-FIX2의 기본안을 사용자가 2026-10-19에 다음 방식으로 승인했고 (AQ-13-3), 작업 P0-03A-FINAL-RESUME에서 반영했다.

1. ADR-0013: `ACCEPTED`, 승인일 2026-10-19 (실제 승인일). ADR-0006의 승인일(2026-10-16)로 소급하지 않는다. 부분 대체의 범위는 이 ADR의 §2와 §8.1이 명시한다.
2. ADR-0006: 상태는 `ACCEPTED` 그대로이며 `SUPERSEDED`로 표시하지 않는다. 개정 이력(§13)에 교차 참조 한 줄("교차 참조" 행)만 추가했다. 그 행은 I6-5의 lot 배수 요구 가운데 실제 수량·브로커 보고 기록·기록된 주문 잔량·파생 예상 포지션·계산된 주문 후보의 계산·기록 범위를 2026-10-19 ADR-0013 §8.1이 부분 대체한다는 것, 그 밖의 I6-5 규칙은 그대로라는 것, §5.1 표와 AT-0006-3 문구는 역사적 기록으로 남고 그 범위에서는 ADR-0013이 우선한다는 것(AQ-13-6)을 적으며, 결정 내용·상태·승인 범위·승인일은 바꾸지 않는다고 밝힌다. I6-5의 문장, 승인 원칙, 인수 테스트 숫자, 상태, 승인일은 다시 쓰지 않았다. 이 한 줄은 결정 내용을 바꾸지 않는 링크·참조이므로 CLAUDE.md §7.1과 ADR-0006 §2 변경 규칙이 허용하는 문서 수정으로 판단했다.
3. CLAUDE.md의 ADR 표: ADR-0013 행을 추가하고 ADR-0006 행에 부분 대체 범위를 표시한다.
4. ADR-0006 §5.1 표와 AT-0006-3 문구는 고치지 않고 역사적 기록으로 유지한다 (AQ-13-6, §8.3).

## 12. Financial Integrity Implications

### 12.1 숫자 예제 (모두 가상 상품)

실제 거래소에서 부분 체결이나 특정 주문을 허용한다는 주장이 아니다 (UNVERIFIED). 계산은 저장소 밖 일회성 스크립트로 독립 확인했다 (CONFIRMED).

**EX-13-1 기업 행사 후 보유 수량**

- 입력: lot size 10주. 분할 전 보유 10주. 분할 비율 3:2(구주 2주당 신주 3주). 분할 전 가격 30,000 KRW/주. 단위: 수량은 주, 가격은 KRW/주.
- 계산: 실제 보유 = 10 × 3/2 = **15주**. 분할 후 기준가격 = 30,000 × 2/3 = **20,000 KRW/주**. 평가액 = 10 × 30,000 = **300,000 KRW** (분할 전) = 15 × 20,000 = **300,000 KRW** (분할 후).
- 기대 결과: 15주를 기록한다 (R13-1). 10주나 20주로 바꾸지 않는다. 평가액 300,000 KRW가 유지된다 (I6-8: 분할은 손익이 아님). 15주 신규 주문의 허용 여부는 별도 검사다 (R13-5).
- 잘못 처리하면: 10주로 기록하면 200,000 KRW(−100,000, −33%), 20주로 기록하면 400,000 KRW(+100,000, +33%).
- 전제조건: 분할 이벤트에 효력일과 비율이 있다 (I6-8). 예외조건: 결과가 정수가 아니면 EX-13-5.

**EX-13-2 부분 체결과 잔량**

- 입력: lot size 10주. 실제 0주. 신규 매수 주문 +10주(lot 배수, 제출 검사 통과). 확인된 부분 체결 +3주. 취소 확정 0주.
- 계산: 실제 포지션 = 0 + 3 = **+3주** (R9-2). 남은 수량 = 10 − 3 − 0 = **+7주** (ADR-0009 §5.1). 기대 예상 포지션 = 3 + 7 = **+10주**. 최악 경우: `q_long_worst` = 3 + 7 = 10, `q_short_worst` = 3 − 0 = 3.
- 기대 결과: 3주 체결과 7주 잔량을 각각 기록한다 (R13-1, R13-2). 목표가 +10이면 새 주문 의도 = 10 − 10 = **0** (R9-1). 신규 7주 주문의 허용 여부를 자동으로 결론 내리지 않는다.
- 전제조건: 주문 상태 `PARTIALLY_FILLED`가 브로커 응답·체결 통보로 확인됨 (ADR-0009 §6.2). 예외조건: 누적 체결이 주문 수량을 넘으면 데이터 무결성 오류로 `HALTED` ([ADR 본문] AT-0009-1 예외조건).

**EX-13-3 검증된 기준 포지션**

- 입력: lot size 10주. 시스템 최초 기록 전 브로커가 보고한 보유 15주. 기준 시각 T0.
- 기대 결과: T0 기준 대조로 검증된 기준 포지션으로 채택되면 15주를 그대로 기록한다 (R13-3). T0 뒤 체결만 더하고, T0 이전 체결을 다시 더하지 않는다 (R9-2, R9-9, AT-0013-11). 검증되지 않은 응답은 사실로 확정하지 않는다.
- 예외조건: 검증 방법과 경계 세부는 Q13-2.

**EX-13-4 목표와 신규 주문의 불일치**

- 입력: lot size 10주. 실제 15주. 미체결 주문 없음. 목표 0주.
- 계산: 기대 예상 포지션 = 15 + 0 = 15. 신규 주문 의도 = 목표 0 − 15 = **−15주** (R9-1).
- 기대 결과 (현행 신규 주문 규칙 기준): −15주는 계산된 주문 후보로 존재할 수 있지만, lot 10의 배수가 아니므로 제출 전 검증을 통과하지 못한다 (I6-5, ADR-0012 BR-2 `NOT_SENT(LOCAL_VALIDATION)`, 위험 축소 후보이므로 ADR-0003 S-5 `INVALID_LOT`). 시스템이 −10주나 −20주로 바꾸지 않는다 (R13-5). 실제 보유 15주 기록은 유효하다. 위험 축소 주문이라고 해서 거래 제약을 우회하지 않는다. Trading State는 ADR-0003 규칙으로 정해진다 (R13-6). 수동 청산이나 특별 주문 절차는 이 ADR에서 정하지 않는다 (Q13-4).
- 일반화: 목표는 현행 규칙상 lot 배수(…, −10, 0, 10, 20, …)여야 하므로, 주문 후보 T − E가 lot 배수인 것과 기대 예상 포지션 E가 lot 배수인 것은 같은 조건이다 (CONFIRMED: 일회성 계산). 이 예제는 E = 15이므로 어떤 목표 T에서도 T − 15는 10의 배수가 되지 않는다 (나머지가 항상 5). 반대로 잔량 때문에 E가 lot 배수가 되면 후보도 lot 배수다. 제출 여부는 다른 검사에 달려 있다 (AT-0013-7 (iii)). §12.2.

**EX-13-5 정수가 아닌 분할 결과**

- 입력: 실제 보유 5주. 분할 비율 3:2.
- 계산: 이론상 분할 후 수량 = 5 × 3/2 = **7.5주**.
- 기대 결과: 이 ADR은 7.5주를 허용하지 않는다. 정수 규칙과 충돌하는 상황이며, 현행 처리(AT-0006-4 예외조건: 거부)를 바꾸지 않는다. 7주나 8주로 조용히 반올림하지 않는다. 소수 주, 현금 정산, 기록 형식은 D3A-49.3~49.5 (R13-7).

**EX-13-6 롤오버와 선물 계약 수**

- 입력: 가상 선물 상품 F, 월물 F.C1(구월물)과 F.C2(신월물). 수량 단위는 계약. F.C1 2계약 보유 중 롤.
- 기대 결과: 롤 체결은 월물별로 기록한다 (F.C1 −2, F.C2 +2. I6-3, ADR-0009 R9-10). 이 ADR의 예외를 이용해 계약의 일부(소수 계약)를 기록하거나 다른 월물 포지션을 합치지 않는다. 정수 규칙과 월물 ID 규칙은 그대로다. 특정 선물 시장의 lot 제약은 실제 참조 데이터가 확인된 뒤 적용한다 (ADR-0006 Q6-5, I6-11).

### 12.2 알려진 결과와 트레이드오프

- 이 ADR의 승인(2026-10-19)으로 lot 미만 실제 보유(예: 15주)를 기록하고 대조할 수 있다. 그 결과 lot 미만 수량을 표현할 수 없어서 생기던 대조 불일치와 계좌 전체 `HALTED`(S-3, R9-8. S-1은 차단)는 그 원인으로는 생기지 않는다 (INFERRED). 다만 검증 절차 자체(Q13-2)가 정해져야 실제로 대조를 마칠 수 있다.
- 그러나 신규 주문과 목표 포지션에는 현행 lot 규칙이 그대로다. 따라서 주문 수량을 lot에 맞추는 규칙(D3A-49.1·49.2, ADR-0006 §9)이 정해질 때까지, **기대 예상 포지션(실제 포지션 + 진행 중 주문의 남은 수량, ADR-0009 §5.1)이 lot 배수가 아니면, lot 배수인 어떤 목표에서도 주문 후보(목표 − 기대 예상 포지션, R9-1)가 lot 배수가 되지 않아 제출 전 검증에 걸린다**. 위험 축소 주문도 예외가 아니며, 그 동안 그 포지션은 자동으로 줄일 수 없다 (EX-13-4).
- 조건부라는 점에 주의한다. 실제 보유가 lot 배수가 아니어도 기대 예상 포지션이 lot 배수이면 주문 후보는 lot 배수다 (목표가 lot 배수이므로). 예: 실제 15주, 확인된 미체결 매수 잔량 +5주, 기대 예상 포지션 20주, 목표 30주 → 후보 +10주 (AT-0013-7 (iii)). 이 후보는 lot 배수 검사를 통과할 수 있지만 (ADR-0003 S-5의 최소 수량 등 다른 주문 단위 조건은 D3A-49.7로 미확인), 실제 제출 여부는 다른 승인된 위험·주문 검사(ADR-0003 L1·L2와 §6.2.2, L3 게이트)에 따로 달려 있다.
- 상태가 `UNKNOWN`인 주문의 수량은 확인된 잔량이 아니다. 최악 경우 예상 포지션에는 전량 체결로 넣고(ADR-0003 §6.3, R9-7), 상태 불명확 주문이 하나라도 있으면 계좌는 `HALTED`이므로(ADR-0003 §6.3, §6.5) 자동 주문 후보를 만들지도 제출하지도 않는다 (R9-12). 위 조건부 설명은 `UNKNOWN` 주문이 없는 경우에만 해당한다. 정정·취소를 요청 중인 주문의 수량은 ADR-0009 §6.2와 RP-1·RP-3을 따르며, 이 ADR은 그 계산을 바꾸지 않는다.
- 이 상태에서 계좌의 Trading State가 무엇인지는 이 ADR이 정하지 않는다 (R13-6). ADR-0012 §6.5 (A)는 로컬 검증 실패 때 Trading State를 바꾸지 않는다고 적지만, 그것은 ADR-0012 §6의 제안이다.
- 따라서 기대 예상 포지션이 lot 배수가 아닌 상품에 대해서는, Trading State가 그대로라면 "계좌 전체 정지"에서 "그 상품의 자동 주문만 막힘"으로 실패 방식이 바뀔 수 있다 (Trading State 자체는 R13-6에 따라 이 ADR이 정하지 않는다). 이것은 개선이라고 단정할 수 없는 트레이드오프이며, 그런 상품을 상품 단위 정지로 둘지는 Q13-4(ADR-0003 Q3-13)에서 사용자가 정한다. lot이 1보다 큰 상품을 실제로 거래하기 전에 D3A-49.1, D3A-49.2, D3A-49.7, Q13-1, Q13-2, Q13-4(ADR-0003 Q3-13)를 정해야 한다.
- 손익 공식(ADR-0001 §6.2)과 위험 노출 식(ADR-0003 §6.3)은 바뀌지 않는다. 오히려 실제 수량을 반올림할 때 생기는 노출 오류(±33%, EX-13-1)를 막는다.

## 13. Acceptance Criteria

인수 테스트는 **명세**다. 이번 작업에서 구현하지 않았다. 별도 표시가 없으면 가상 ETF `ETF.L10`(lot size 10주, 거래통화 KRW, 승수 1)을 쓴다.

### AT-0013-1 신규 주문 lot 위반

- **Given**: 실제 0주, 미체결 주문 없음. 주문 의도 +15주 (lot 10의 배수 아님).
- **When**: 주문 의도를 만들고 제출 전 검사를 한다.
- **Then**: 현행 제약 그대로 제출 전 검증에서 거부된다. 근거는 I6-5의 lot 배수와 ADR-0012 BR-2(`NOT_SENT(LOCAL_VALIDATION)`)다. 이 주문은 위험 증가 주문이므로 S-5(위험 축소 후보의 조건)는 해당하지 않는다. lot 배수가 아닌 값으로 제출할 주문 수량 객체를 만들려 하면 ValueError다 (I6-5). 계산된 주문 후보 자체는 기록할 수 있다 (R13-5). 주문 상태가 `INTENT`로 남는다는 세부는 ADR-0012 §6.5 (A)의 제안이다. +10이나 +20으로 자동 변경하지 않는다. R13-1~R13-4는 적용되지 않는다.
- **전제조건**: lot size가 참조 데이터로 주어진다. **예외조건**: lot size가 없으면 LIVE에서의 처리는 ADR-0006 I6-11([ADR 본문])과 P0-03A D3A-48 (1)에 따른다.
- **관련 규칙**: R13-5. **V1 영향**: 없음. **새 테스트 후보**: `test_new_order_quantity_requires_lot_multiple`

### AT-0013-2 기업 행사 후 실제 15주

- **Given**: 보유 10주, 분할 전 가격 30,000 KRW, 3:2 분할 효력.
- **When**: 분할을 반영한다.
- **Then**: 실제 보유 **15주**, 기준가격 **20,000 KRW**, 평가액 **300,000 KRW** (EX-13-1). 10주나 20주로 바꾸지 않는다. 분할은 손익·거래·비용이 아니다 (I6-8).
- **관련 규칙**: R13-1. **새 테스트 후보**: `test_split_result_recorded_without_lot_rounding`

### AT-0013-3 3주 부분 체결

- **Given**: 실제 0주. 제출된 매수 주문 +10주가 `ACCEPTED`.
- **When**: 체결 `X-1` +3주가 통보되어 R9-9에 따라 반영된다.
- **Then**: 체결 기록 +3주 (R9-3), 실제 포지션 **+3주** (R9-2). lot 배수 검사로 거부하지 않는다. 주문 상태 `PARTIALLY_FILLED`.
- **관련 규칙**: R13-1. **새 테스트 후보**: `test_partial_fill_below_lot_is_recorded`

### AT-0013-4 제출된 10주 주문의 잔량 7주

- **Given**: AT-0013-3 직후. 목표 +10주.
- **When**: 남은 수량과 다음 의사결정의 주문 의도를 계산한다.
- **Then**: 남은 수량 = 10 − 3 − 0 = **+7주**를 기록한다. 새 주문으로 다시 검증하지 않는다 (R13-2). 기대 예상 포지션 **+10주**, 새 주문 의도 = 10 − 10 = **0** (R9-1). 7주짜리 새 주문을 만들거나 제출하지 않는다.
- **예외조건**: 정정·재제출 수량의 lot 규칙은 Q13-1 (기대 결과 보류).
- **관련 규칙**: R13-2, R13-4. **새 테스트 후보**: `test_remaining_quantity_recorded_not_revalidated_as_new_order`

### AT-0013-5 이미 존재하는 15주 기준 포지션

- **Given**: 시스템 최초 기록 전 브로커가 기준 시각 T0에 15주 보유를 보고한다.
- **When**: (a) T0 기준 대조 절차로 검증된다. (b) 응답은 왔지만 검증 절차가 끝나지 않았다.
- **Then**: (a) 검증된 기준 포지션으로 **15주**를 기록한다 (R13-3). (b) 15주는 브로커 보고 기록으로 그대로 보관한다 (R13-1a, lot 배수 검사로 거부하지 않음). 그러나 실제 포지션으로 확정하지 않는다. 그동안의 주문 차단과 Trading State는 ADR-0003 S-1, S-3, §6.5를 따른다.
- **예외조건**: 도입 시점의 검증 방법, 재기준 조건, 기준 시각 경계는 Q13-2 (보류). 따라서 (a)에 이르는 절차는 아직 정해지지 않았다.
- **관련 규칙**: R13-3. **새 테스트 후보**: `test_verified_baseline_recorded_without_lot_rounding`, `test_unverified_broker_response_not_baseline`

### AT-0013-6 15주 보유, 목표 0주

- **Given**: 실제 15주, 미체결 없음, 목표 0주.
- **When**: 주문 의도를 계산하고 제출 전 검사를 한다.
- **Then** (현행 신규 주문 규칙 기준): 계산된 주문 후보 **−15주** (EX-13-4)는 기록할 수 있지만, 제출 전 검증을 통과하지 못한다 (I6-5, BR-2 `NOT_SENT(LOCAL_VALIDATION)`, 위험 축소 후보이므로 S-5 `INVALID_LOT`). −10주나 −20주로 자동 보정하지 않는다. 실제 보유 15주 기록은 그대로 유효하다. 이 ADR은 Trading State를 바꾸지 않는다 (AT-0013-12).
- **관련 규칙**: R13-5, R13-6. **새 테스트 후보**: `test_risk_reducing_intent_not_auto_rounded_to_lot`

### AT-0013-7 실제 수량과 예상 포지션

- **Given**: (i) 실제 15주, 미체결 없음, `P_ref` 20,000 KRW, 승수 1, fx 1. (ii) AT-0013-4의 실제 3주와 잔량 +7주. (iii) 보유 10주에서 제출한 매수 주문 +10주(lot 배수) 가운데 +5주가 체결되어 실제 15주, 확인된 미체결 매수 잔량 +5주 (상태 `PARTIALLY_FILLED`), `UNKNOWN` 주문 없음, 목표 30주.
- **When**: 기대·최악 경우 예상 포지션과 예상 노출을 계산하고, (iii)에서는 주문 후보도 계산한다 (R9-1, ADR-0003 §6.3).
- **Then**: (i) 기대 15, `q_long_worst` 15, `q_short_worst` 15, 예상 노출 = 15 × 20,000 × 1 × 1 = **300,000 KRW**. 10주(200,000)나 20주(400,000)로 왜곡하지 않는다. (ii) 기대 10, `q_long_worst` = 3 + 7 = **10**, `q_short_worst` = 3 − 0 = **3**. (iii) 기대 예상 포지션 = 15 + 5 = **20**, 주문 후보 = 30 − 20 = **+10주**. 후보는 lot 10의 배수이므로 lot 배수 검사로는 거부되지 않는다 (S-5의 다른 주문 단위 조건은 D3A-49.7). 후보를 낸다고 가정한 최악 경우: `q_long_worst` = 15 + 5 + 10 = **30**, `q_short_worst` = 15 − 0 = **15**. 실제 제출 여부는 다른 승인된 위험·주문 검사에 따로 달려 있으며 이 AT의 범위가 아니다. "실제 보유가 lot 배수가 아니면 자동 주문이 모두 막힌다"고 일반화하면 이 사례에서 틀린다.
- **예외조건**: (iii)의 잔량이 `UNKNOWN` 주문의 수량이면 확인된 잔량이 아니며, 계좌가 `HALTED`이므로 자동 주문 후보를 만들지 않는다 (ADR-0003 §6.3, §6.5, R9-12).
- **관련 규칙**: R13-4, R13-5. **새 테스트 후보**: `test_projected_positions_use_actual_quantities`, `test_candidate_lot_check_depends_on_expected_projected_position`

### AT-0013-8 7.5주 분할 결과

- **Given**: 실제 5주, 3:2 분할. (b) 변형: 브로커가 분할 뒤 보유를 7.5주로 보고한다.
- **When**: 분할을 반영한다. (b) 브로커 보고를 받는다.
- **Then**: 이론값 7.5주는 정수가 아니므로 소수 주로 기록하지 않는다. 7주나 8주로 반올림하지 않는다. 현행 처리(AT-0006-4 예외조건: 거부)를 따른다 (R13-7). 소수 주와 현금 정산의 처리는 **기대 결과 보류** (D3A-49.3~49.5). (b) 7.5주를 정수 도메인 수량으로 만들지 않고 반올림하지 않는다. 원본 응답과 변환 불가 사실은 보존한다 (R13-1a). 그 수량은 일치로 확인되지 않은 것이며, 주문 차단과 Trading State는 ADR-0003 S-1·S-3, R9-8을 따른다. 원본 보존의 형식은 **보류** (ADR-0009 Q9-9, ADR-0012 Q12-7).
- **새 테스트 후보**: `test_non_integer_split_result_not_rounded`

### AT-0013-9 다른 단위·거래 단위의 수량 합산

- **Given**: (a) 선물 월물 2계약(`CONTRACT`)과 `ETF.L10` 15주(`SHARE`). (b) `ETF.L10` 15주와 다른 ETF `ETF.B` 10주. 둘 다 `SHARE`.
- **When**: (a)·(b) 각각 두 수량을 더해 하나의 "총 포지션"을 만든다. (c) 포트폴리오 보고를 위해 두 ETF의 기준통화 명목가치를 합산한다.
- **Then**: (a) 거부한다. 수량 단위가 다르다 (I6-5 "단위가 다른 수량을 더하지 않는다"). (b) 거부한다. 단위는 같지만 거래 단위(포지션 식별자)가 다르다. 실제 포지션은 거래 단위별로 계산하며(ADR-0009 §5.1), I6-4(ETF의 거래 단위는 종목)와 I6-5의 예시 "상품 간 '총 포지션' 합계"를 같은 단위의 서로 다른 상품에도 적용한다고 읽는다 (I6-5 원문의 예시는 단위가 다른 경우를 든다. 이 해석은 ADR-0009 §5.1의 거래 단위별 계산으로 뒷받침된다). 15 + 10 = 25주라는 단일 포지션을 만들지 않는다. (c) 허용될 수 있다. 이것은 포지션을 합치는 것이 아니라 각 거래 단위의 명목가치를 기준통화로 환산해 보고용으로 합산하는 것이며, 그 방식은 ADR-0003 §6.3("포트폴리오 지표는 월물별로 기준통화 금액을 구한 뒤 더한다")과 ADR-0001 §6.2를 따른다. 위험 검사에서의 쓰임은 ADR-0003 §6.2.2, NAV 보고는 ADR-0008을 따른다. R13-1의 예외는 이 규칙들을 완화하지 않는다.
- **새 테스트 후보**: `test_actual_quantities_of_different_units_not_summed`, `test_same_unit_different_instruments_not_merged_into_one_position`

### AT-0013-10 원장 기록과 주문 검증의 분리

- **Given**: 실제 15주 (AT-0013-2), 잔량 7주 (AT-0013-4).
- **When**: 장부에 기록하고, 같은 크기(−15주, +7주)의 신규 주문을 검사한다.
- **Then**: 장부 기록은 유효하다. 같은 크기의 신규 주문은 lot 검사로 거부된다. 기록이 유효하다는 사실이 주문의 유효성을 뜻하지 않는다 (D3A-49 (6), R13-5).
- **새 테스트 후보**: `test_ledger_record_validity_independent_of_order_validity`

### AT-0013-11 기준 포지션과 체결 이력의 중복 반영

- **Given**: T0 검증 기준 포지션 15주. 이 15주에는 T0 이전 체결 `X-0`(+5주)이 이미 포함되어 있다. T0 뒤 체결 `X-1`(+10주).
- **When**: 복구 중 브로커 체결 내역(`X-0`, `X-1`)을 다시 읽고, `X-1`이 한 번 더 통보된다.
- **Then**: 실제 포지션 = 15 + 10 = **25주** (R9-2: 기준 이후 체결만 더함). `X-0`을 다시 더한 30주, `X-1`을 두 번 더한 35주가 되지 않는다 (R9-9). 같은 체결 ID의 내용이 다르면 `HALTED` (R9-9).
- **예외조건**: `fill_at` = T0인 체결의 귀속은 Q13-2 (보류).
- **새 테스트 후보**: `test_baseline_and_fills_counted_once`

### AT-0013-12 `INVALID_LOT`과 Trading State

- **Given**: (a) Trading State `NORMAL`, 주문 의도 −15주가 lot 검사에서 막힘. (b) 다른 원인으로 `HALTED`인 계좌에서 실제 15주 기록이 가능해짐.
- **When**: Trading State를 확인한다.
- **Then**: 이 ADR은 어느 경우에도 상태 전이를 만들지 않는다. (a) ADR-0003 §6.5의 진입 조건은 예시 목록이며, `INVALID_LOT`이나 `NOT_SENT(LOCAL_VALIDATION)`는 그 예시에 없다. 이 ADR은 이를 진입 조건으로 추가하지 않는다. 그 결과 상태가 `NORMAL`로 유지되는지는 이 ADR이 정하지 않으며 **기대 결과 보류**다 (ADR-0012 §6.5 (A)의 제안, Q13-4). (b) 실제 수량을 기록할 수 있게 된 것만으로 `NORMAL`로 돌아가지 않는다. 해제는 ADR-0003 §6.5(원인 해소 확인 + 대조 완료 + 사용자 승인)를 따른다.
- **관련 규칙**: R13-6. **새 테스트 후보**: `test_adr_0013_adds_no_trading_state_transition` (상태 유지 여부 자체는 검증하지 않음)

### AT-0013-13 선물 월물과 계약 단위

- **Given**: 가상 선물 F의 월물 F.C1 2계약 보유, F.C1 → F.C2 롤 (EX-13-6).
- **When**: 롤 체결을 반영하고, (a) 소수 계약 1.5를 기록하려 하거나 (b) F.C1과 F.C2 포지션을 하나로 합치려 한다.
- **Then**: 롤 체결은 F.C1 −2, F.C2 +2로 월물별로 기록한다. (a) 정수가 아니므로 거부. (b) 포지션은 월물 ID별로 표현해야 하므로 (I6-3), 이 ADR의 예외로 월물 구분을 없앤 단일 포지션을 만들지 않는다. 상품 단위 집계를 보고용으로 할 수 있는지는 이 ADR의 범위가 아니다. R13-1은 정수 규칙과 월물 ID 규칙을 완화하지 않는다.
- **새 테스트 후보**: `test_futures_actual_quantity_keeps_contract_identity_and_integer_rule`
